## Reasoning

The repaired gate is no longer pointed at the wrong worktree, which was the
fatal defect in the first half of this audit. The remaining problem is semantic:
the gate’s green light means “48 files exist, each exact module built, and
every module containing a `sorry` also contains a marker.” It does not mean
“the 48-module lane is a closed,
committed, reproducible unit.” Each of those missing meanings is independently
checkable and independently false today.

The index defect matters because the generated index is the artifact a reviewer
or a later lane will read. Right now `docs/OBLIGATIONS-GENERATED.md` says
`WaveE | 2`, and `agents/status/obligations.json` says `WaveE: 2`, while the
same tree contains 48 E markers and `check.py` counts all 80 markers. The
permissive `check.py` regex proves the intended marker grammar accepts bare
ids; the collector regex is the outlier. This is a one-line parser bug with a
large audit consequence: `LN-WE-E27`, one of the two open obligations, is
absent from the index.

The missing commit is not a bookkeeping nicety. `check-wave-e.py` compares
against `BASE = 6b451f9` with `git diff`, so all 48 E modules are invisible to
its unexpected-file scan while untracked. Even after a commit, the prefix
whitelist would accept a 49th file under `LnLean/Proofs/WaveE/`, and the
`range(1,49)` loop would not count it. The `E03Alt` episode demonstrates the
gap: a 49th module with a `sorry` and a non-catalog id existed, the checker
ignored it, and its `.olean` survived deletion. A gate that cannot name the
exact set of modules is not an integration gate.

Closure is a policy decision the gate has not made. The plan explicitly allows
a marked `sorry` for a false claim; the two E cases are faithful false
statements with counterexamples, so failing the lane for having them would be
wrong. But passing with an unconstrained `sorries=2` is also wrong: a third
`sorry`, or a `sorry` moved to a different theorem, would pass identically.
The fix is an exact allowlist (`LN-WE-E27`, `LN-WE-E40`) plus a hard failure on
any other `sorry`, or an explicit decision that the lane is conditional and
must never be reported as closed. Either is defensible; the current silence is
not.

Reproducibility is the difference between “it built once in this prepared
worktree” and “this revision is gated.” The E build depends on an absolute
symlink into the main worktree for `vendor/btc-lean-core`; the anchor check
depends on an absolute symlink for `refs/rust-lightning`; both are ignored or
untracked as symlinks. A fresh checkout of `wave-e/48` cannot build or run
`verify-anchors.py`, and `verify-vendor.sh` exits 2 because
`vendor/VENDOR-SHA256` is inside the ignored tree. The repo documents the
reference pins in `refs/PINNED.md`, but the gate does not bootstrap or verify
them. That is a setup prerequisite, not a proof defect, but it must be
committed or scripted before the gate result is portable.

The statement-fidelity sample is a caution, not a rejection. E34 and E35 prove
projections/arithmetic restatements of their hypotheses; E18 and E04 are
definitional; E01/E41 are `rfl` seam identities; E05 is a model artifact; E32
is conditional despite a “proved” label. The reports mostly say so. A reviewer
comparing D and E should not count these as independent evidence for the same
catalog claims. None of this contradicts the build, and none of it is a reason
to call the lane false; it is a reason not to over-read a green gate.
