## 4. What remains open

No `sorry` is left. The following are **`Prop` targets** (definitions in §10 +
a few conditional theorems). Each was left as a definition because it cannot be
stated truthfully over the current wave-A model; stating it as a theorem with
`sorry` would have been an overclaim.

1. **LN-SEC-002 — adaptive corruption is declared, not modelled.**
   `SecurityGame.step` receives the same `Adversary` record at every step, so
   `Adversary.corrupted` is static for the whole run; `CorruptionMode.adaptive`
   and `Adversary.adaptive` are documentation. Target:
   `AdaptiveCorruption g` (a strictly growing `corruptedAt : Nat → List NodeId`).
   *Next smallest step:* add `corruptedAt : Nat → List NodeId` to
   `SecurityGame` (integrator-owned `Security.Model`), make `run` pass
   `corruptedAt n`, and re-state `protectedNodes` per step.
2. **LN-SEC-003 — `honest` and `corrupted` are not required to be disjoint.**
   `honestDisjoint_not_automatic` exhibits a wave-A game that "protects" a node
   it corrupts. Target: the conjunct `HonestDisjoint g` in every game
   constructor, or use `protectedNodes g` as the honest set.
   *Next smallest step:* a one-line `honest := protectedNodes` change in each
   wave-A game constructor; `protectedNodes_honestDisjoint` then discharges it.
3. **LN-SEC-006 — Lightning instance of power monotonicity.**
   `Simulation.winning_antitone` proves the transfer, and
   `power_monotonicity_needs_hypothesis` proves the simulation hypothesis is
   necessary. What is missing is `LightningPowerMonotone g b`: no wave-A module
   exports a concrete `SecurityGame.step`, so the relation `R` cannot be built.
   *Next smallest step:* instantiate `reorgGame_wins_monotone` for the fee
   environment (`FeeEnvironment.atHeight` is already pointwise ordered by
   `AdversaryLe`), then do the channel transition once B10/A3 export a step
   relation.
4. **LN-SEC-008 — C3 is not connected to `Invoice`.**
   `Invoice` has five fields and no signer key or signature; `signatureValid`
   is a Boolean input. `invoice_fields_only` shows attribution cannot be read
   off `Invoice`; `invoice_attribution_of_reduction` is the exact conditional
   form. *Next smallest step:* move `SignatureModel`/`SignedInvoice` into
   `Security.Model` and prove `SignedInvoice.Verified → payeeKey = expected`
   from an explicit reduction hypothesis.
5. **LN-SEC-009 — schedule bridge.** INV-10 is over `Schedule.latency`,
   the adversary capability is `NetworkSchedule.delivery`; no bridge exists.
   *Next smallest step:* define `NetworkSchedule.toSchedule` with
   `latency m = if delivery m.tag j then some (m.send + maxDelay) else none`
   and prove `PartiallySynchronous` when `maxDelay ≤ Δ`.

### Findings the integrator should record

* The ten catalog predicates are all discharged, but **none of them mentions
  `Adversary`**. The catalog is a set of state invariants; the adversary only
  enters through `SecurityGame.bad`. Traceability must connect the two.
* **C4, C5, C6, C7 have no consumer** in the core catalog
  (`core_catalog_ignores_c4_c5_c6_c7`): taproot, ECDH, HKDF and AEAD are not
  covered by any of the ten invariants.
* **Three of the four adversary capabilities have no invariant consumer**
  (`no_corruption_assumption`, `no_reorg_assumption`,
  `no_fee_spike_assumption`); only the network schedule appears (INV-10).
* The catalog's INV-05 is independent of the penalty's economics
  (`punishable_without_economics`), so "a breach is punished" needs
  `LN-PENALTY-ECON`; the catalog does not contain it.
