# F09 — Dust trimming and fee accounting

## Target
- Marker: `LN-WF-F09`
- Module: `LnLean.Proofs.ModelHardening.F09`

## Result
- Status: conditional
- Build: RC 0
- New definitions:
  - `outputValue` — satoshi value of a `List CommitmentOutput`.
  - `candidateOutputs`, `candidateValue`, `anchorValue` — pre-trim outputs and their values.
  - `keepOutput`, `dropDustOutput`, `dustOutputs`, `dustDroppedOutputs` — the strict dust rule (`value < dust` is dropped) split into kept and recorded-trimmed buckets.
  - `trimmedValue`, `droppedValue` — values of the kept and trimmed buckets.
  - `requiredFee` — `baseFee + droppedValue`.
  - `dustFeeAccounted` — the missing invariant `c.feeSat = requiredFee dust baseFee c`.
  - `counterexampleCommitment` — a conserving commitment with two 500-sat outputs.
- Main theorems:
  - `trimmedValue_add_droppedValue`: kept + dropped = candidate value.
  - `trimmedValue_le_candidateValue`: dust trimming cannot increase output value.
  - `trimmedValue_lt_candidateValue_of_dropped`: the inequality is strict when anything is trimmed.
  - `trimmedValue_eq_candidateValue_of_no_dust`: no dust implies no value change.
  - `outputValue_commitmentOutputs`, `commitmentOutputs_value_eq_totalOutputValue`: the model's `commitmentOutputs` is value-exact (equality, not increase).
  - `commitmentOutputs_value_eq_trim_one`: the model's trimming is the dust rule with limit 1.
  - `model_keeps_subdust_output`: `commitmentOutputs` still emits a 500-sat output at the 546-sat limit.
  - `conservation_with_requiredFee`: with `requiredFee`, trimming conserves value (unconditional positive accounting theorem).
  - `conservation_of_dustFeeAccounted`: main conditional conservation theorem.
  - `conservation_iff_dustFeeAccounted`: post-trim conservation holds iff the reported fee includes the trimmed value.
  - `dust_trim_preserves_conservation_counterexample`: the unconditional conservation claim is false.
- Added hypotheses:
  - `hgross : c.totalOutputValue + baseFee = c.fundingValueSat` — pre-trim conservation with the base fee.
  - `dustFeeAccounted dust baseFee c` — the fee credit required by BOLT 3 §2.
- Statement fidelity: the mission's first claim, "dust trimming cannot increase
  output value", is proved unconditionally at both the list level and the
  model's `commitmentOutputs` level.  The second claim, "trimmed value is
  accounted for as fee", is false for the current model without a credit
  hypothesis: `Commitment.feeSat` is an independent field and no operation
  updates it.  The faithful unconditional statement
  `dust_trim_preserves_conservation` is retained with one `sorry` and the
  unique marker.  Its negation is mechanized by
  `dust_trim_preserves_conservation_counterexample`; the corrected statement
  `conservation_of_dustFeeAccounted` and the iff
  `conservation_iff_dustFeeAccounted` are fully proved.

## Missing model field / next step

`Commitment` has a `feeSat` field but no dust-limit-aware constructor.  In
particular:

1. `Commitment.commitmentOutputs` trims only `toLocalSat = 0` /
   `toRemoteSat = 0`; it never consults `ChannelParams.dustLimitSat`.  It is
   exactly the dust rule with limit 1 (`commitmentOutputs_value_eq_trim_one`).
2. When the real dust limit is applied, the dropped value is not added to
   `feeSat`.  `dustFeeAccounted` names the missing link; the model neither
   constructs nor validates it.

Next step for integration: add a trimming operation that returns both the kept
outputs and the fee increment (or a `ChannelParams.dustLimit`-parameterized
`Commitment` constructor), then prove `dustFeeAccounted` by construction.  A
separate, already-recorded gap remains at the HTLC level: `candidateOutputs`
uses gross `amountSat`, while BOLT 3 trims on `amount - second_stage_fee`;
that belongs to the HTLC workstream (`isDustHTLC`).
