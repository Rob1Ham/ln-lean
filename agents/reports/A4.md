## 4. Open items and next smallest step

No open placeholders in the four modules. The following are explicitly
outside the scaffold and are the natural wave-B/C obligations:

1. **Concrete shachain/SHA-256 instantiation.** `Shachain.derive` is a
   parameter. Next smallest step: import the Crypto model (wave B) and
   instantiate `Shachain` with `build_commitment_secret`-style derivation,
   proving `derive_size` and `derive_injective` from SHA-256 hypotheses.
2. **HTLC-output penalties.** `PenaltyTx` sweeps the two main outputs only.
   BOLT 5 also resolves HTLC-timeout/HTLC-success outputs. Next step: add a
   second-output-class variant that spends revoked HTLC outputs.
3. **L1 script bridge.** `L1ScriptBridge.noDoubleSpend` is an interface.
   Next step: instantiate `confirms` from `vendor/btc-lean-core`'s
   `Bitcoin.Interpreter` and derive the field, or record it as a named
   assumption in `docs/ASSUMPTIONS.md`.
4. **HTLC count bound.** `addHTLC` checks total value but not the 483-HTLC
   count. Next step: add a live-count parameter and the count guard, then
   prove the count bound.
5. **Per-commitment orientation.** The model uses one point of view
   (`Direction.local` = offered by us). Flipping orientation for the
   counterparty commitment is not modelled.
6. **Crypto conditionality.** Preimage soundness is only the transition
   guard `hashFn p.bytes = paymentHash`; no preimage-resistance theorem is
   claimed. Signature checks are not modelled in `Penalty`.
