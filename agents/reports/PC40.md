## What is modelled

The subset is the four BOLT 11 tags `p` (1), `s` (16), `d` (13), `x` (6).
A semantic value is `Value.paymentHash b`, `Value.paymentSecret b`,
`Value.description b` (opaque UTF-8 payload bytes), or `Value.expiry n`
(seconds).  `TagList` is an ordered list of values with the per-value
predicate `Value.Canonical`:

* `p`/`s`: payload size = `groupsToBytes 52` = 32 bytes;
* `d`: payload size ≤ `MAX_TAGGED_FIELD_DATA_BYTES` = 639 bytes;
* `x`: `n < 2^64`, encoded in minimum-width big-endian (`expiryWidth`).

`encodeField`/`encodeFields` produce `Field = { tag : Tag, data : ByteArray }`;
`decodeField`/`parseFields` reject unknown tags, wrong fixed lengths,
oversize descriptions, non-minimum-length expiries, and expiries above 8
bytes.  The main theorem is `TagList.parse_encode`:
`parseFields (encode l) = some l.values` for every `TagList l`.

`shortHashBytes.size = 31` encodes to a field whose tag is `p`, but

canonicality hypothesis in `TagList.parse_encode` cannot be dropped.

## Correspondence to the existing model

* `TagKind.toTag` embeds into `LnLean.Payment.Tag`; `TagKind.toTag_code`
  proves the numbers agree (`1`, `16`, `13`, `6`).
* `TagKind.toTag_fixedDataLength` proves the local fixed-group table agrees
  with `LnLean.Payment.Tag.fixedDataLength`.
* `valid_paymentHash_groups`/`valid_paymentSecret_groups` connect BOLT 11's
  52 groups to `Invoice.Valid.paymentHashLength`/`paymentSecretLength`
  (`LnLean.Payment.Invoice`, `LnLean.Proofs.Payment.InvoiceProps`).
* The expiry encoding uses `LnLean.Wire.beBytes`/`decodeBE` from
  `LnLean/Wire/BigSize.lean`, but `x` is a plain big-endian integer, not a
  BigSize.  The `uint64` bound mirrors LDK's checked `parse_u64_be` /
  `IntegerOverflowError`.
* This parser starts from separated `Field`s.  It is the per-tag contract a
  future `RawInvoice`/`decodeSemantic` wiring must refine; no bech32 step is
  assumed.

## Remaining obligations (no `sorry` used)

These are explicit future bridges, not admitted lemmas.  Names and the exact
missing field/hypothesis are given so later work can add them without
weakening this module.

1. **`PC3-PC40-BECH32`** — bech32/charset/checksum/HRP and the signable
   digest.  Missing structure field: a codec record with
   `encodeFields32 : List Field → ByteArray`,
   `decodeFields32 : ByteArray → Option (List Field)`, and the hypothesis
   `roundtrip : ∀ fs, decodeFields32 (encodeFields32 fs) = some fs`.  No such
   codec exists in the tree (`LnLean.Payment.Invoice` documents this as
   `LN-PAY-INVOICE-ENCODING`), so it is not assumed.
2. **`PC3-PC40-PADDING`** — 5-bit group packing, bit padding, and the 10-bit
   `data_length` prefix.  Missing structure: `FieldWire` with fields
   `type5 : Fin 32`, `dataLength10 : Fin 1024`,
   `dataGroups : List (Fin 32)`, and the bridge
   `pack : ByteArray → List (Fin 32)` plus
   `pack_unpack : ∀ b, unpack (pack b) = b`.  This module only proves the
   byte-level arithmetic (`groupsToBytes_52 = 32`, etc.).
3. **`PC3-PC40-UTF8`** — UTF-8 validation of `d` and the `String` view.
   Missing hypothesis: `utf8Roundtrip : ∀ s : String,
   String.fromUTF8? s.toUTF8 = some s` (Lean core lacks this lemma), and the
   bridge `Value.toInvoiceDescription?` for `InvoiceDescription.direct`.
   The description payload is opaque bytes here, so no UTF-8 claim is made.
4. **`PC3-PC40-COUNTS`** — BOLT 11's exactly-one-`p`, exactly-one-`s`,
   exactly-one-`d`-or-`h`, at-most-one-`x`, and "most-preferred first"
   ordering.  Missing predicate/field: a `TagList.WellFormed : TagList → Prop`
   with count and order clauses, plus the theorem
   `WellFormed → encodes accepted by LDK check_field_counts`.  This parser
   proves per-field and per-list round trips only.
5. **`PC3-PC40-SUBSUMOUT`** — tags outside the subset (`n`, `h`, `c`, `f`,
   `r`, `9`, `m`) are rejected by `decodeField`.  Widening is future work;
   their fixed lengths are already in `Tag.fixedDataLength`.  Missing
   extension: additional `Value` constructors and `decodeField` branches,
   plus a proof that the extended parser round-trips.
6. **`PC3-PC40-SIG`** — payment-hash/preimage and signature authorization.
   Reuse `Invoice.preimageCommits` with an explicit hash-function parameter
   (C1) and `InvoiceSignatureAssumption` with `eufCmaHolds`/`sound`
   (`LnLean.Proofs.Payment.InvoiceProps`); this module proves neither.

Next smallest step: add `FieldWire` and the 5-bit pack/unpack functions with
`unpack_pack`, then restate `TagList.parse_encode` over the wire codec.  That
closes `PC3-PC40-PADDING` without touching this module's semantic round trip.
