## 3. Proof approach and helper lemmas

`settleHTLCOutputErase` either is a no-op (`hadOutput = false`, hence `c` is
returned and `hc` closes the goal) or replaces `c.htlcs` by
`c.htlcs.erase h` and credits `h.amountSat` to `fundingSide` of the
appropriate creditor.  Conservation follows from the exact output-sum
identity

```
totalOutputValue { creditCommitment c side h.amountSat with
                   htlcs := c.htlcs.erase h } = totalOutputValue c
```

because `feeSat` and `fundingValueSat` are untouched by both operations.

The value identity is proved in three small steps:

1. `amount_le_htlcOutputsValue`: by induction on the list; membership puts
   `h.amountSat` in the sum, so the subtraction in the next step is exact.
2. `htlcOutputsValue_erase`: use the core lemma `List.exists_erase_eq` to
   decompose `c.htlcs = before ++ h :: after` with
   `c.htlcs.erase h = before ++ after`; `htlcOutputsValue_append` reduces the
   claim to arithmetic, closed by `omega`.  This is exactly the
   duplicate-valued case: `erase` removes one list element, not one value,
   and equal-valued entries have equal `amountSat`.
3. `totalOutputValue_credit_erase`: case on `BalanceSide` and on
   `anchorOutputs`; unfold `totalOutputValue`/`htlcOutputValue` and combine
   the previous identity with the credited amount by `omega`.

The model derives `BEq` and `DecidableEq` separately and does not export
`LawfulBEq` for `Direction`, `HTLCState`, or `CommitmentHTLCOutput`.  The
`List.erase` lemmas need `LawfulBEq`, so the file adds three `private`
instances proved directly from the derived implementations
(`Direction`/`HTLCState` compare `ctorIdx`; `CommitmentHTLCOutput` compares
all four fields).  No new `BEq` instance is introduced, so the `List.erase`
inside the existing public definition still uses the model's original
derived `BEq`.
