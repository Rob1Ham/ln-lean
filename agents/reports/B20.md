## 4. What remains open, and the next smallest proof step

The file deliberately proves the contract over a two-field `ChannelView`
(`channelId`, `phase`) rather than the full channel state machine.  This is
because the assigned wave-A import set is `LnLean.Protocol.Messages` +
`LnLean.Basic.Core`; `LnLean.Channel.State` belongs to another wave-A module
and is not imported here.

Open items:

1. **Bridge to the full channel state machine.**  `ChannelView.failed` is
   `phase = .closed`.  There is no theorem yet that the state machine's close
   transition and `applyToChannel (.error e)` agree, nor that funds/HTLCs are
   resolved by the error path.
2. **Wire `data` is not an error code.**  BOLT 1 `error` carries free-form
   bytes; the `ErrorCode` enumeration is an internal classification.  The
   module proves the enumeration is total over `ProtocolError.code` but does
   not decode wire data into it.
3. **No printable-ASCII enforcement.**  BOLT's sanitisation recommendation is
   documented but not modelled; `data` is an arbitrary `ByteArray`.
4. **No peer identity in the all-zero case.**  `handleInbound` treats the
   supplied list as one peer's channels.  A future `ChannelView` with a
   `peerId` field should prove that an all-zero error affects only channels
   belonging to the sender.
5. **Warning side effects are not modelled.**  BOLT says a receiver MAY
   attempt `shutdown`; the file proves only that the phase is unchanged.
6. **No connection teardown.**  LDK disconnects after an all-zero error
   (`peer_handler.rs:2422-2424`); this is outside the channel projection.

Next smallest proof step: add a projection
`ChannelView.ofState : LnLean.Channel.State → ChannelView` in a follow-up
wave-B module that may import `LnLean.Channel.State`, then prove
`(applyToChannel (.error e) (ofState s)).phase = .closed` whenever
`e.channelId` matches `s`'s identifier.  That is the missing link between the
error messages and the full state machine; it does not require changing the
theorems in this file.
