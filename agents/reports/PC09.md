## Why the original statement is blocked

`spendLocalBalance b amountMsat` uses truncated subtraction:

```lean
{ b with localBalance := ⟨b.localBalance.val - amountMsat⟩ }
```

The theorem has no hypothesis bounding `amount.val` by
`c.balance.localBalance.val`.  If `amount.val > localBalance.val`, the
settled balance loses only `localBalance.val`, while the appended pending
HTLC contributes the full `amount.val` to `htlcInFlightValue`.  The
counterexample in the file uses a zero-balance, zero-funding channel and
`amount = 1 msat`: the successor has `0 + 1 + 0 ≠ 0`.

The corrected theorem therefore carries the BOLT 2 funding precondition

```lean
h_fits : amount.val ≤ c.balance.localBalance.val
```

and proves the same ledger equation by unfolding the append/filter sum and
using `omega` (`spendLocalBalance_total_val` rewrites the total to
`c.balance.total.val - amount.val`).

Missing bridge: a `Step` / `update_add_htlc` constructor that enforces
`amount.val ≤ c.balance.localBalance.val`.  Once such a constructor supplies
`h_fits`, `committed_update_preserves_ledger_of_le` discharges the ledger
arithmetic directly.

Next smallest step: add that balance-bound constructor to
`LnLean/Channel/State.lean` (owned outside this lane), then restate the
target theorem with the constructor (or derive `h_fits` from it) and apply
`committed_update_preserves_ledger_of_le`.
