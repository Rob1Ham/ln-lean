## 3. Proof approach and helper lemmas

`anchorWitnessScript fundingKey` unfolds to

```
pushData fundingKey.bytes ++ <fixed six-opcode suffix>
```

* Take `congrArg Script.bytes h` to move from `Script` equality to `ByteArray`
  equality (the L1 `Script` structure has no `DecidableEq`, only `Repr`).
* Right-cancel the identical opcode suffix with
  `ByteArray.append_left_inj`: `pushData k₁.bytes = pushData k₂.bytes`.
* The new private helper `pushData_injective` unfolds
  `pushData b = (empty.push b.size.toUInt8) ++ b`.  Both one-byte length
  prefixes have size `1`, so `ByteArray.append_eq_append_iff_of_size_eq_left`
  splits the equation into prefix equality and payload equality; the payload
  component is `a = b`.
* Close `k₁ = k₂` by `cases` on the `PubKey` structures.

`localAnchor_hash_ne_remoteAnchor_hash` rewrites both stored hashes with the
`HashesMatch` projections `h.2.2.1` / `h.2.2.2`, applies the injectivity
hypothesis `hcr` to obtain equal witness scripts, then applies
`anchorWitnessScript_key_injective` and contradicts `hkeys`.  The
collision-resistance hypothesis `hcr` remains explicit in the statement, so
the crypto assumption is still visible.

No model fields were added and no L1/vendor files were edited.
