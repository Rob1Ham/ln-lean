## 3. Proof approach and helper lemmas

* Added `private theorem htlcInFlightValue_append_pending`.  It unfolds
  `htlcInFlightValue` and rewrites with `List.filter_append`,
  `List.map_append`, and `List.sum_append`; the singleton pending HTLC then
  reduces to its amount.
* Added `committed_update_preserves_ledger_of_guard`, which is the true
  arithmetic statement once BOLT 2's affordability guard
  `amount.val ≤ c.balance.localBalance.val` is assumed.  The proof:
  1. substitutes the constructed `c'`;
  2. rewrites `htlcInFlightValue c'` to `htlcInFlightValue c + amount.val`;
  3. proves `(spendLocalBalance b a).total.val = b.total.val - a` using the
     guard (truncated subtraction does not bite);
  4. closes the resulting linear arithmetic with `omega` and `h_old`.
* The original theorem statement was **not** changed.  The new guarded theorem
  is a documented companion, not a replacement.

## 4. False / unprovable statement

`committed_update_preserves_ledger` is false as stated for the current model.
`spendLocalBalance` uses truncated `Nat` subtraction, and the hypotheses never
bound `amount.val` by the local balance.  Since `amount` is an arbitrary
`Msat`, the appended pending HTLC can add more to `htlcInFlightValue` than the
balance drop removes.

Counterexample:

* `c.balance.localBalance = ⟨1000⟩`, `c.balance.remoteBalance = ⟨0⟩`
* `c.fundingValue = ⟨1000⟩`, `c.htlcs = []`, `fee = ⟨0⟩`
* `amount = ⟨1001⟩`

Then `h_old` is `1000 + 0 + 0 = 1000`, and `h_step` is satisfiable by the
record update.  But `spendLocalBalance` gives local balance
`1000 - 1001 = 0`, while the new pending HTLC contributes `1001`, so the
conclusion is `0 + 1001 + 0 = 1000`, i.e. `1001 = 1000`.

Missing model field/precondition: BOLT 2 `update_add_htlc` requires the sender
to retain its reserve and to have sufficient balance, i.e. at least
`amount.val ≤ c.balance.localBalance.val` (in the fuller model,
`reserve * 1000 + amount.val ≤ localBalance.val`).  The current `Step`
relation does not model balance-changing updates at all, so this guard is
absent from the statement.  `committed_update_preserves_ledger_of_guard`
proves the intended result under that guard.

The module already records that the gross dust rule is weaker than BOLT 3's
net-of-HTLC-fee rule (`gross_dust_rule_insufficient`); that is a separate,
already-proved gap and does not affect `LN-CH-101`.
