## Remaining gap / next step

- Actual serialized weight is not modelled: `Bitcoin.Data.Tx` has no weight function, so the Appendix A byte check is arithmetic on BOLT 3's stated byte counts, not a bound on a real transaction (same limitation as `Proofs.Bitcoin.WeightProps`). Next step: add `Tx.weight`/serialized-size semantics to the L1 seam and prove the expected weight is attained under BOLT 3's 73-byte-signature assumption.
- `numHtlcs` counts *untrimmed* outputs; this module does not decide dust trimming. Next step: import `LnLean.Channel.Fee` and prove the untrimmed-count characterization.
- The anchor variant's extra 400 weight units and the `shared_anchor`/zero-fee-commitment variants are outside this obligation; only the separation `724` vs `1124` is proved.
