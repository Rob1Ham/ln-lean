# D11 — No commitment output has a negative value and the output sum stays within the funding value

## Target

- Parent/catalog: `LN-CH-002`
- Module: `LnLean.Proofs.WaveD.D11`
- File: `LnLean/Proofs/WaveD/D11.lean`

## Result

- Status: conditional (non-negativity unconditional; sum bound needs the
  BOLT 3 balance equation, proved unconditionally for the canonical
  constructions, with checked counterexamples for arbitrary records)
- Build: RC 0 with
  `flock -w 900 /tmp/ln-build.lock lake build LnLean.Proofs.WaveD.D11`
  (Lean `v4.35.0`, PATH `/dev/shm/btc/elan/toolchains/leanprover--lean4---v4.35.0/bin`).
  `python3 scripts/check-wave-d.py` reports `D11 CLOSED markers=1`; no
  `sorry`/`axiom`/`admit`/`native_decide`/`unsafe`/`@[implemented_by]` and
  no Mathlib or new dependency.
- Theorems/definitions:
  - `waveD_d11_output_value_nonneg` — every `o ∈ c.commitmentOutputs` has
    `0 ≤ o.value`; no hypothesis.
  - `waveD_d11_all_outputs_nonnegative` — record-level form of the same.
  - `waveD_d11_outputsValue_eq_total` — the list sum
    `(c.commitmentOutputs.map CommitmentOutput.value).sum` equals
    `c.totalOutputValue` (zero `to_local`/`to_remote` omitted, anchors 330
    each).
  - `waveD_d11_output_value_le_total` — each emitted output is at most
    `c.totalOutputValue` (`private value_le_sum_of_mem` helper).
  - `waveD_d11_outputs_within_funding` — if
    `c.totalOutputValue + c.feeSat = c.fundingValueSat`, then the emitted
    list sum is at most `c.fundingValueSat`.
  - `waveD_d11_output_value_le_funding` — same hypothesis, every single
    emitted output is at most the funding value.
  - `waveD_d11_outputs_nonnegative` — catalog-level conjunction of
    unconditional non-negativity and the conditional sum bound.
  - `waveD_d11_settled_outputs_eq_funding_sub_fee` and
    `waveD_d11_settled_outputs_within_funding` — the canonical
    `settledCommitment` has output sum exactly `funding - fee`, hence at
    most `funding`, under the cover hypothesis
    `fee + toLocal + htlcOutputsValue htlcs + anchors ≤ funding`.
  - `waveD_d11_zeroHtlc_outputs_within_funding` — the zero-HTLC
    (`zeroHtlcCommitment`) opening/settled case.
  - `waveD_d11_residual_outputs_within_funding` — any record whose
    `toRemoteSat` is the BOLT 3 residual
    `funding - fee - toLocal - htlcs - anchors`, with the cover hypothesis,
    stays within funding.
  - `waveD_d11_pair_outputs_within_funding` — both commitments of
    `commitmentPairOfBalances` stay within funding when anchors are
    disabled and `fee ≤` the funder's balance.
  - `waveD_d11_overspentCommitment`, `waveD_d11_overspent_outputs_exceed`,
    `waveD_d11_overspent_still_nonnegative` — checked counterexample:
    `toLocalSat = 1`, `fundingValueSat = 0` is non-negative but its output
    sum exceeds funding.
  - `waveD_d11_anchorParams`, `waveD_d11_anchorBalance`,
    `waveD_d11_pair_anchor_outputs_exceed`,
    `waveD_d11_pair_anchor_outputs_list_exceed` — checked counterexample:
    `commitmentPairOfBalances` with anchors and zero fee emits 2660 sat
    against a 2000-sat funding value.
- Added hypotheses: only the BOLT 3 balance/cover equations stated
  explicitly in each theorem.  The non-negativity claim has no added
  hypothesis.
- Statement fidelity:
  - The model represents every output value as `Nat`
    (`CommitmentOutput.value : CommitmentOutput → Nat`), so "no output is
    negative" is true by the type and is not weakened: a negative output is
    unrepresentable, and zero-valued `to_local`/`to_remote` outputs are
    omitted by `commitmentOutputs` (BOLT 3 trimming).  The theorem is still
    a real statement about the concrete emitted list, including HTLC and
    anchor outputs.
  - The catalog's second half is not true for an arbitrary `Commitment`
    record, because the record type does not enforce the BOLT 3 balance
    equation.  The faithful forms are the conditional record theorem and
    the unconditional canonical `settledCommitment`/`zeroHtlcCommitment`
    theorems; the counterexample documents the exact missing invariant.
  - The anchor counterexample records a pre-existing model gap in
    `commitmentPairOfBalances` (already noted in
    `LnLean.Proofs.Conservation`): the builder sets `anchorOutputs` but does
    not debit `2 * anchorOutputSat` from the funder's output.  This module
    does not modify the model.

## Remaining gap / next step

- The model should make `Commitment` well-formed by construction (or add a
  `CommitmentConserved` field/invariant): `to_remoteSat` must be the BOLT 3
  residual with a cover proof.  Then `waveD_d11_outputs_within_funding`
  would apply without an extra hypothesis, and the catalog target
  `LnLean.Channel.Commitment.outputs_nonnegative` could be stated
  unconditionally.
- `commitmentPairOfBalances` should subtract `2 * anchorOutputSat` from the
  funder's output when `option_anchors` is negotiated (LDK
  `insert_non_htlc_outputs`), removing the anchor counterexample.
- Not modelled here: script/witness bytes, output ordering, the
  single-anchor exception, and the `shared_anchor` output.
