- Added hypotheses: none.
- Statement fidelity: The claim is a structural statement about `peel`, and it is true unconditionally in the model. `OnionPacket.layers` is an outermost-first list; `peel` pattern-matches on it, returning `some (.forward l.hop {p with layers := ls})` for `l :: ls` and `some (.final p.routingInfo)` for `[]`. `OnionPayload.forward` and `.final` are distinct constructors, so a single result cannot be both. `peel` does not decrypt or check an HMAC; that is `openLayer`, whose acceptance condition is separate and unused here. The catalog's Lean target name `LnLean.Routing.Onion.peel_deterministic` is not declared in the model, so the target is realised here as `waveE_e24_peel_deterministic` (plus the exclusive-branch theorem `waveE_e24_peel_never_both`), without editing the model.

## Remaining gap / next step

The model's `peel` is the structural/unwrapped split only. The cryptographic statement "a node accepts the layer and then forwards or delivers" additionally needs the C8 assumption `OnionInterface.hmacBinding` and a connection theorem between `openLayer` and `peel`; neither is required for `LN-RT-003` as stated. The branch claim is not weakened, so no missing model field blocks it.
