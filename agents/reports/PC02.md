### Capacity bound

`channelCapacityMsat p = fundingSatoshis * MSAT_PER_SAT` and
`MSAT_PER_SAT = 1000`.  Well-formedness gives
`fundingSatoshis ≤ MAX_MONEY`, and `MAX_MONEY = 21_000_000 * COIN =
2_100_000_000_000_000`.  Multiplying by the nonnegative constant `1000`
yields `≤ 21_000_000 * 100_000_000 * 1000`, which is definitionally
`Msat.MAX.val`.  No new axioms or Mathlib.

### Why the unconditional parse theorem is false

`FundingParams` does not constrain funding-key lengths.  `pushData` writes
the key length as a single `UInt8` (truncating it), so a key of length 81 has
length byte `0x51`, which the wave-A parser reads as `OP_1` rather than as a
33-byte push.  The rest of the key is then decoded as opcodes.

The counterexample `cexP` uses two identical `cexKey`s of 81 bytes:

```
4b 00*69 0c 00*5 4b 00*4
```

With `orderedFundingKeys_self`, the witness script bytes are explicit, and
`decide` checks the five parser steps (offsets `0 → 1 → 2 → 78 → 154 → 167`).
At offset 154 a push swallows the final `OP_CHECKMULTISIG`, so `parse`
returns `some …`, not `none`.  The theorem is therefore genuinely refuted by
the definitions in this repository, not merely hard to prove.

The corrected theorem adds `p.WellFormed`, which forces both keys to be 33
bytes.  In that case each key is a direct `0x21` push, the parser advances
`1 → 35 → 69 → 70`, and `parseWith_checkMultisig` rejects the trailing
`OP_CHECKMULTISIG` because `ScriptInstr` has no case for it.
