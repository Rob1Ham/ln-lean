### Capacity bound

`channelCapacityMsat p = p.fundingSatoshis * 1000`.  `p.WellFormed` gives
`0 ≤ p.fundingSatoshis ≤ Bitcoin.Data.MAX_MONEY`; multiplying by the
nonnegative `1000` and unfolding `MAX_MONEY`, `COIN`, and `Msat.MAX` yields
`channelCapacityMsat p ≤ Msat.MAX.val`.  No Mathlib, no new axioms.

### Why the unconditional parse theorem is false

`FundingParams` does not constrain key sizes.  `pushData` stores the key
length in one `UInt8`, so an 81-byte key has length byte `0x51`, which the
wave-A parser decodes as `OP_1`; the key body is then followed as opcodes and
can swallow the trailing `OP_CHECKMULTISIG` as push data.  The proved
counterexample uses two identical keys
`4b 00*69 0c 00*5 4b 00*4` and `decide`-checked parser steps through offsets
`0 → 1 → 2 → 78 → 154 → 167`.

For `p.WellFormed`, both keys are 33 bytes (`PubKey.Valid`), so each is a
direct `0x21` push; the parser advances `1 → 35 → 69 → 70`, reaches the
trailing `OP_CHECKMULTISIG`, and `decodeOp` returns `none` because
`ScriptInstr` has no `checkMultisig` constructor.  This is
`witnessScript_parse_eq_none_of_wellFormed`.
