## 4. What remains open

1. **`LN-PAY-MPP-001` — permutation invariance of the collected total.**
   `sumParts_addParts_perm` is the only `sorry` in this file. It is true
   (`addParts` keeps exactly the distinct records, and reordering the input
   reorders only the accumulator, not the retained amounts) but needs a fold
   invariant that carries both the membership set and the sum through
   `List.Perm`.
   *Next smallest step:* prove `addPart` commutes on sums,
   `sumParts (addPart (addPart acc y) x) = sumParts (addPart (addPart acc x) y)`
   by the four membership cases, then lift to
   `sumParts (l.foldl addPart acc)` by induction on `List.Perm` with an
   accumulator-membership invariant. `sumParts_addParts_of_nodup` already
   gives the duplicate-free case.
2. **Overpay (`LN-PAY-MPP-OVERPAY`).** BOLT 4 requires the set total to be
   `≥ total_msat`, not exactly equal; `mppComplete` is the exact-sum special
   case and `mppCompleteGe` records the lower-bound form. The overpay safety
   theorem (no part above twice the invoice amount) needs the BOLT 11 amount,
   which `MPPPlan` does not carry. *Next step:* add an `invoiceAmount : Msat`
   field or a `PlanLinkedToInvoice` predicate and prove
   `total ≤ 2 * invoiceAmount` under the BOLT 4 writer rules.
3. **Per-part hash/secret fields.** `MPPPart` has no `paymentHash` or
   `paymentSecret` field, so "all parts share" is true by construction for
   plan parts and is stated conditionally (`WirePart.matches`) for observed
   parts. A model change adding these fields would let the unconditional
   statement be proved; the proof file cannot add fields to wave-A records.
4. **HTLC identity.** Duplicate detection here is whole-record equality.
   `sameKey_distinctAmount_both_counted` proves that two parts with the same
   channel and CLTV but different amounts are both retained. LDK keys an
   HTLC by `(channel_id, htlc_id)`; `MPPPart` has neither, so full BOLT 4
   duplicate rejection is not expressible without a model change.
5. **Settlement does not check the preimage.** `PaymentSession.settle` and
   the proof-layer `settleParts` change state only; `paymentHash` is carried
   but no preimage is present. Preimage soundness belongs to the crypto /
   channel layer and is not claimed here.
6. **Liveness / `mpp_timeout`.** Only safety ("never a mixed outcome") is
   stated. Eventual collection under partial synchrony is outside this file.

No wave-A file was edited. `settlePart`/`settleParts`/`AllOrNothing`/`WirePart`
are proof-layer definitions in this module, not changes to the model.
