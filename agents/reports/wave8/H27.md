## Scope caveats

- **Value-only downstream account.** Scripts, witnesses, sighash, signatures,
  and consensus validity are out of scope; the theorems are about
  `CommitmentOutput.value` / `CommitmentTxOutput.valueSat` sums.
- **Second-stage fee is not part of the commitment fee.** The identity is
  `effectiveFee = base fee + trimmedTotalSat`. The HTLC second-stage fee is
  withheld later by the HTLC-timeout/success transaction out of the gross HTLC
  output. This module does not model those child transactions and does not
  include their fee in either side.
- **`netAmountSat` relation stays external.** No theorem assumes
  `net + second_stage_fee = gross`; the `NetConsistentOnRecords` boundary of
  `CommitmentTypesTargets` remains the only bridge and is not consumed here.
- **The balance equation is the exact value hypothesis.** Every three-term and
  effective-fee theorem takes `CommitmentConserved tx.commitment`. The
  `underfundedTx` counterexamples show it cannot be dropped.
- **No positivity hypothesis for value accounting.** `0 < dustLimitSat` is
  *not* used by any theorem in this module. It remains necessary only for
  `Migrated`/list equality/permutation at the consumer boundary (wave 6/7),
  not for value sums.
- **The legacy two-term predicate is insufficient under trimming.** On a
  migrated record `CommitmentConserved` holds iff `trimmedTotalSat = 0`.
  Consumers that only assert the legacy predicate undercount the fee by the
  trimmed gross value; they must use the three-term equation or
  `effectiveFeeSat`.
- **Ordering.** D12's refutation stands: this module proves sums and value
  identities, never list equality/ordering of `commitmentOutputs`.
- **`commitmentPairOfBalances` with anchors.** The concrete pair instance is
  restricted to `anchorOutputs = false` on both sides, matching the existing
  `commitmentPairOfBalances_conserved` theorem. The builder's anchor-debit
  gap (`commitmentPair_anchorCounterexample`) is outside this lane.
