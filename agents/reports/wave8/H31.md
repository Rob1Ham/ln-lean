### 1. The checker equality (proved locally)

```lean
theorem schnorrVerdict_failClosed (verify : ByteArray → ByteArray → ByteArray → Bool)
    (sig pk : ByteArray) (v : SigVersion) (d : ScriptExecutionData) :
    schnorrVerdict verify (fun _ _ _ => none) sig pk v d = false

theorem txCheckerFor_some_eq_realCheckerOf (tx : Bitcoin.Data.Tx) (nIn : Nat)
    (amount : Amount) :
    Bitcoin.TxValidation.Full.txCheckerFor tx nIn (some amount) =
      Bitcoin.Capstone.RealChecker.realCheckerOf tx nIn amount
```

`txCheckerFor` assembles ECDSA **and** Schnorr via `txCheckerOf`;
`realCheckerOf` carries only `ecdsaEntry`.  The Schnorr fields agree because
`txCheckerFor`'s BIP 342 sighash is the fail-closed `fun _ _ _ => none`, so
`schnorrVerdict` is constantly `false` — the value `ecdsaEntry` puts there.
Both index `tx.vin` with `Bitcoin.Capstone.RealChecker.dummyTxIn`, so the
equality needs **no** in-range hypothesis.

## Scope caveats

- **Positive-direction P2WSH only.**  The left-hand side is the vendored
  `verifyWitnessProgram` (the P2WSH branch) called with the witness stack
  directly; the `scriptSig`/`scriptPubKey` pre-parse of `verifyScriptFull`, the
  `scriptLane` fold and `txVerdictFull` composition are **not** part of this
  result (lane H04's composition target).  In particular this module does not
  prove that `txVerdictFull` accepts a transaction.
- **Flag word is the literal `{ csv := true }` with `pol = {}`.**  That is the
  word wave 5/7 mechanized.  `OP_CSV` reads `flags.csv`; because that word has
  `dersig = false`, the `OP_CHECKSIG` encoding gate is inert, so no BIP 66 DER
  premise is needed.  A `getBlockScriptFlags height` instantiation (with
  `dersig = true`) would additionally require `isValidSigEncoding sig = true`;
  that transfer is **not** mechanized.  CSV activation itself is wave 7's
  `getBlockScriptFlags_csv_of_csvHeight_le`.
- **`csv < 32768`** stays a hypothesis (fixed-width two-byte delay must decode
  non-negatively).  The `csv ≥ 32768` / disable-bit edge is lane H06's.
- **Explicit `amount : Amount`** is the spent output value.  The digest commits
  to it (BIP 143); this module does not claim it equals the value of the
  referenced outpoint, nor that the outpoint exists.
- **`amount = none`** is the missing-data state (`amount < 0`,
  `HandleMissingData`); the module proves the delayed branch is then
  *impossible*, not that some other branch is chosen.
- **In-range premise** `nIn < tx.vin.length` is required to name the signing
  input's `nSequence`; the out-of-range `getD` totalizations genuinely differ
  (`0xFFFFFFFF` versus `0`), mechanized above.
- ECDSA remains the concrete vendored **lax** verifier
  `Bitcoin.Crypto.Ecdsa.Verify.verifyImpl`; no EUF-CMA/computational claim
  (C3) is made or used.  Schnorr remains the fail-closed `none` stand-in.
- No claim that the `to_local` witness script bytes are the BOLT 3 script for a
  particular channel: the script hash premise `hprog` is explicit, and the
  script is `toLocalOps` (wave-5 canonical form).
