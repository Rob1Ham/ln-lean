  compactSizeEnc ws.length ++
    ws.foldl (fun acc item => acc ++ compactSizeEnc item.size ++ item)

def serWitnessSection (witness : List WitnessStack) : ByteArray :=
  match witness with
  | [] => ByteArray.empty
  | _ =>
      serU8 0x00 ++ serU8 0x01 ++
        witness.foldl (fun acc ws => acc ++ serWitnessStack ws) ByteArray.empty

## The math, in one paragraph

For a `4 + k`-output anchor commitment the base serialization is
`4 + 1 + 41 + 1 + (43 + 43 + 43 + 43) + 43*k + 4 = 223 + 43*k` bytes (the
anchor `to_remote` is P2WSH, so `43` not `31`). The funding input witness is
BOLT 3's `⟨∅, sig(73), sig(73), multi_sig(71)⟩`, which serializes to
`1 + 1 + 74 + 74 + 72 = 222` bytes, plus the 2-byte marker/flag header = `224`.
Hence the literal weight is `4*(223 + 43k) + 224 = 1116 + 172k`. BOLT 3's fee
section charges on `1124 + 172k`, i.e. on a `225`-byte base, which its
Appendix A table obtains from `count_tx_out: 3 byte` — a three-byte
CompactSize for a four-output transaction, contradicting the fee section's own
assumption "there are a small number of outputs (thus 1 byte to count them)".
The `8 = 4 * 2` residual is exactly that field, and is independent of *any*
witness byte count (`gap_witness_independent`). The literal `1124` claim is
therefore false and is retained as `anchor_literal_weight_neq_fee_basis`; the
sharp condition for equality is `countBytes = 3`, reachable only at
`0xfd ≤ 4 + k` (≥ 253 outputs). The fee consequence is exact and non-trivial:
at BOLT 3's own example feerate of 5000 sat/kw the fee basis overcharges by 40
satoshis (`bolt3_example_rate_anchor_fees`), bounded in general by
`ceil(8 * feerate / 1000)`.

## Scope caveats

- The 73-byte DER signature and 71-byte `multi_sig` lengths are BOLT 3's
  maximum/fixed assumptions, supplied as explicit size hypotheses. Actual
  DER-length variability is not modelled (same boundary as `WeightTargets`).
- The serialization theorem covers `4 + k < 0xfd` outputs (one-byte count).
  The ≥ 253-output case is covered only by the conditional
  `appendixA_eq_fee_basis_iff` / non-vacuity instance; the ≥ 65536-output
  five-byte count (a further 8 WU) is not modelled.
- HTLC outputs are assumed untrimmed, as in `WeightTargets`; dust/second-stage
  fee selection stays in `LnLean.Channel.Fee` / wave-D `D12`.
- Anchor output script hashes remain 32-byte parameters; SHA-256 preimage
  computation is not performed here.
- No claim that `1124` is a *lower* bound on any commitment record; it is the
  negotiated fee-basis upper bound, strict at every `k`.
- The witness-section model assumes a non-empty witness list for segwit
  serialization (`serWitnessSection []` is the legacy empty form), which is
  the only case the commitment transaction reaches.
