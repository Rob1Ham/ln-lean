```lean
structure PopTranscript where
  channelId : ByteArray      -- accept_channel.temporary_channel_id bytes
  challenge : ByteArray      -- verifier-issued challenge nonce
  signature : EcdsaSig       -- signature over popMessage

def popMessage (t : PopTranscript) : ByteArray :=
  popTag ++ t.channelId ++ t.challenge
-- popTag = #[0x70, 0x6f, 0x70] ("pop"), popTag ≠ fundingTag

def PopAccepted (M : PrimitiveModel) (pk : PubKey) (t : PopTranscript) : Prop :=
  M.ecdsaVerify pk (popMessage t) t.signature = true

structure Registration where
  accept : AcceptChannel
  transcript : PopTranscript

def register (M : PrimitiveModel) (a : AcceptChannel)
    (t : PopTranscript) : Option Registration :=
  if t.channelId = a.temporaryChannelId.bytes then
    if M.ecdsaVerify a.fundingPubKey (popMessage t) t.signature then
      some { accept := a, transcript := t }
    else none
  else none

def PopSoundOn {M : PrimitiveModel} (K : KeyModel M)
    (Issued : PopTranscript → Prop) : Prop :=
  ∀ (pk : PubKey) (t : PopTranscript), Issued t → PopAccepted M pk t →
    ∃ sk : SecretKey, K.Owns pk sk

def PopSound {M : PrimitiveModel} (K : KeyModel M) : Prop :=
  PopSoundOn K (fun _ => True)
```

## Scope caveats

- **`PopSound` is an explicit extraction premise, not a proved reduction.**
  `PopSoundOn K Issued` says every verifying transcript on an issued challenge
  yields a secret key generated with the advertised public key. It is the exact
  algebraic form of the PoP game, but no computational knowledge-soundness
  theorem for secp256k1/ECDSA is proved. A deployment must instantiate it (or
  prove it from the signature scheme's extraction property plus a fresh
  challenge).
- **It is genuinely additional.** `keyBinding_completeness_not_popSound`
  exhibits a C3 + key-binding verifier with a signer complete on every message
  where a transcript verifies under a key that key generation cannot produce.
  So `PopSound` is not derivable from C3, `KeyBinding`, or completeness; key
  binding constrains the key for a fixed signature, not the provenance of the
  signature.
- **Freshness is only the `Issued` predicate.** There is no randomness,
  probability, challenge store, session state, or consumption/uniqueness proof.
  `register` models verifier acceptance of a transcript; challenge generation
  and replay protection are outside the model. `PopSound` is the unrestricted
  (all-transcripts) form consumed by the positive theorems; `PopSoundOn` is the
  issued-set form and is weaker.
- **Signature provenance is still not tracked.** The module proves key
  attribution (`KeyBinding`) and key possession (`PopSound`), the strongest pair
  the symbolic model supports. It does not prove "this wire signature was
  produced by that peer" (`PeerIdentity` remains the transport obligation in
  `docs/ASSUMPTIONS.md` §3 / `FundingAuthTargets`).
- **PoP message encoding is not injective.** `popMessage = popTag ++ channelId
  ++ challenge` has no length prefixes; `popMessage_split_not_injective`
  exhibits two `(channelId, challenge)` splits with the same signed bytes, and
  `popAccepted_of_popMessage_eq` transfers acceptance across the collision.
  Ownership attribution is unaffected, but channel binding requires a
  length-prefixed challenge or a fixed-width channel id. This is recorded as a
  caveat, not assumed away.
- **No concrete EC arithmetic.** Verifiers in the negative/non-vacuity
  witnesses are toy boolean models (`keyedSigVerify`, `twoKeyVerify`,
  `selfSigVerify`, `singleMessageVerify`); they prove logical separation and
  non-vacuity, not computational security. `register` compares raw
  `temporary_channel_id` bytes and does not model BOLT 8 transport framing.
- **`AdvertisesKey` is derived only under `PopSound`.** Without the registration
  event, the wave-7 counterexample
  (`key_generation_not_key_attribution_retained`) still shows that key
  generation + C3 do not attribute a signature. Registration is an additional
  premise on the received message, not a consequence of the wire field alone.
- **Handshake storage is abstract.** `registered_negotiation_key_owned` takes
  the registration premise as a function of `s.acceptReceived`, so it is
  independent of how a verifier persists `Registration` records.
