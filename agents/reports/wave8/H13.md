### `313` reconciliation (the task-table figure)

```lean
/-- The wave-7 sketch basis: `chain_hash` and `channel_reserve_satoshis`
omitted, a 34-byte `shutdown_scriptpubkey` counted without TLV prefix. -/
def reducedBasisLength : Nat :=
  32 + 8 + 8 + 8 + 8 + 8 + 4 + 2 + 2 + 6 * 33 + 1 + 34

theorem reducedBasisLength_eq_313 : reducedBasisLength = 313
theorem reducedBasisLength_add_six :
    reducedBasisLength + 6 = OpenChannelMsg.fixedPayloadLength
theorem reducedBasisLength_ne_fixed :
    reducedBasisLength ≠ OpenChannelMsg.fixedPayloadLength
theorem reducedBasisLength_adjustment :
    reducedBasisLength - 34 + 32 + 8 = OpenChannelMsg.fixedPayloadLength
theorem reducedBasis_gap (m : OpenChannelMsg) (spk : ByteArray)
    (h : m.tlvs = { upfrontShutdownScript := some spk, channelType := none })
    (hspk : spk.size = 34) :
    m.payloadLength = reducedBasisLength + 42
theorem reducedBasis_gap_decomposition : (42 : Nat) = 32 + 8 + 2
```

So `313 + 32 (chain_hash) + 8 (channel_reserve_satoshis) + 2 (TLV type +
BigSize length) = 355 = 319 + 36`, i.e. the reduced basis is short by `42`
for a message that actually carries a 34-byte `upfront_shutdown_script`, and
short by `6` when compared to the mandatory payload alone.

## Scope caveats

- **Length model only.**  No byte encoder/decoder is defined; `payloadLength`
  excludes BOLT 1's two-byte message type (`wireLength` adds it), matching
  `Protocol.Messages.msgLength`.  H14/H18 own encode/decode and truncation.
- **`fundingSatoshis : BtcAmount` (`= Int`)** matches
  `Protocol.Handshake.OpenChannel`/`FundingNegotiation`; wire range and
  non-negativity are the explicit `WellFormedOnWire` conjuncts, not a change of
  representation.  `pushMsat : Msat` keeps the unit distinction.
- **`channelFlags : Nat`** (with `FitsU8`), so BOLT 2's "undefined bits MUST be
  0" rule can be stated later; only the one-byte width is used here.  H15's
  local copy also uses `Nat`; H17's uses `UInt8` — the parent should pick one
  when unifying.
- **TLVs** are the two defined `open_channel_tlvs` entries (types 0 and 1) as
  `Option ByteArray`; unknown TLV types and TLV ordering/duplicate rules are out
  of scope.  `tlvsLength` includes the BigSize type and length bytes.
- **No authentication.**  `open_channel` carries no sender identity or
  signature; transport attribution remains the explicit hypothesis of
  `FundingAuthTargets` (`docs/ASSUMPTIONS.md` §3).  This module claims nothing
  about key ownership.
- The record is **local** because `Protocol/Messages.lean` is shared.  Adding
  `openChannel` to `Msg`/`MsgKind` is an integrator action (patch below).

## Exact shared-file integration patch (`LnLean/Protocol/Messages.lean`)

```lean
-- 1. Imports (top of file, after `import LnLean.Channel.Types`).
import LnLean.Wire.BigSize
-- (`Wire.BigSize` imports only `Basic.Core`, so there is no cycle.)

-- 2. New structures, immediately before `structure AcceptChannel`.
/-- Optional `open_channel_tlvs` (BOLT 2 type 32, TLVs 0 and 1). -/

  upfrontShutdownScript : Option ByteArray := none
  channelType : Option ByteArray := none
deriving Repr, BEq

/-- BOLT 2 `open_channel` (type 32).  The fixed payload is 319 bytes; optional
TLVs are additional. -/
structure OpenChannelMsg where
  chainHash : ChainHash
  temporaryChannelId : ChannelId
  fundingSatoshis : LnLean.Bitcoin.BtcAmount
  pushMsat : Msat
  dustLimitSatoshis : Nat
  maxHtlcValueInFlightMsat : Nat
  channelReserveSatoshis : Nat
  htlcMinimumMsat : Nat
  feeratePerKw : Nat
  toSelfDelay : Nat
  maxAcceptedHtlcs : Nat
  fundingPubKey : PubKey
  revocationBasepoint : PubKey
  paymentBasepoint : PubKey
  delayedPaymentBasepoint : PubKey
  htlcBasepoint : PubKey
  firstPerCommitmentPoint : PubKey
  channelFlags : Nat
  tlvs : OpenChannelTlvs := {}
deriving Repr, BEq

-- 3. `inductive Msg`: add immediately after `| init (m : InitMsg)`
  | openChannel (m : OpenChannelMsg)

-- 4. `inductive MsgKind`: add immediately after `| init`
  | openChannel

-- 5. `Msg.kind`: add immediately after `| .init _ => .init`
  | .openChannel _ => .openChannel

-- 6. `wireType`: add immediately after `| .init => 16`
  | .openChannel => 32

-- 7. `kindOfType?`: add immediately after `| 16 => some .init`
  | 32 => some .openChannel

-- 8. TLV length helpers (module level, next to `sigLen`/`sigListLen`), and the
--    `msgLength` case, immediately after `| .init m => ...`:
def tlvEntryLength (typ : Nat) (value : ByteArray) : Nat :=
  (LnLean.Wire.encode typ).size + (LnLean.Wire.encode value.size).size + value.size

namespace OpenChannelTlvs
def tlvsLength (t : OpenChannelTlvs) : Nat :=
  (match t.upfrontShutdownScript with
    | none => 0
    | some v => tlvEntryLength 0 v) +
  (match t.channelType with
    | none => 0
    | some v => tlvEntryLength 1 v)
end OpenChannelTlvs

  | .openChannel m => 319 + m.tlvs.tlvsLength

-- 9. `channelId?`: add immediately after `| .init _ => none`
  | .openChannel m => some m.temporaryChannelId

-- 10. `pubKeys`: add immediately before the `| .acceptChannel m =>` case
  | .openChannel m =>
      [m.fundingPubKey, m.revocationBasepoint, m.paymentBasepoint,
       m.delayedPaymentBasepoint, m.htlcBasepoint, m.firstPerCommitmentPoint]
```
