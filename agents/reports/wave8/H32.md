`txCheckerFor_some_base_ecdsa_eq` is an **ECDSA-entry** equality only. The two
checkers' Schnorr fields genuinely differ (`txCheckerFor` installs
`Schnorr.Verify.verifyImpl` with the fail-closed BIP 342 `none` dispatch;
`ecdsaEntry` installs `fun _ _ _ _ => false`), and a whole-checker equality is
not needed or claimed here: witness-v0 P2WSH ECDSA execution never reaches the
Schnorr slot. (Wave-8 lane `H31` proves a whole-checker equality by a different
route; H32 deliberately does not depend on another lane's module.)

## Scope caveats

- **Amount premise.**  Positive/negative acceptance results use
  `txCheckerFor tx nIn (some amount)`; `amount : Amount` is the spent output
  value committed by BIP 143.  The module does not prove the value equals the
  referenced outpoint or that the outpoint exists.
- **Missing data.**  `none` is the `-1`-amount sentinel / `HandleMissingData`
  state.  `txCheckerFor_none_ecdsa_false` and
  `txCheckerFor_none_revocation_fail` prove the revocation branch is
  *impossible*, not that another branch is selected.
- **Script-hash premises.**  `hps : program.size = 32` and
  `hprog : toLocalProgram … = program` (i.e. `hashSha256` of the
  `toLocalOps` script) are explicit.  No claim is made that these bytes are the
  BOLT 3 script of a particular channel.
- **Flags.**  The consensus word is `{ csv := true }` and the policy word is
  empty (`minimalData = false`).  This module does not cover the
  `minimalData`/policy scaffold (`H05`) or block-flag `dersig` transfer.
- **Signature premises.**  `hr`/`hd` are 33-byte compressed-key lengths,
  `hsigsz : sig.size ≤ 520`, `hne : 0 < sig.size`, and
  `hpk : isValidPubKey … = true` are explicit seam gates.  ECDSA remains the
  concrete **lax** vendored verifier `Bitcoin.Crypto.Ecdsa.Verify.verifyImpl`;
  no EUF-CMA/consensus-cryptography claim (C3/`CR-01`) is made.
- **Key separation.**  `EcdsaKeySeparated` is an explicit hypothesis for the
  two Lightning wrong-key theorems.  Without it, a signature accepted under
  both keys is not excluded by this model.
- **Sequence domain.**  `txCheckerFor_checkSequenceDef_iff` and the delayed
  theorems require `csv < 32768`, the fixed-width non-sign-bit domain.  The
  `csv ≥ 32768`/disable-bit edge is `H06`'s lane and is not claimed.
- **Pipeline composition.**  No `scriptLane`/`txVerdictFull` result is proved
  here (that is `H04`); the result is at the `txCheckerFor` and
  `verifyWitnessProgram` boundary.
- **Environment indexing.**  The delayed theorems state the sequence context
  with `(tx.vin.getD nIn fullDummyTxIn).sequence`, matching the full checker
  without an in-range hypothesis.  `txCheckerFor_some_env_eq_locktimeEnvOf`
  (the equality to the model `locktimeEnvOf`) does require
  `nIn < tx.vin.length`; the two `getD` totalizations genuinely differ out of
  range (`0xFFFFFFFF` versus `0`).
- **No whole-checker equality.**  Only the ECDSA entry and the environment are
  identified; the Schnorr fields differ by design and are never reached by a
  witness-v0 P2WSH ECDSA spend.
