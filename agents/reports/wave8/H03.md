```lean
theorem txCheckerFor_some_checkECDSA_eq_realCheckerOf
    (tx : Bitcoin.Data.Tx) (nIn : Nat) (amount : Amount)
    (sig pk code : ByteArray) (sv : SigVersion)
    (ed : Bitcoin.Crypto.Seam.ScriptExecutionData) :
    (txCheckerFor tx nIn (some amount)).base.checkECDSASignature sig pk code sv ed =
      (Bitcoin.Capstone.RealChecker.realCheckerOf tx nIn amount).base.checkECDSASignature
        sig pk code sv ed

theorem txCheckerFor_some_env_eq_realCheckerOf
    (tx : Bitcoin.Data.Tx) (nIn : Nat) (amount : Amount) :
    (txCheckerFor tx nIn (some amount)).env =
      (Bitcoin.Capstone.RealChecker.realCheckerOf tx nIn amount).env

theorem txCheckerFor_some_checkECDSA_eq_checkerOf
    (tx : Bitcoin.Data.Tx) (nIn : Nat) (amount : Amount)
    (hIn : nIn < tx.vin.length)
    (sig pk code : ByteArray) (sv : SigVersion)
    (ed : Bitcoin.Crypto.Seam.ScriptExecutionData) :
    (txCheckerFor tx nIn (some amount)).base.checkECDSASignature sig pk code sv ed =
      (checkerOf Bitcoin.Crypto.Ecdsa.Verify.verifyImpl tx nIn amount).base.checkECDSASignature
        sig pk code sv ed

theorem txCheckerFor_env_eq_locktimeEnvOf (tx : Bitcoin.Data.Tx) (nIn : Nat)
    (amount : Amount) (hIn : nIn < tx.vin.length) :
    (txCheckerFor tx nIn (some amount)).env = locktimeEnvOf tx nIn
```

The first two are `rfl`.  A *full* checker equality with `realCheckerOf`
does **not** hold: `txCheckerFor` carries the real BIP 340 verifier in its
Schnorr slot while `realCheckerOf` carries the fail-closed stub.  The module
therefore proves the exact pointwise ECDSA equality (and environment equality)
that the revocation branch consumes, rather than an unsound whole-structure
equality.

## Scope caveats

1. **`some amount` only.**  `txCheckerFor … none` is the fail-closed
   missing-data state and is lane H01's transfer, not claimed here.
2. **`nIn < tx.vin.length` is used exactly where it is needed**: to identify
   the checker's `nSequence`/`locktimeEnvOf` with the signing input and to
   relate the checker ECDSA entry to `checkerOf` (hence the model digest).
   The pure vendored-acceptance transfer
   `verifyWitnessProgram_toLocal_revocation_txCheckerFor` needs no `hIn`,
   because it only instantiates the wave-6 theorem at a concrete checker.
3. **No whole-checker equality.**  `txCheckerFor` and
   `RealChecker.realCheckerOf` differ in the Schnorr entry; the module proves
   the pointwise ECDSA and environment equalities instead.  This is deliberate
   and prevents a false unconditional equality.
4. **The signature hypotheses are vendored EC verdicts** (assumption C3), not
   cryptographic proofs.  `RevocationKeySeparated` remains an explicit
   hypothesis; no computational reduction is claimed (`CR-01`).
5. **`csv < 32768`** is required to discharge the fixed-width decode,
   non-negativity and BIP 68 disable-bit premises.  The `csv ≥ 32768` and
   `minimalData` policy edges are lanes H06/H05.
6. **Fixed flag/policy words.**  The witness-program calls use
   `({ csv := true } : ScriptFlags)` and `({} : PolicyFlags)` exactly as the
   wave-6/7 bridges; this module makes no claim about other policy words.
7. **One-directional results.**  Positive acceptance and the three concrete
   rejection outcomes are proved; there is no converse
   `verifyWitnessProgram = .ok → P2WSHSpend`, and no enumeration of every
   possible `ExecError`.
8. **Checker boundary, not pipeline.**  This module does not evaluate
   `scriptLane`/`scriptLaneTx`/`txVerdictFull`; the pipeline-level transfer for
   a one-input revocation/delayed transaction is lane H04.  H03 therefore
   supplies the exact `txCheckerFor` facts H04 consumes, not a claim that the
   full verdict accepts.
9. **`vendorLaws` ignores its `msg` parameter**; the digest is passed as `msg`
   for the model correspondence, while the vendored checker constructs its own
   BIP 143 digest.  This is the same convention as `SequenceContextTargets`.
