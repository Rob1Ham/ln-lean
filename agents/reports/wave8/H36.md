### 2. Declared gap 1 — unknown-type / namespace policy

```lean
theorem unknown_even_type_gap :
    decodeTLV unknownEven12 = some (TLVStream.mk [⟨18, bytes []⟩]) ∧
      decodeAdmissible unknownEven12 = true
```

`unknownEven12 = bytes [0x12, 0x00]` is BOLT 1 Appendix B's unknown **even** type 18, which a namespace-aware decoder must reject. The model parses *and* admits it; the decoded stream is even `WellFormed` (`unknownEven12_wellFormed`), so this is a missing policy, not a broken predicate.

Structural form (not a single-vector accident):

```lean

theorem any_singleton_roundtrip (ty : Nat) (v : ByteArray)
```

Unknown odd types are also accepted without any "ignore" processing (`unknownOdd19`, `unknownOdd19Value`). The two gaps compose in `unknownEven12NonMinimalValue` (`12 02 0001`), which is admitted.

### 3. Declared gap 2 — `tu64` value minimality

Local reference predicate (BOLT 1 known-type value convention, **not** part of the wire model):

```lean
def MinimalTu64Value (v : ByteArray) : Prop := ∃ n : Nat, Wire.encode n = v

theorem not_minimalTu64_of_size_two (v : ByteArray) (hv : v.size = 2) :
    ¬ MinimalTu64Value v

theorem nonminimalTu64_zero_one :
    ¬ MinimalTu64Value (bytes [0x00, 0x01])

theorem value_minimality_gap :
    ¬ MinimalTu64Value (bytes [0x00, 0x01]) ∧
      decodeAdmissible valueNonMinimalZeroOne = true
```

with `valueNonMinimalZeroOne = bytes [0x01, 0x02, 0x00, 0x01]` (the BOLT 1 Appendix B `n1` case) decoding to `⟨1, bytes [0x00, 0x01]⟩` (`valueNonMinimalZeroOne_decode`). Minimal values `00`, `01`, `fc`, `fd 00 fd`, `fe 00 01 00 00` are shown to be genuine `tu64` encodings (`minimalTu64_zero/one/252/253/65536`).

Value opacity is structural:

```lean
theorem admission_value_opaque {b c : ByteArray} {s t : TLVStream}
    (hb : decodeTLV b = some s) (hc : decodeTLV c = some t)
    (h : s.types = t.types) :
    decodeAdmissible b = decodeAdmissible c
```

Two decoded streams with the same type list get the same admission decision regardless of value bytes.

### 6. Truncation — parser is all-or-nothing

Every vector below has `decodeTLV = none` and `decodeAdmissible = false`:

| vector | failure |
|---|---|
| `01 01 2a 02` | dangling type after a valid record |
| `01 01 2a 02 fd` | dangling type + partial length |
| `01 02 2a` | one value byte short |
| `01 01` | missing value |
| `fe 00` | partial four-byte type |
| `ff 000000` | partial eight-byte type |
| `01 fe 0000` | partial four-byte length |
| `02` | type with no length |

Control: `completeControl = 02 02 2a2b` decodes to `⟨2, bytes [0x2a, 0x2b]⟩` and is admitted, so the negatives are not "all short inputs fail".

## Declared model gaps (retained, now mechanized)

1. **No namespace / known-type policy.** Unknown even type `12 00` is parsed and admitted; `any_type_value_admitted` shows this for every in-domain type/value, so no even/odd or known-type table exists. Not a BOLT conformance claim.
2. **No `tu64` / known-type value decoding.** A value is opaque bytes; the non-minimal `0001` value is admitted. `MinimalTu64Value` is a local reference predicate supplied here to state the gap; the wire model never consults it.

The older parser/admission gap is also retained and re-exercised: `decodeTLV` does not enforce ordering or duplicate suppression; `decodeAdmissible` is the enforcement point.

## Scope caveats

- These are **finite local vectors plus structural theorems about the existing `LnLean.Wire.TLV` model**, not a new production decoder or a namespace-aware BOLT implementation.
- `MinimalTu64Value` is a local reference predicate, not a field of `TLVStream`/`TLVRecord`; the model's actual behaviour is "accept the opaque bytes". No value decoding is added.
- The unknown-even acceptance is a **missing policy**, not a contradiction: the decoded singleton is legitimately `WellFormed` under `Sorted ∧ Unique`.
- `decodeTLV` remains structural: ordering/duplicate checks live in `decodeAdmissible`, so any production path must call the admission layer. No theorem `decodeTLV b = some s → s.WellFormed` exists.
- The vectors are not wired into `tests/conformance/vectors.json` or `scripts/check-conformance.py` (shared files, parent-owned). They are Lean-side conformance evidence only.
- No BOLT conformance claim is made for `unknownEven12`, `unknownEven12NonMinimalValue`, or `valueNonMinimalZeroOne`; the corresponding theorems record the model's actual (non-conforming) decision.
