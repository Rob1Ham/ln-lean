### Sequence semantics and isolated premises

```lean
def runRaw : GossipState → List GossipMessage → GossipState

    CanonicalStore → List GossipMessage → CanonicalStore

    List GossipMessage → Prop

def UpdatesDescending (l : List ChannelUpdate) : Prop :=
  l.Pairwise (fun a b => b.timestamp < a.timestamp)
```

explicit:

```lean

  store : CanonicalStore

    EpochStore → List EpochEvent → EpochStore

def EpochMonotone (events : List EpochEvent) : Prop := EpochChainFrom 0 events

  EpochMonotone events ∧
```

### Sharp obstruction: the clock premise is necessary

```lean
theorem raw_clock_obstruction :
    ∃ (verify : SigVerifier) (cs : CanonicalStore) (m : GossipMessage),
      CanonicalStoreShape cs.gossip ∧
        CanonicalMessageAdmitted verify cs m ∧
          ¬ RawClockAdmits cs.gossip m ∧
            canonicalStoreView (applyGossip cs.gossip m) ≠
              (applyGossipCanonicalStore verify cs m).gossip

theorem clock_premise_necessary :
    ¬ ∀ (verify : SigVerifier) (cs : CanonicalStore) (msgs : List GossipMessage),
        CanonicalStoreShape cs.gossip →
          CanonicalGatesHold verify cs msgs →
            canonicalStoreView (runRaw cs.gossip msgs) =
              (runCanonical verify cs msgs).gossip

theorem epochClock_premise_necessary :
    ∃ (verify : SigVerifier) (es : EpochStore) (events : List EpochEvent),
      CanonicalStoreShape es.store.gossip ∧
        CanonicalGatesHold verify es.store (events.map EpochEvent.message) ∧
          ¬ EpochStrictlyAdvances es.clock (events.map EpochEvent.message) ∧
            canonicalStoreView
                (runRaw es.store.gossip (events.map EpochEvent.message)) ≠
              (runEpoch verify es events).store.gossip
```

### Concrete non-vacuous witness

The witness is a channel announcement, a timestamp-1 update, and a strictly
newer timestamp-2 update in the same directional slot:

```lean
theorem realisticEpochSequence_witness :
    ∃ (verify : SigVerifier) (k : NodeId → PubKey) (events : List EpochEvent),
      RealisticEpochSequence verify k events ∧ events ≠ [] ∧
        (runEpoch verify (EpochInitial k) events).store.gossip.updates = [u1] ∧
          u0 ∉ (runEpoch verify (EpochInitial k) events).store.gossip.updates
```

The supporting private computation shows the raw store retains both records, so
this is a genuine replacement, not a vacuous equality:

```lean
private theorem runRaw_epochEvents_updates :
    (runRaw (EpochInitial (fun _ => key2)).store.gossip
      (epochEvents.map EpochEvent.message)).updates = [u1, u0]
```

Thus the raw list is `[u1, u0]`, the canonical epoch list is `[u1]`, and the
projection square still holds because `canonicalStoreView` selects the newest
record per `(shortChannelId, direction)` slot on the descending list.

## Scope caveats

- The exact square is **conditional**: the raw/canonical starting store must
  satisfy `CanonicalStoreShape` and `UpdatesDescending`, and the sequence must
  satisfy canonical admission gates plus the raw/epoch clock premise. The
  obstruction theorems prove the clock premise cannot be dropped even when
  every canonical gate holds.
- `UpdatesDescending` is a real initial-state premise, not a consequence of
  `CanonicalStoreShape` alone. It is maintained by raw steps under
  `RawClockHolds`, and the empty/`EpochInitial` store satisfies it.
- `EpochStrictlyAdvances` requires every successive **update timestamp** to
  strictly increase globally, not merely within one directional slot.
  Announcements and node announcements leave the epoch clock unchanged. This
  is the exact ordering premise used; it is stronger than BOLT 7 per-slot
  replacement, and H40 does not claim the per-slot-independent case.
- `EpochMonotone` only requires non-decreasing epoch numbers. Epoch numbers are
  schedule labels; the refinement clock is timestamp-based.
- The conclusion is equality of the **canonical observation**, not of the raw
  append-only list. The witness deliberately has raw `[u1, u0]` versus canonical
  `[u1]`. Raw insertion remains non-canonical and the two preserved
  counterexamples document that boundary.
- Signatures are abstracted through `SigVerifier`. The concrete witness uses an
  accept-all verifier to isolate store/transition semantics; it makes no
  cryptographic verification claim.
- No network delivery, fairness, eventual-inclusion, or liveness claim is made.
  Those remain separate issues (for example the H43 schedule lane).
