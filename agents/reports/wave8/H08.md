|---|---|---|

The hash-lock branch is explicit in the layouts:

* offered: `OP_HASH160 <HASH160(payment_hash)> OP_EQUALVERIFY OP_CHECKSIG`
  at bytes `104..132` (the 20-byte hash is at `109..128`);
* received: `OP_IF OP_HASH160 <HASH160(payment_hash)> OP_EQUALVERIFY 2 OP_SWAP`
  followed by the local-key/multisig branch, with the 20-byte hash at `69..88`.

Note the constant distinction: the witness script commits to
`HASH160(payment_hash)` (20 bytes).  The full 32-byte `paymentHash` is carried
explicitly in `HtlcScriptView` and related to the script field by
`HashesMatch`; the script itself does not contain the 32-byte value.
Likewise the revocation branch commits to `HASH160(revocationpubkey)`, while
`revocationPubKey` is explicit in the view.

## Scope caveats

* **Payment hash vs. its hash.**  The witness script contains the 20-byte
  `HASH160(payment_hash)`, not the 32-byte `paymentHash`.  Both are explicit in
  `HtlcScriptView`; `HashesMatch` is the stated C2 hypothesis connecting them.
  The lane does not prove RIPEMD160/SHA256 correctness.
* **Revocation key.**  The script contains `HASH160(revocationpubkey)`; the
  full revocation public key is explicit in the view and connected by
  `HashesMatch`.  The lane does not derive revocation keys from the
  commitment secret.
* **HTLC public keys.**  Both 33-byte HTLC public keys are explicit in the
  script and in the view.  The model does not decide which party owns which
  key; `offered`/`received` are relative to the commitment owner, matching
  BOLT 3 output naming.
* **CLTV.**  The offered script does **not** contain the expiry; the
  HTLC-timeout transaction carries it in `nLockTime`.  The received script
  contains the minimal `CScriptNum` push, proved only on `0 ≤ c < 2^31`.
  BOLT 3 Appendix A budgets a 4-byte operand (`140` received bytes); 500000
  is a 3-byte operand (`139` bytes).  Both cases are proved.
* **Anchors.**  The `option_anchors` variants are defined and their sizes are
  proved (`+3`: 136 offered, 142/143 received).  The general byte-layout and
  fixed-offset slice theorems are stated for the non-anchor scripts; the
  anchor definitions are the same template with the
  `OP_1 OP_CSV OP_DROP` suffix and are not separately sliced.
* **P2WSH / C1.**  `sha256` is a parameter to `htlcScriptPubKey`; the
  `34`-byte P2WSH size theorem assumes the supplied hash is 32 bytes.  C1 is
  an assumption, not an axiom.
* **Digest.**  The vendor digest equality is the in-range case for the exact
  one-input `HtlcWire`.  Wire parsing/serialization and out-of-range behavior
  belong to H09/H11.
* **`OP_CODESEPARATOR`.**  BOLT 3 HTLC scripts contain none, so `scriptCode`
  is the full witness script; no annex/accumulator cases are modelled.
* **Vectors.**  Vector keys and hashes are repeated-byte placeholders; they
  validate byte layout and sizes, not cryptographic key/hash values.
