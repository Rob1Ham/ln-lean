## What was wrong with the interface, and what this module does

The base module (`LnLean/Proofs/Security/SecurityGameTargets.lean`) states
`AdvantageReduction.tight` as a *field*:

```lean
tight : ∀ n, protocol.value n ≤ primitive.value n + loss n
```

so `AdvantageReduction.bound` is arithmetic on an assumed inequality, and the
record is satisfiable for **every** protocol advantage by `loss := protocol.value`.
This module mechanises both facts and adds the strongest true results around
them:

1. **A bound with no tightness hypothesis at all.**  The event-level indicator
   advantage `winAdvantage g` (`1` on a bad horizon, `0` otherwise) is a genuine
   `Advantage` (and an `ExactAdvantage`).  A bare `EventReduction` proves
   `winAdvantage P ≤ winAdvantage C` with **zero loss**, from `map_run` and
   `win_transport` only.
2. **A general event-level route to an accounting inequality.**  An
   `EventCover` (protocol win ⊆ primitive win ∪ loss event) yields
   `winAdvantage P ≤ winAdvantage C + indicator lossEvent` by cases on the two
   win events — again no `tight` field.  Every `EventReduction` is a cover with
   the empty loss event.
3. **`Negligible` arithmetic, now proved.**  Closure under addition
   (`negligible_add`), domination (`negligible_of_le`), eventually-zero
   (`negligible_of_eventually_zero`), and the sharp negative result
   `not_negligible_one`.  The closure proof doubles the denominator (`c + c`)
   so that the two `1/(c+c)` bounds sum to `1/c`; it is the arithmetic that
   composes a game-hopping loss with a primitive advantage.
4. **The exact remaining obligation, as a record, plus the theorem that would
   follow.**  `ReductionObligation` = accounting inequality + negligible
   primitive advantage + negligible loss; `ReductionObligation.protocol_negligible`
   derives `Negligible protocol.value`.  This is arithmetic, not a reduction.
5. **Sharp counterexamples (non-derivability).**

   * `accounting_not_implied_by_event`: identity event reduction on `unitGame`,
     zero loss, two valid advantages (`1` and `0`); the bound fails.  So `tight`
     cannot be replaced by the event simulation.
   * `exactAdvantage_not_determined`: on one non-secure game there are two
     `ExactAdvantage` values (`1` and `0`).  `ExactAdvantage` is the strongest
     event↔advantage link the model can state; even it does not determine an
     advantage.
   * `tautological_loss_not_negligible`: the `loss := protocol.value` reduction
     is always tight, but its loss is the constant `1` on a constant-one
     advantage, and `not_negligible_one` proves that is not negligible.  This is
     why `ReductionObligation.loss_negligible` is load-bearing.

## Scope caveats (keep these in any catalog or release wording)

- **No computational reduction.**  There is no probability space, no
  adversary transformation, no oracle simulation, no efficiency preservation,
  and no protocol game (corruption/schedule/L1/win condition).  Nothing here
  bounds the success probability of any adversary.
- **`AdvantageReduction.tight` is still an assumed field** in the shared module,
  which this lane did not edit.  §2/§3 derive *event-level* accounting
  inequalities without it, but only for the indicator advantage
  `indicator (g.Wins n)`, not for an arbitrary `Advantage`.
- **`Advantage` is still not linked to `Game.Wins` by the shared interface.**
  `winAdvantage` is one particular functional; `exactAdvantage_not_determined`
  shows that even `ExactAdvantage` does not determine a sequence, so event
  security alone cannot yield an accounting inequality.
- **`ReductionObligation` is a specification, not evidence.**  Its three
  mathematical fields are hypotheses; the record is inhabited
  (`zeroObligation`) and its conclusion theorem is therefore non-vacuous, but no
  concrete protocol instantiates the accounting field.
- **`Negligible` is the base module's definition** (`1/c` with `Nat` `c`); the
  closure proved here is closure for that definition only.  No asymptotic
  family, no ensembles, no `λ`-indexed advantage functions.
- **Numbers are `Rat` and literal.**  The concrete constants (`2`, `1/2`) are
  used only to show `not_negligible_one`; they are not cryptographic constants.
- The `alwaysBadGame` counterexample is a degenerate game; it shows a logical
  separation, not an attack on a protocol.

## Exact remaining reduction obligation (for `SEC-01`/`CR-01`)

For a fixed protocol game `G_PROTOCOL`, primitive game `G_C`, advantage
semantics `Adv`, and adversary transformation `R`, the open work is exactly:

1. define `G_PROTOCOL` (corruption model, network schedule, L1 model, winning
   condition) and `G_C` as probability games with an explicit adversary;
2. define `Adv` from `Game.Wins` under that probability semantics (the model has
   none today);
3. prove `R`'s **accounting inequality** `Adv_P(A, n) ≤ Adv_C(R A, n) + loss(A, n)`
   for every `n` and every `A` (this is `ReductionObligation.accounting`);
4. prove `Negligible (Adv_C(R A, ·))` and `Negligible (loss(A, ·))`
   (`primitive_negligible`, `loss_negligible`);
5. prove efficiency preservation and oracle-simulation correctness (not
   expressible in the current interface).

Given 3 and 4, step 5 is the only missing ingredient for
`Negligible (Adv_P(A, ·))`; item 5 itself is arithmetic now
(`ReductionObligation.protocol_negligible`), so the residual mathematical
content is exactly items 1–2 and 5.
