## Which boundaries are new

Existing inventory (not duplicated): `ConformanceTargets` +
`ConformanceDiffTargets` already pin BigSize
`0, 1, 252, 253, 254, 255, 256, 65535, 65536, 4294967295, 4294967296, 2^64-1`,
TLV types `1, 2, 31, 254, 255, 65535, 65536, 2^64-1`, TLV empty/sorted/duplicate
streams, framing types `0, 16, 255, 256, 65535`, and the `65533/65534` payload
boundary. H38 adds exactly these new points:

| Area | New boundary | Why new |
|---|---|---|
| BigSize | `32768 = 0x8000` (`fd 80 00`) | first two-byte payload with the high bit set |
| BigSize | `16777215 = 0xffffff` / `16777216 = 0x01000000` | three-byte value inside a four-byte field / first use of the fourth byte |
| BigSize | `2^63` (`ff 80 … 00`) | first eight-byte payload with the high bit set |
| BigSize | `2^64-2` (`ff ff … fe`) | largest non-maximal `uint64` |
| BigSize | streaming `fd`/`fe`/`ff` with one trailing byte | existing suite pins only the one-byte trailing case |
| BigSize | non-minimal four-byte `65021 = 0xfdfd` | interior of the four-byte rejection region; existing pins `0` and `65535` |
| TLV | type `0`, `252`, `253` | smallest type and the `fc`/`fd 00 fd` type-field class transition |
| TLV | adjacent types `65535`, `65536` in one stream | three-byte/five-byte type-field transition |
| TLV | encoder vectors (`TLVStream.encode`, `TLVRecord.encode`) | existing modules only encode the empty stream |
| TLV | value length `252` (`fc`) versus `253` (`fd 00 fd`) | value-length BigSize class transition |
| Framing | types `1`, `128`, `32768`, `65534` | existing framing vectors use `0, 16, 255, 256, 65535` |
| Framing | minimal transport frame `00 10 00 02` and its decode | concrete minimal BOLT 8 frame |
| Framing | payload-only decoder rejects that same minimal frame | concrete instance of the generic length-convention boundary (existing suite has only the four-payload case) |
| Framing | payload-only frame `00 10 00 00` and its decode | concrete payload-only counterpart |
| Framing | `u16BE 255`, `u16BE 256` | two-byte header class transition; existing pins `65535`/`65536` |
| Framing | one-byte and two-byte truncated headers | existing suite pins only the three-byte short header |

No vector duplicates an existing input/expected pair.

## Scope caveats

- **Finite-vector conformance only.** These are concrete encoder/decoder
  decisions; they do not prove the TLV parser round trip, known-type length
  policy, even/odd unknown-type policy, message-body semantics, or
  implementation equivalence.
- **No shared fixture edit.** `tests/conformance/vectors.json`,
  `scripts/check-conformance.py`, and the two shared conformance modules are
  untouched. Until the parent adds the module to the checker's Lean path and
  adds matching JSON entries, `check-conformance.py` will not cross-check these
  theorem names (they still build and are auditable).
- **Local proof scaffolding, not model changes.** The module adds a `local
  instance : DecidableEq WireMessage` because `WireMessage` only derives
  `Repr`; this is required for the two positive decode vectors and is not
  exported. It also sets `maxRecDepth 100000` (file-local option) because the
  structural TLV parser over 252/253-byte values exceeds the default reduction
  budget. Neither changes any statement or shared definition.
- **Two declared TLV model gaps are retained unchanged**: unknown even type
  acceptance and opaque (non-minimal) TLV values.
- The framing vectors use the promoted `Wire.Transport` model; they do not add
  Noise encryption, MACs, or dispatch.
