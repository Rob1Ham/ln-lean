## Payload arithmetic — correction to the wave-7 sketch

The wave-7 `Messages.lean` patch sketch proposed `msgLength = 313` and said a
full record including `chain_hash` is 345 bytes.  Both figures under-count.

Mandatory BOLT 2 v1 `open_channel` data:

| Field group | Bytes |
|---|---:|
| `chain_hash` | 32 |
| `temporary_channel_id` | 32 |
| six `u64` fields (`funding_satoshis`, `push_msat`, `dust_limit_satoshis`, `max_htlc_value_in_flight_msat`, `channel_reserve_satoshis`, `htlc_minimum_msat`) | 48 |
| `feerate_per_kw` (`u32`) | 4 |
| `to_self_delay`, `max_accepted_htlcs` (`u16` each) | 4 |
| six `point` fields | 198 |
| `channel_flags` (`u8`) | 1 |
| **Mandatory total** | **319** |

The wave-7 record omitted `chain_hash` and `channel_reserve_satoshis` (40 bytes)
and summed the 34-byte shutdown script without its 2-byte TLV header.  Thus:

- mandatory: **319**;
- the wave-7 field list without those two fields and without TLVs: **279**;
- that field list plus a 34-byte shutdown script with TLV header: **315**,
  not 313;
- the full BOLT 2 record plus a standard 34-byte shutdown TLV: **355**
  (mechanized as `msgLength_shutdown_34`);
- the wave-7 “345” figure omits `channel_reserve_satoshis` (8) and the TLV
  header (2): `345 + 8 + 2 = 355`.

The integration patch below therefore uses `319` plus the exact BigSize-based
TLV overhead, not `313`.

## Scope caveats

- **Local record only.**  `Messages.lean`, `Handshake.lean`, `Laws.lean`,
  `Peer.lean`, root imports, catalog, traceability, and audit are untouched.
- **The local `Kind` table is a copy, not `Messages.MsgKind`.**  It is used to
  prove type uniqueness independently of the shared module, but
  `wireType_eq_messages`/`wireType_shared` mechanize that every one of the
  seventeen shared kinds has exactly the existing `Messages.wireType` value.
  The integration patch below maps the same numbers into `Messages`.
- **`OpenChannelMsg` is not yet `Msg`.**  No `Peer.sendEvent?`/
  `receiveEvent?`/handshake routing is claimed; adding type 32 requires the
  patch and a separate handshake-event decision.
- **Length, not bytes.**  `msgLength` is an arithmetic model.  It does not
  encode little-endian integers, the BigSize byte values, or the TLV stream.
  Optional non-shutdown TLVs (`channel_type`, etc.) are not modelled or
  counted.
- **`wellFormed` is local.**  It checks the framing bound, chain-hash width,
  channel-id/key widths, and `u32`/`u16` domains.  It does not check
  `MoneyRange` on `funding_satoshis`, channel-flag semantics, key validity on
  the curve, or any signature (there is none).
- **No attribution/consensus claim.**  This is wire registration only; it does
  not connect `open_channel.funding_pubkey` to a peer (`PR-01`) or execute any
  script (`L1-01`/`L1-02`).
