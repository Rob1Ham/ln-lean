### The local equality lemma (no checker-shaped hypothesis)

```lean
theorem realChecker_sighashDispatch_witnessV0 (tx : Tx) (nIn : Nat)
    (amount : Amount) (scriptCode : ByteArray) (ht : UInt8) :

theorem txCheckerFor_checkECDSASignature_eq_checkerOf
    (tx : Tx) (nIn : Nat) (amount : Amount)
    (sig pk scriptCode : ByteArray) (ed : Bitcoin.Crypto.Seam.ScriptExecutionData) :
    (Bitcoin.TxValidation.Full.txCheckerFor tx nIn (some amount)).base.checkECDSASignature
        sig pk scriptCode .witnessV0 ed =
      (LnLean.Proofs.Bitcoin.SighashBridgeTargets.checkerOf
          Bitcoin.Crypto.Ecdsa.Verify.verifyImpl tx nIn amount).base.checkECDSASignature
        sig pk scriptCode .witnessV0 ed
```

The lemma is unconditional: both sides are `ecdsaVerdict verifyImpl _ true`, so
the `isValidPubKey`/empty-signature gates coincide, and the only difference is
the sighash closure, identified by `sighashWitnessV0_eq_interface` (L1-08).
`txCheckerFor` is therefore *proved* equal to the wave-6 concrete wiring at
witness-v0; no assumption about its definition is introduced.

with

```lean
def fundingDigest (tx : Tx) (nIn : Nat) (a b : PubKey) (sig : ByteArray)
    (amount : Amount) : ByteArray :=
  LnLean.Bitcoin.Sighash.sighashWitnessV0 tx nIn (fundingScriptCode a b)
    (hashtypeOf sig) amount

def FundingSigOK (tx : Tx) (nIn : Nat) (a b pk : PubKey) (sig : ByteArray)
    (amount : Amount) : Prop :=
  Bitcoin.Crypto.Ecdsa.Verify.verifyImpl (sig.extract 0 (sig.size - 1)) pk.bytes
    (fundingDigest tx nIn a b sig amount) = true
```

The two signature premises are *exactly* the concrete `verifyImpl` calls, and
they are discharged into the vendored checker by
`txCheckerFor_consumes_model_digest`; the result then follows from
`InterpreterBridgeTargets.verifyWitnessProgram_funding` and
`InterpreterBridgeTargets.funding_model_spend`. The committed script hash
`program` is supplied explicitly (`hps`, `hprog`), not computed away.

### Wrong-key negative

```lean
theorem checkMultiSig_two_of_two_bad_sig
    (chk : Bitcoin.Interpreter.ScriptChecker) (scriptCode a b s1 s2 dummy : ByteArray)
    (h2 : chk.base.checkECDSASignature s2 b scriptCode .witnessV0
      (default : Bitcoin.Crypto.Seam.ScriptExecutionData) = false) :
    Bitcoin.Interpreter.stepBody.checkMultiSig ... 0xae
      { stack := [ByteArray.mk #[0x02], b, a, ByteArray.mk #[0x02], s2, s1, dummy], ... }
    = Except.ok { stack := [ByteArray.empty], ... }

theorem evalFrom_fundingWireOps_bad_sig ...   -- final stack = [empty]
theorem evalScriptBytes_funding_bad_sig ...   -- = Except.ok [ByteArray.empty]
theorem executeWitnessScript_funding_bad_sig ... -- = .fail .evalFalse
theorem verifyWitnessProgram_funding_bad_sig ... -- = .fail .evalFalse

theorem funding_txCheckerFor_wrongKey_rejected
    (tx : Tx) (nIn : Nat) (amount : Amount)
    (a b : PubKey) (s1 s2 dummy : ByteArray) (program : ByteArray)
    (ha : a.bytes.size = 33) (hb : b.bytes.size = 33)
    (hs1 : s1.size ≤ 520) (hs2 : s2.size ≤ 520) (hdu : dummy.size ≤ 520)
    (hpka : Bitcoin.Crypto.Seam.Der.isValidPubKey a.bytes = true)
    (hpkb : Bitcoin.Crypto.Seam.Der.isValidPubKey b.bytes = true)
    (hne1 : 0 < s1.size) (hne2 : 0 < s2.size)
    (hps : program.size = 32)
    (hprog : Bitcoin.Interpreter.hashSha256
      (Bitcoin.Script.Parser.serializeOpcodes (fundingOps a b)) = program)
    (h1 : FundingSigOK tx nIn a b a s1 amount)
    (h2bad : ¬ FundingSigOK tx nIn a b b s2 amount) :
    Bitcoin.Interpreter.verifyWitnessProgram 6
        [dummy, s1, s2, Bitcoin.Script.Parser.serializeOpcodes (fundingOps a b)] 0 program
        ({} : Bitcoin.Activation.ScriptFlags) ({} : Bitcoin.Interpreter.PolicyFlags)
        (Bitcoin.TxValidation.Full.txCheckerFor tx nIn (some amount)) false
      = .fail .evalFalse ∧
      ¬ Accepts
        (vendorLaws (Bitcoin.TxValidation.Full.txCheckerFor tx nIn (some amount))
          (Bitcoin.Script.Parser.serializeOpcodes (fundingOps a b)))
        (fundingDigest tx nIn a b s1 amount) (fundingProg a b) [s2, s1, dummy]
```

`h2bad` is the wrong-key premise: the second witness signature is rejected by
the concrete verifier under the ordered second funding key (e.g. it was made by
a different key). The vendored verifier returns `.fail .evalFalse` and the
model spend is not accepting. Mechanically this is the funding analogue of
wave-6's revocation wrong-key negative, proved against the vendored
`stepBody.checkMultiSig`/`evalFrom`/`executeWitnessScript` stack rather than
the local machine.

## Scope caveats

- **Checker boundary, not the tx pipeline.** The result is stated at
  `Bitcoin.TxValidation.Full.txCheckerFor` (the per-input `ScriptChecker`).
  The `scriptLane`/`scriptLaneTx`/`txVerdictFull` wrapper is **not** proved
  here: that needs `verifyScriptFull` (P2SH/cleanstack/`isWitnessProgram`
  computation), `tableSupplied`, `checkTransaction`, and the fee slice. Lanes
  H01/H02/H03/H04 own those transfers; this module supplies the exact checker
  equality they need.
- **Spent amount is context, not a resolved coin.** `(some amount)` is a
  parameter. `funding_digest_commits_amount` proves the digest commits to it;
  proving it equals the referenced outpoint's value needs the UTXO table.
  `none` is proved to fail closed.
- **Out-of-range index.** The digest theorem uses `tx.vin[nIn]? = some i`;
  for `nIn ≥ tx.vin.length`, `sighashWitnessV0` is BIP 143's zero digest
  (totalized), not a spend.
- **Signatures are hypotheses.** The module proves that *if* `verifyImpl`
  accepts, the spend works; it does not construct a valid signature (C3 is
  used as the executable verifier, not as an EUF-CMA reduction).
- **Flags.** Both the positive and negative verifications use the
  consensus-default flag word `{}` and policy word `{}`; BIP66 `dersig`,
  LOW-S, NULLDUMMY, and `minimalData` policy gates are outside this lane.
  (The funding witness's dummy element is consumed unconditionally by
  `OP_CHECKMULTISIG`; NULLDUMMY is not exercised.)
- **Ordered keys.** `a`/`b` are the `orderedFundingKeys` outputs; the ordered
  2-of-2 script is unchanged from `SpendTargets`/`InterpreterBridgeTargets`.
  Positive-direction P2WSH only (no negative-direction
  vendor-failure⇒model-rejection lemma for arbitrary scripts).
