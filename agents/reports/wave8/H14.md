
`channel_flags` is a `UInt8`, so its one-byte width needs no hypothesis.
`WireValid` is a *wire-domain* predicate, not a semantic check: it does not
assert that the points are valid curve points, that amounts are economically
sane, or that `chain_hash` names Bitcoin's chain.  `*_valid` corollaries expose
the identifier/point size facts via `Valid` from `Basic/Core.lean`.

### Encoding and decoding

```lean
def OpenChannelMsg.fieldWidths : List Nat :=
  [32, 32, 8, 8, 8, 8, 8, 8, 4, 2, 2, 33, 33, 33, 33, 33, 33, 1]

def OpenChannelMsg.chunks (m : OpenChannelMsg) : List ByteArray
def OpenChannelMsg.encode (m : OpenChannelMsg) : ByteArray
def OpenChannelMsg.payloadSize (m : OpenChannelMsg) : Nat
def OpenChannelMsg.messageSize (m : OpenChannelMsg) : Nat

def takeExact (n : Nat) (l : List UInt8) : Option (ByteArray × List UInt8)
def parseFields : List Nat → List UInt8 → Option (List ByteArray)
def OpenChannelMsg.decodeChunks : List ByteArray → Option OpenChannelMsg
def OpenChannelMsg.decode (b : ByteArray) : Option OpenChannelMsg
```

`encode` emits the fields in BOLT 2 order, using `beBytes` for the ten
numeric fields and the raw bytes for the two 32-byte identifiers and six
33-byte points.  `decode` runs the generic strict prefix parser over
`fieldWidths` and then requires exactly eighteen chunks; any short input,
trailing byte, or TLV tail is rejected.  All decoder witnesses are built from
the same `fieldWidths` list as the encoder, so the two cannot drift.

### Non-vacuity

`witness` is the all-zero 319-byte payload: both identifiers and all six
points are runs of the BOLT 2 widths, every integer is `0`, and
`channelFlags = 0`.  `witness_wireValid` discharges `WireValid`, so
`witness_roundtrip` and `witness_encode_size` are concrete, unconditional
facts.  `witness_decode_length` (definitionally the same as
`witness_encode_size`) confirms the decoder accepts the witness at exactly
319 bytes.

## Scope caveats

1. **TLV tail excluded.**  BOLT 2 allows an `open_channel_tlvs` stream after
   `channel_flags` (TLV 0 `upfront_shutdown_script`, TLV 1 `channel_type`).
   `decode` here accepts exactly the 319-byte fixed prefix and rejects every
   longer input (`decode_eq_none_of_size_gt`).  That is a deliberate sharp
   statement, not a claim that a real BOLT 2 message has no TLVs.  H13 models
   the TLV stream and its extra length; the two records share the same
   319-byte fixed prefix.
2. **319 vs 313.**  The wave-7 sketch and `docs/OPEN-ISSUES.md:165` use a
   `313`-byte figure for a reduced record that omits `chain_hash` (32) and
   `channel_reserve_satoshis` (8) and assumes an inline 34-byte
   `shutdown_scriptpubkey` (34).  The full mandatory BOLT 2 fixed prefix is
   `313 + 32 + 8 − 34 = 319`; `payload_layout` states the exact arithmetic and
   `encode_size` proves it on the wire domain.  The task-table and issue text
   should be corrected to **319** (TLVs additional).
3. **Wire domain, not semantics.**  `decode_encode` is conditional on
   `WireValid`; without it `beBytes` truncates modulo `256^k`.  No theorem
   asserts cryptographic validity of the points, amount sanity, or
   `chain_hash` correctness.  `decode_wireValid` shows every accepted record
   *is* in that domain, so the domain is not an extra assumption on received
   messages.
4. **No shared-file claim.**  Nothing in `Protocol/Messages.lean`,
   `Protocol/Handshake.lean`, `Protocol/Laws.lean`, or `Protocol/Peer.lean` was
   changed.  The patch below is a proposal for the parent; until it is applied,
   `Msg.openChannel`/`MsgKind.openChannel` do not exist and this module's
   record is local.  H14 is also independent of H13's TLV-complete record: the
   integrator must choose one record (or merge them) rather than adding both.
5. **No consensus or signature claim.**  This is a byte-layout and parser
   theorem.  It says nothing about ECDSA, funding authorization (`S7`), or
   channel state.

## Exact shared-file integration patch (`LnLean/Protocol/Messages.lean`)

before `structure AcceptChannel` (line 90); `UInt8`, `Nat`, `ChainHash`,
`ChannelId`, and `PubKey` are already in scope.  No new import is needed.

```lean
-- 2. `inductive Msg`: add immediately after `| init (m : InitMsg)`.
  | openChannel (m : OpenChannelMsg)

-- 3. `inductive MsgKind`: add immediately after `| init`.
  | openChannel

-- 4. `Msg.kind`: add immediately after `| .init _ => .init`.
  | .openChannel _ => .openChannel

  | 32 => some .openChannel

  | .openChannel _ => 319

-- 8. `channelId?`: add immediately after `| .init _ => none`.
  | .openChannel m => some m.temporaryChannelId

-- 9. `pubKeys`: add immediately before the `| .acceptChannel m =>` case.
```

cases automatically.  `msgLength = 319 ≤ 65535`, so `wellFormed` holds on the
same wire domain.
