### The transition carries the exact message

```lean
theorem msgStep_sendOpen_exact {s s' : MsgFundingPhase} {m : OpenChannelMsg}
    (h : msgStep s (.sendOpen m) = some s') :
    s'.openSent = some m ∧ s'.openReceived = s.openReceived ∧
      s'.acceptSent = s.acceptSent ∧ s'.acceptReceived = s.acceptReceived

    (h : msgStep s (.recvOpen m) = some s') :
    s'.openReceived = some m ∧ s'.openSent = s.openSent ∧
      s'.acceptSent = s.acceptSent ∧ s'.acceptReceived = s.acceptReceived

    {a : AcceptChannel} (h : msgStep s (.sendAccept a) = some s') :
    s'.acceptSent = some a ∧ s'.openReceived = s.openReceived ∧
      s'.openSent = s.openSent ∧ s'.acceptReceived = s.acceptReceived ∧

    {a : AcceptChannel} (h : msgStep s (.recvAccept a) = some s') :
    s'.acceptReceived = some a ∧ s'.openSent = s.openSent ∧
```

The exact `accept_channel` is stored, the exact opposing `open_channel` is
preserved unchanged, and a successful accept transition still requires the
open payload to be present.

```lean
    {es : List MsgFundingPhaseEvent} (ht : MsgTrace s es) {a : AcceptChannel}

    ∃ m : OpenChannelMsg,
      s.openSent = some m ∧ MsgFundingPhaseEvent.sendOpen m ∈ es ∧
      OccursBefore (MsgFundingPhaseEvent.sendOpen m)
        (MsgFundingPhaseEvent.recvAccept a) (es ++ [MsgFundingPhaseEvent.recvAccept a])

theorem msgTrace_sendAccept_prior_recvOpen {s : MsgFundingPhase}
    {es : List MsgFundingPhaseEvent} (ht : MsgTrace s es) {a : AcceptChannel}

        (MsgFundingPhaseEvent.recvAccept a) es
```

The `_exact_provenance` theorems are the strongest ordering form: the exact
message guarded by the transition is the one that occurred earlier in the same
history, strictly before the new accept event.

## Scope caveats

- **Local payload only.** `H16.OpenChannelMsg` is the funding-relevant
  projection, not the wire-complete type-32 record. It has no `chain_hash`,
  policy/basepoint fields, `channel_flags`, or `shutdown_scriptpubkey`, and no
  encoder/decoder. Wire registration/length belongs to H13/H15/H17 and the
  pending `Protocol.Messages` patch.
- **H13/H15/H17 adapter is exact but external.** The parent can instantiate
  the bridge from a wire record with
  `H16.OpenChannelMsg.ofWire r.temporaryChannelId r.fundingSatoshis r.pushMsat
  r.fundingPubKey`; `ofWire_toOpenChannel` proves the resulting projection is
  the explicit `OpenChannel` record. H15's `OpenChannelMsg.toOpenChannel` is
  the same four-field projection, so the adapter is definitionally the same
  map.
- **Transport attribution remains external.** `open_channel` carries no
  sender and no signature. `same_msg_distinct_senders` proves one payload is
  compatible with two distinct claimed senders. `msgAttributed_key_in_script`
  is conditional on `OpenChannelAttributed`, and neither Noise authentication
  nor key ownership is proved here (`PR-01`/C3, `docs/ASSUMPTIONS.md` §3).
- **No `HandshakeState`/`handshakeStep` edit.** The bridge targets the
  existing separate `FundingPhase`; the ten-milestone `HandshakeState` is
  untouched. Wiring an `OpenChannelMsg` field into `HandshakeState` or
  `Protocol.Messages` is a shared-file change outside this lane.
- **History is an event trace, not a network trace.** `MsgTrace` records one
  endpoint's local transition order. `OccursBefore` is intra-endpoint event
  precedence; cross-peer causality/delivery is not modelled. The witness
  relates the two endpoints only by sharing the same exact messages.
- **Ordering theorems require reachability/trace.** Arbitrary
  `MsgFundingPhase` records (constructed directly, not reached through
  `msgStep`) need not satisfy `OrderingInv`.
- H15 records the fixed BOLT 2 payload as **319** bytes; the wave-8 table's
  `313` figure is not asserted by this module. H16 makes no wire-length claim.
