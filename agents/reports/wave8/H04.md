## What is mechanized

The module fixes:

- `probePrevout := ⟨[1].toByteArray, 0⟩` — a short non-null outpoint;
- `oneInputTx w seq` — version 2, one input with empty scriptSig and sequence
  `seq`, one empty zero-valued output, witness stack `[w]`;
- `probeTable program amount` — every prevout resolves to the P2WSH program
  `(p2wsh program).bytes` with a *known* amount `some amount`;
- `probeUtxo` — a non-coinbase, matured, in-range UTXO entry.

For this transaction the module proves the *computational* reduction

```lean
scriptLaneTx (oneInputTx w seq) (probeTable program amount) standardScriptFlags
    ({} : PolicyFlags)
  = (match verifyWitnessProgram
        (pipelineFuel ByteArray.empty (p2wsh program).bytes w)
        w 0 program standardScriptFlags ({} : PolicyFlags)
        (txCheckerFor (oneInputTx w seq) 0 (some amount)) false with
     | .ok => some true | .fail _ => some false | .unjudged => none)
```

(`scriptLaneTx_oneInput_verify`), and hence the `some true` / `some false`
specializations.  The outer P2WSH script is reduced by
`verifyScriptFull_p2wsh`; the outer two pushes are shown to parse and execute,
and the transaction/table/fee gates are discharged by
`oneInputTx_checkTransaction`, `oneInputTx_not_coinbase`,
`probeTable_supplied`, `probeTable_amountsKnown` and `probeUtxo_feeOk`.

The fuel mismatch between the concrete
`pipelineFuel = 34 + 77 + |sig| + 28` and the development fuel `10` is
removed by a general fuel-inertness lemma
`evalFrom_fuel_eq_of_lt` (`ops.length < f → ops.length < g`), lifted through
`evalScriptBytes`, `executeWitnessScript` and `verifyWitnessProgram`
(`..._toLocal_fuel_eq_...`).  `pipelineFuel_oneInput_gt_nine` supplies the
strict bound.

## Exact result

All names are in `LnLean.Proofs.WaveH.H04`.  Write

```lean
sc := serializeOpcodes (toLocalOps revocationKey delayedPaymentKey csv)
chk := txCheckerFor (oneInputTx [sig, sel, sc] seq) 0 (some amount)
```

where `sel = ByteArray.empty` is the delayed selector and
`sel = revocationSelector` (`#[0x01]`) is the revocation selector.

### Delayed lane: iff / positive / negatives

```lean
theorem scriptLaneTx_oneInput_delayed_iff
    (rk dpk : PubKey) (csv : Blocks) (program : ByteArray) (amount : Amount)
    (sig : ByteArray) (seq : UInt32) (n : ScriptNum)
    (hr : rk.bytes.size = 33) (hd : dpk.bytes.size = 33) (hsigsz : sig.size ≤ 520)
    (hdec : decodeNum ({} : PolicyFlags) (delayBytes csv) 5 = .ok n)
    (hnn : 0 ≤ n) (hdis : Int.toNat n &&& SEQUENCE_LOCKTIME_DISABLE_FLAG = 0)
    (hseq : checkSequenceDef chk.env n = true)
    (hder : isValidSigEncoding sig = true)
    (hps : program.size = 32)
    (htruth : Bitcoin.Numeric.castToBool program = true)
    (hprog : hashSha256 sc = program) :
    scriptLaneTx (oneInputTx [sig, ByteArray.empty, sc] seq)
        (probeTable program amount) standardScriptFlags ({} : PolicyFlags) = some true
      ↔ chk.base.checkECDSASignature sig dpk.bytes sc .witnessV0
          (default : Bitcoin.Crypto.Seam.ScriptExecutionData) = true
```

The positive and negative lane verdicts are separate theorems:

```lean

theorem scriptLaneTx_oneInput_delayed_bad_sig   … (hsig : … = false) : … = some false
theorem scriptLaneTx_oneInput_delayed_csv_false … (hseq : checkSequenceDef chk.env n = false)
                                                                     : … = some false
```

and the same five shapes at `verifyWitnessProgram` level
(`verifyWitnessProgram_delayed_std_iff`, `..._std`, `..._bad_sig_std`,
`..._csv_false_std`, plus `..._fuel` arbitrary-fuel forms).

### Full pipeline

`txVerdictFull_oneInput` proves that the stateless prefix, coinbase gate,
prevout table, amount table and fee slice all pass on this concrete data and
leave exactly the script lane.  Composing with the lane results yields:

```lean
theorem txVerdictFull_oneInput_delayed_ok        … : txVerdictFull … = some true
theorem txVerdictFull_oneInput_delayed_bad_sig   … : txVerdictFull … = some false

theorem txVerdictFull_oneInput_revocation_ok      … : txVerdictFull … = some true
theorem txVerdictFull_oneInput_revocation_bad_sig … : txVerdictFull … = some false
```

with table `probeTable program amount`, UTXO set `probeUtxo`, arbitrary spend
height `sh`, flags `standardScriptFlags` and policy `{}`.

### Consensus-height flag corollary

```lean
theorem txVerdictFull_oneInput_delayed_ok_at_height
    … (height : UInt32)
    (hheight : Bitcoin.Activation.BIP147_HEIGHT < height)
    (hexc : height ∉ Bitcoin.Activation.EXCEPTION_HEIGHTS) … :
    txVerdictFull … (getBlockScriptFlags height) ({} : PolicyFlags) = some true
```

by `flags_after_burial`.  Only the delayed positive verdict is specialized;
the negative verdicts transport identically but were not duplicated.

### Checker bridge

```lean
theorem txCheckerFor_ecdsa_eq_verify
    (tx : Bitcoin.Data.Tx) (nIn : Nat) (amount : Amount)
    (sig pk code : ByteArray)
    (hpk : Bitcoin.Crypto.Seam.Der.isValidPubKey pk = true) (hne : 0 < sig.size) :
    (txCheckerFor tx nIn (some amount)).base.checkECDSASignature sig pk code .witnessV0
        (default : Bitcoin.Crypto.Seam.ScriptExecutionData)
      = Bitcoin.Crypto.Ecdsa.Verify.verifyImpl
          (sig.extract 0 (sig.size - 1)) pk
          (LnLean.Bitcoin.Sighash.sighashWitnessV0 tx nIn code (hashtypeOf sig) amount)
```

This is the pointwise bridge to the concrete vendor verifier; it is not used
as a premise by the lane theorems, which stay at the `checkECDSASignature`
boundary exactly as `scriptLane` consumes it.

## Scope caveats

1. **One concrete transaction shape.**  The result is for `oneInputTx`
   (one input, empty scriptSig, one empty output, one witness stack) and the
   constant table `probeTable`.  No general multi-input or arbitrary-table
   transfer is claimed.
2. **`some amount` only.**  `txCheckerFor … none` (missing-data fail-closed
   state) is lane H01's subject; this module always supplies `some amount`.
3. **Fixed flag/policy words.**  Statements use `standardScriptFlags` (all
   seven flags true) and `({} : PolicyFlags)`.  The height corollary only
   covers `BIP147_HEIGHT < height` and non-exception heights via
   `flags_after_burial`; `minimalData` is lane H05 and the `csv ≥ 32768`
   boundary is lane H06.
4. **DER side condition is explicit.**  `hder : isValidSigEncoding sig = true`
   is a premise of every positive/negative lane theorem.  The module does not
   prove an invalid-DER negative; with `dersig = true` that is the encoding
   gate, not the ECDSA verdict.  It also does not prove `isValidSigEncoding`
   from any byte-level premise.
5. **Signature hypotheses are vendored checker verdicts.**  The lane theorems
   consume `checkECDSASignature … = true/false`; they do not prove that this
   verdict equals a concrete `verifyImpl` call in the lane statements (the
   separate `txCheckerFor_ecdsa_eq_verify` gives that equality under
   `isValidPubKey` and `0 < sig.size`).  No computational EC reduction is
   claimed (`CR-01`).
6. **Sequence/decode premises are explicit.**  `hdec`, `hnn`, `hdis` and
   `hseq` are hypotheses.  They can be discharged by
   `decodeNum_delayBytes`, `nonneg_delay`, `disableBit_delay` and
   `checkSequenceDef_delay_iff` under `csv < 32768`; the range edge itself is
   H06.
7. **Program premises are explicit.**  `program.size = 32`,
   `castToBool program = true` and `hashSha256 sc = program` are required.
   The hash equality is a premise, not a collision-resistance claim.
8. **No model/`P2WSHSpend` refinement here.**  H04 is the
   `scriptLaneTx`/`txVerdictFull` transfer; the model-level `P2WSHSpend`
   correspondence remains the wave-5/6/7 bridge (and lanes H02/H03/H31/H32).
9. **Fuel is not a side condition.**  `pipelineFuel` is shown strictly larger
   than the nine executed opcodes, and fuel above the opcode count is proved
   inert, so no fuel premise leaks into the verdicts.
