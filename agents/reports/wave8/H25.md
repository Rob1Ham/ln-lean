## Scope caveats

- **Full wire equality needs the wire-domain index bound.**  `SighashContext`
  stores `fundingOutputIndex : Nat` while `CommitmentWire` stores `UInt32`.
  `viewOfTx_eq_viewOfWire` therefore assumes `fundingOutputIndex < 2^32`; the
  unconditional relation is the modulo field lemma
  `viewOfTx_fundingOutputIndex_mod`.  This is a type-boundary artifact, not a
  missing proof; BOLT 3's output index is a 4-byte field.
- **Exact legacy refinement is output-order sensitive.**  `viewOfState` reads
  `Commitment.commitmentOutputs` in construction order; the rich site reads
  the BOLT-3-sorted `outputsNet`.  `viewOfTx_eq_viewOfState_of_outputs` is the
  exact hypothesis needed to transport every existing `SighashTargets` theorem
  (digest derivation, `SighashProduces`, C3 binding, coverage).  The general
  normal-form result `viewOfTx_outputs_perm_viewOfState` is only a `List.Perm`;
  the commitment digest is **not** order-invariant, and D12 remains the
  unconditional ordering refutation.  No digest claim is made under a
  permutation.
- The normal-form permutation uses `dustLimitSat = 0` and nonzero
  `toLocalSat`/`toRemoteSat`, exactly the hypotheses of the existing
  `CommitmentTx.map_toCommitmentOutput_outputsUnsorted`.  It is not a claim
  that arbitrary dust limits agree with the legacy zero-value trimming; the
  rich dust test is the CH-03 net test and stays separate.
- **HTLC identity is not in `CommitmentHTLCOutput`.**  The adapter reads
  `htlcViewsOfState ctx st` (as `viewOfState` does) because `htlcId` and
  `paymentHash` are only on `SignedHtlc`.  A caller with only a
  `CommitmentTx` must supply that metadata; this module does not invent it.
- **Scripts are dropped by the structural view.**  `viewOfTx_eq_of_map_eq`
  records the coarseness; the script-sensitive wire bytes are only constrained
  by the existing `SighashTargets.structuralView_not_determine_scripts`.  No
  view-level script injectivity is claimed.
- The obscured-number encoding is proved for `obscuredCommitmentNumber < 2^48`
  only (BOLT 3's 48-bit field); out-of-range values are not claimed.
- `wireOfTx` fixes version `2` and derives `nSequence`/`nLockTime` from the
  obscured number as BOLT 3 specifies; it does not model BIP 68 relative
  locktime or the single-anchor exception.
- No shared file was edited; no Git operation was performed.
