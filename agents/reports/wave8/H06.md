## Exact result

The lane question was what happens to the delayed `to_local` branch at and
above `csv = 32768`, where wave 7 assumed `csv < 32768`. The answer is exact:
the payload is little-endian **sign-magnitude**, so the high byte `≥ 0x80` is a
sign byte and the decoded operand is negative (or zero at exactly `32768`).
A two-byte payload cannot encode any non-negative value `≥ 32768` at all, so
the “out-of-range” branch is not representable; the canonical minimal encoding
of such a value needs at least three bytes. The BIP 68 operand disable bit is
therefore never set, and the BIP 112 “disable bit ⇒ NOP” branch of `OP_CSV` is
unreachable through `delayBytes`.

```lean
/-- Exact out-of-range decoding: `-(csv - 32768)`, not `csv`. -/
theorem setVchBE_delay_ge (csv : Nat) (hlo : 32768 ≤ csv) (hhi : csv < 65536) :
    setVchBE [(csv >>> 8) % 256, csv % 256] = -(((csv - 32768 : Nat)) : Int)

theorem decodeBE_delay_ge (csv : Nat) (hlo : 32768 ≤ csv) (hhi : csv < 65536) :
    decodeBE false 5 (bytesOf (delayBytes csv)).reverse =
      some (-(((csv - 32768 : Nat)) : Int))

theorem decodeNum_delayBytes_ge (pol : PolicyFlags) (hmin : pol.minimalData = false)
    (csv : Nat) (hlo : 32768 ≤ csv) (hhi : csv < 65536) :
    decodeNum pol (delayBytes csv) 5 = .ok (-(((csv - 32768 : Nat)) : Int))

/-- At exactly `32768` the delay silently collapses to `0`. -/
theorem decodeNum_delayBytes_32768 :
    decodeNum ({} : PolicyFlags) (delayBytes 32768) 5 = .ok (0 : Int)

theorem dispatchOp_csv_delayBytes_32768_nonneg (ctx : Ctx) (st : State)
    (htop : topAt st.stack 1 = delayBytes 32768)
    (hmin : ctx.pol.minimalData = false) :
    decodeNum ctx.pol (topAt st.stack 1) 5 = .ok (0 : Int)
```

## Scope caveats

- **The boundary defect is a model artifact, not a mainnet consensus claim.**
  `delayBytes csv` is the fixed-width two-byte little-endian field
  `[csv % 256, (csv / 256) % 256]`. BOLT 3 requires the *minimal*
  `CScriptNum` encoding, and a faithful implementation encodes a delay in
  `[32768, 65535]` in **three** bytes
  (`encodeScriptNum_delay_size_ge_three`). The sign-byte collapse at
  `csv = 32768` therefore shows that this model's payload stops being a
  faithful script number exactly at `32768`; it does not say that a BOLT 3
  node would misencode `to_self_delay`. `csv < 32768` is exactly the domain on
  which the pairwise payload is faithful
  (`decodeNum_delayBytes_self_iff`).
- **The wave-7 range hypothesis cannot be dropped without changing the
  operand.** `boundary_nominal_context_fails` is deliberately stated against
  the *nominal* claim `32768 ≤ masked sequence` with `csv = 32768` substituted
  for the decoded operand. The true statement at the boundary is
  `toLocal_delayed_boundary_32768_vendor_iff`, whose sequence side is
  `checkSequenceDef env 0`. The two differ; that gap is the theorem.
- **`minimalData = false` is assumed for decoding.** With `minimalData = true`
  the vendor would reject the non-minimal two-byte payload before `OP_CSV`;
  the module therefore carries `hmin : pol.minimalData = false` wherever a
  concrete payload is decoded. The `minimalData = true` scaffold encoding is
  outside this lane (as in wave 7).
- **`OP_CSV` is analyzed at the `dispatchOp` step, not through the full
  pipeline.** This is the same `SequenceContextTargets` level as wave 7; the
  `TxValidation.Full`/`txCheckerFor` transfer is H01/H02 and is imported here
  only through the derived vendor criterion.
- **No consensus/EC claim is added.** The retained counterexample assumes the
  delayed-key ECDSA check is `true`; assumption C3 (EUF-CMA) and the
  transaction-validity bridge remain open, and the `.ok` verdict is about the
  vendored interpreter with the abstract `ScriptChecker`, not about Bitcoin
  Core consensus.
- **`delayBytes` is not injective** (`delayBytes_not_injective`): `0` and
  `65536` share a payload. This is a second, independent fidelity limitation of
  the fixed `u16` field; it is recorded rather than repaired because changing
  the encoding is a model change outside this lane.
