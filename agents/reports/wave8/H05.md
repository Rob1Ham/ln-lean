### 2. Model/vendor branch-selection counterexample

With the same witness `#[0x00]` the model executes the revocation (`OP_IF`)
branch, while the vendor casts `#[0x00]` to false and executes the delayed
(`OP_ELSE`) branch:

```lean
theorem exec_toLocal_nonminimal_selector_model
    (L : InterpreterLaws) (msg : ByteArray)
    (revocationKey delayedPaymentKey : PubKey) (csv : Blocks)
    (sig : ByteArray)
    (h : L.sigCheck revocationKey.bytes msg sig = true) :
    execStmts L msg (toLocalProg revocationKey delayedPaymentKey csv)
      [nonMinimalFalse, sig] = some [oneByte]

theorem accepts_toLocal_nonminimal_selector_model
    (L : InterpreterLaws) (msg : ByteArray)
    (revocationKey delayedPaymentKey : PubKey) (csv : Blocks)
    (sig : ByteArray)
    (h : L.sigCheck revocationKey.bytes msg sig = true) :
    Accepts L msg (toLocalProg revocationKey delayedPaymentKey csv)
      [nonMinimalFalse, sig]
```

The vendor side is a symbolic execution of the delayed branch, rejecting with
`.unsatisfiedLocktime` when the sequence check fails:

```lean

    (chk : ScriptChecker)
    (revocationKey delayedPaymentKey : PubKey) (csv : Blocks)
    (sig : ByteArray) (n : ScriptNum)

    (hseq : checkSequenceDef chk.env n = false) :
    evalFrom
      { flags := ({ csv := true } : ScriptFlags), pol := ({} : PolicyFlags),
        chk := chk, sv := .witnessV0,
        bytes := serializeOpcodes (toLocalOps revocationKey delayedPaymentKey csv),
        ed := (default : Bitcoin.Crypto.Seam.ScriptExecutionData) }
      10 (toLocalWireOps revocationKey delayedPaymentKey csv)
      { stack := [nonMinimalFalse, sig], alt := [], vf := [], opCount := 0,
        codeSep := 0, vwLeft := none }
```

(`toLocalCtx` and `toLocalInit` are the definitional abbreviations of the
context and initial-state records used in the other theorems.)

The pair is stated as one mechanized divergence at the full P2WSH verifier:

## Scope caveats

- The truthiness divergence is a property of the **Wave-4 model**
  (`truthy d := d.size ≠ 0`), not of the vendored interpreter. The vendor half
  uses Core's `castToBool`; `#[0x00]` and `#[0x80]` are Core-false and
  model-true. Witness elements are not opcode pushes, so `MINIMALDATA` cannot
  repair this divergence.
- `minimalDataPolicy` is `{ minimalData := true }` with every other policy bit
  off. The positive `MINIMALDATA` theorem is for `128 ≤ csv < 32768`; the
  negative theorem is for `csv < 128`. Values `≥ 32768` are outside the
  two-byte payload and are handled separately by H06.
- The `csv < 128` rejection is a **policy** rejection
  (`scriptFailKind = .notStandard`), not a consensus rule. The default/block
  word remains the wave-7 exact iff.
- The full-verifier theorems assume the standard witness-shape facts
  (`revocationKey.bytes.size = 33`, `delayedPaymentKey.bytes.size = 33`,
  `sig.size ≤ 520`, `program.size = 32`, `program = hashSha256 script`), the
  exact sequence environment (`checkSequenceDef chk.env n = true/false`), and
  the delayed-key ECDSA result. They do not assume signature validity.
- The positive path is symbolic in `pol` only through `IsDelayPolicy`
  (`pol = {}` or `pol = minimalDataPolicy`), matching the two policy words
  characterized in this wave.

## Catalog / roadmap recommendation

- Close the `MINIMALDATA` edge for the scaffold `to_local` delayed branch:
  the sharp boundary is `csv = 128`, the push is minimal, and the failure is
  `.scriptNum` under a standard-not-mandatory bit.
- Keep `MODEL-01` open only for the model's truthiness law; the vendor is not
  affected. The counterexample `truthy_nonminimal_true` is preserved.
- Reuse `decodeNum_delayBytes_minimalData_iff` as the canonical policy-decode
  target for future policy lanes; no catalog rewording is needed.
