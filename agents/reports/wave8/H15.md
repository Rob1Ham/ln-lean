   `H13` (or the `H17` full record) is kept by the parent, the projection must
   be re-pointed; see the integration patch below.

   `refs/bolts/02-peer-protocol.md:686-706` sums to
   `32 + 32 + 6*8 + 4 + 2 + 2 + 6*33 + 1 = 319`.  The wave-8 table's `313`
   figure is not the BOLT 2 value; `fixedPayloadWidth_eq` records `319`.
3. **TLVs are excluded.**  `open_channel_tlvs` types 0
   (`upfront_shutdown_script`) and 1 (`channel_type`) are optional and live
   outside the fixed payload, matching `Messages.lean`'s no-TLV-parsing policy.
   `H17` includes `shutdownScriptpubkey : Option ByteArray`; this local record
   does not.
4. **Field-shape mismatch with the sibling full record.**  `H17` uses
   `chainHash : ByteArray` and `channelFlags : UInt8`; this record uses
   `ChainHash` and `Nat`.  The four funding fields are identical in both, so
   the projection theorems transfer by `rfl` once the parent picks one record.
5. **No decoder/encoder or message registration.**  `H14`/`H18` own
   encode/decode and `H17` owns `Messages.lean` type-32 registration.  This
   module proves only the projection, field agreement, negotiation, and hash
   link.
6. **No attribution.**  `open_channel` carries no sender identity or
   signature.  `FundingAuthTargets.same_message_distinct_senders` remains the
   scope boundary; this lane adds no authentication claim.
7. **No new cryptographic assumption.**  `toFundingParams_keys_in_script`
   reuses the existing `FundingAuthTargets` result and the finite
   `CollisionFreeOn` admission; no global SHA-256 injectivity is assumed.
