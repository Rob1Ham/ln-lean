## Scope caveats

- **The witness model is degenerate by design.** `registration_witness` and
  `honest_witness` instantiate the pinned single-message verifier
  (`KeyModelTargets.pinnedModel` / `pinnedKeyModel`). It is a full
  `PrimitiveModel` satisfying the model's `EufCma` field and
  `KeyBinding`, but it is not a real secp256k1/ECDSA implementation, not a
  computational EUF-CMA game, and its key generation is constant. The result
  proves *logical non-vacuity* of the conditional contract, not computational
  security.
- **`AdvertisesKey` remains a hypothesis.** This module proves what follows
  from it and supplies an instance; it does not derive it from
  `accept_channel.funding_pubkey`. `KeyModelTargets.key_generation_not_key_attribution`
  and lane H24 retain the counterexample.
- **No possession/ownership game.** `Owns` is the existential
  "some seed generates this pair" relation from `Crypto.KeyModel`; it is not a
  proof-of-possession. The secret key is concrete and non-empty (32 bytes) but
  never appears in the accept payload.
- **Transport attribution is out of scope.** `accepting_key_attribution` binds
  the *key receiving the funding signature* and its presence in the script; it
  does not bind the key to a peer identity. That remains the Noise/transport
  obligation (`docs/ASSUMPTIONS.md` §3) as modelled by
  `FundingAuthTargets.PeerIdentity`/`OpenChannelAttributed`.
- **The v1 machine has no `open_channel` constructor.** The complete
  open/accept/funding exchange is witnessed in the additive
  `FundingPhase`/`fundingStep` machine; the `HandshakeState` witness covers the
  `init → accept_channel → funding_created` boundary only. This matches the
  documented v1 simplification.
- **`M.sha256` is the model's opaque SHA-256 interface**, not verified FIPS
  180-4. The P2WSH output theorem is conditional on that model function; the
  hash link and 32-byte width law are proved from `PrimitiveModel.sha256_size`.
- **Ordering is not pinned in the statement.** `firstFundingKey`/
  `secondFundingKey` are the BOLT 3 lexicographic order; the module proves the
  output equals `p2wsh (H (TwoOfTwoScriptBytes first second))` rather than
  asserting a specific key order for the concrete pair.
- **No H19–H22 import.** At this base the H19–H24 modules are other lanes'
  files. H23 is deliberately self-contained and uses the shared
  `AcceptChannel`/`FundingPhase`/`KeyModel` model directly, so it builds
  independently of whether the parent keeps any particular sibling lane. If
  H19's `AcceptChannelPayload` is retained, a follow-up bridge can relate its
  funding-key projection to `demoAccept.fundingPubKey`; no current theorem
  depends on that name.
