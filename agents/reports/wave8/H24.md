```lean
namespace LnLean.Proofs.WaveH.H24

/-- `accept_channel` payload + the sender identity reported by the transport. -/
structure ReceivedAccept where
  sender : PeerIdentity          -- FundingAuthTargets.PeerIdentity
  message : AcceptChannel

/-- The exact additional premise for sender attribution: the
Noise-authenticated peer identity is the `funding_pubkey` in the payload. -/
def TransportBound (r : ReceivedAccept) : Prop :=
  r.sender.key = r.message.fundingPubKey

/-- Registration + generated sender identity (composed premise). -/
def RegisteredBound {M : PrimitiveModel} (K : KeyModel M) (seed : ByteArray)
    (r : ReceivedAccept) : Prop :=
  AdvertisesKey K seed r.message ∧ r.sender.key = K.publicOfSeed seed
```

### Negative result (preserved and strengthened)
```lean
/-- *Every* accept payload can be emitted by two distinct senders. -/
theorem any_accept_payload_two_senders (a : AcceptChannel) :
    ∃ r₁ r₂ : ReceivedAccept,
      r₁.message = a ∧ r₂.message = a ∧ r₁.sender ≠ r₂.sender

/-- The heads-up negative result at the accept payload. -/
theorem same_accept_payload_distinct_senders :
    ∃ r₁ r₂ : ReceivedAccept,
      r₁.message = r₂.message ∧ r₁.sender ≠ r₂.sender

/-- The whole wire `Msg` is equal for the two senders. -/
theorem same_accept_wire_message_distinct_senders :
    ∃ r₁ r₂ : ReceivedAccept,
      Msg.acceptChannel r₁.message = Msg.acceptChannel r₂.message ∧
      r₁.sender ≠ r₂.sender

/-- The fixed 270-byte payload length is also identical. -/
theorem same_accept_wire_length_distinct_senders :
    ∃ r₁ r₂ : ReceivedAccept,
      msgLength (Msg.acceptChannel r₁.message) =
          msgLength (Msg.acceptChannel r₂.message) ∧
        msgLength (Msg.acceptChannel r₁.message) = 270 ∧
        r₁.sender ≠ r₂.sender

/-- No total payload→sender decoder exists. -/
theorem no_payload_to_sender_function :
    ¬ ∃ f : AcceptChannel → PeerIdentity,
        ∀ r : ReceivedAccept, f r.message = r.sender

/-- Any payload-determined predicate is blind to the sender. -/
theorem payload_only_test_cannot_attribute (P : ReceivedAccept → Prop)
    (hP : ∀ r₁ r₂ : ReceivedAccept,
      r₁.message = r₂.message → (P r₁ ↔ P r₂)) :
    ∃ r₁ r₂ : ReceivedAccept,
      r₁.message = r₂.message ∧ r₁.sender ≠ r₂.sender ∧ (P r₁ ↔ P r₂)
```

### Registration / proof of possession are not sender attribution
```lean
/-- `AdvertisesKey` is a payload property and holds for both senders. -/
theorem registration_does_not_attribute {M : PrimitiveModel} (K : KeyModel M)
    (seed : ByteArray) (a : AcceptChannel)
    (hreg : AdvertisesKey K seed a) :
    ∃ r₁ r₂ : ReceivedAccept,
      r₁.message = a ∧ r₂.message = a ∧ r₁.sender ≠ r₂.sender ∧
      AdvertisesKey K seed r₁.message ∧ AdvertisesKey K seed r₂.message

/-- PoP transcript for the advertised funding key. -/
structure ReceivedAcceptPop where
  receipt : ReceivedAccept
  challenge : ByteArray
  proof : EcdsaSig

def ProvesFundingKey (M : PrimitiveModel) (p : ReceivedAcceptPop) : Prop :=
  M.ecdsaVerify p.receipt.message.fundingPubKey p.challenge p.proof = true

/-- A valid funding-key PoP is compatible with two distinct senders. -/
theorem funding_key_pop_does_not_attribute_senders (M : PrimitiveModel)
    (a : AcceptChannel) (challenge : ByteArray) (sig : EcdsaSig)
    (hpop : M.ecdsaVerify a.fundingPubKey challenge sig = true) :
    ∃ p₁ p₂ : ReceivedAcceptPop,
      p₁.receipt.message = a ∧ p₂.receipt.message = a ∧
      p₁.receipt.sender ≠ p₂.receipt.sender ∧
      p₁.challenge = challenge ∧ p₂.challenge = challenge ∧
      p₁.proof = sig ∧ p₂.proof = sig ∧
      ProvesFundingKey M p₁ ∧ ProvesFundingKey M p₂
```

## Scope caveats
- **`TransportBound` is not derived.** It is exactly the transport-attribution assumption of `docs/ASSUMPTIONS.md` §3 (Noise authenticates a peer identity; the model treats the transport as an ideal authenticated channel). The theorem `transport_bound_attributes_sender` is conditional on it, and the negative results show it cannot be obtained from the `AcceptChannel` payload.
- **The payload really has no sender field.** `ReceivedAccept` attaches the sender outside `AcceptChannel`; the counterexample proves the attachment is not a function of the payload. `PeerIdentity` is the model-level peer key, not a proved Noise property.
- **Registration alone is insufficient for sender attribution.** `AdvertisesKey` from `KeyModelTargets` constrains only `funding_pubkey`; `registration_does_not_attribute` shows it holds equally for two senders. It is a *key*-registration hypothesis, not a channel-attribution hypothesis.
- **PoP alone is insufficient for sender attribution.** `ProvesFundingKey` is an abstract `PrimitiveModel.ecdsaVerify` predicate; it says the funding key was used to sign a challenge, not who owns the transport. A PoP transcript is compatible with two senders (`funding_key_pop_does_not_attribute_senders`). The composed `RegisteredBound` closes the gap only because it explicitly equates `sender.key` with the generated key.
- **No key-binding claim.** Nothing here derives `KeyBinding` or key ownership from C3. `KeyModelTargets.key_generation_not_key_attribution` remains the mechanized limit; C3 is an EUF-CMA-style assumption under a fixed key, not a key-ownership game.
- **No claim about the BOLT 8 implementation.** The theorem consumes the peer identity as given; it does not model the Noise handshake, static-key pinning, or channel binding.
- **`acceptChannelWithFundingKey` is used for neutral concrete payloads.** Other accept fields are fixed to `0`/zero values; the counterexample depends only on the absence of a sender field, so this does not narrow the result. The universal theorem `any_accept_payload_two_senders` removes any dependence on that concrete payload.
- **No shared-file edits.** Root import, `AxiomAudit`, catalog, traceability, and `check-final.py` counts are parent-owned; the exact patches are below.
- **Existing counterexample untouched.** `FundingAuthTargets.same_message_distinct_senders` is imported and re-exported by `open_channel_counterexample_retained`; the source file was not modified.
