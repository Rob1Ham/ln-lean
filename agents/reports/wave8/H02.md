### Local checker equality (H01 is not present)

Whole-record equality
`txCheckerFor tx nIn (some amount) = realCheckerOf tx nIn amount` is **false**:
`txCheckerFor`'s base is `txCheckerOf …` (real BIP340 Schnorr entry) while
`realCheckerOf`'s base is `realEcdsaEntry` (fail-closed Schnorr stub). On
witness-v0 P2WSH only the ECDSA entry and the locktime environment are
consulted, so the needed local equality is proved instead of assumed:

```lean
theorem txCheckerFor_some_checkECDSA_eq_checkerOf
    (tx : Bitcoin.Data.Tx) (nIn : Nat) (amount : Amount)
    (sig pk code : ByteArray) (v : Bitcoin.Crypto.Seam.SigVersion)
    (d : Bitcoin.Crypto.Seam.ScriptExecutionData) :
    (Bitcoin.TxValidation.Full.txCheckerFor tx nIn (some amount)).base.checkECDSASignature
        sig pk code v d =
      (LnLean.Proofs.Bitcoin.SighashBridgeTargets.checkerOf
        Bitcoin.Crypto.Ecdsa.Verify.verifyImpl tx nIn amount).base.checkECDSASignature
        sig pk code v d

theorem txCheckerFor_some_env_eq_locktimeEnvOf
    (tx : Bitcoin.Data.Tx) (nIn : Nat) (amount : Amount)
    (hIn : nIn < tx.vin.length) :
    (Bitcoin.TxValidation.Full.txCheckerFor tx nIn (some amount)).env =
      LnLean.Proofs.Bitcoin.SighashBridgeTargets.locktimeEnvOf tx nIn

theorem txCheckerFor_some_consumes_model_digest
    (tx : Bitcoin.Data.Tx) (nIn : Nat) (amount : Amount)
    (sig pk scriptCode : ByteArray) (ed : Bitcoin.Crypto.Seam.ScriptExecutionData)
    (hpk : Bitcoin.Crypto.Seam.Der.isValidPubKey pk = true) (hne : 0 < sig.size) :
    (Bitcoin.TxValidation.Full.txCheckerFor tx nIn (some amount)).base.checkECDSASignature
        sig pk scriptCode .witnessV0 ed =
      Bitcoin.Crypto.Ecdsa.Verify.verifyImpl (sig.extract 0 (sig.size - 1)) pk
        (LnLean.Bitcoin.Sighash.sighashWitnessV0 tx nIn scriptCode
          (LnLean.Proofs.Bitcoin.SighashBridgeTargets.hashtypeOf sig) amount)
```

### Transfer theorem

```lean
theorem toLocal_delayed_txCheckerFor_iff_realChecker
    (tx : Bitcoin.Data.Tx) (nIn : Nat) (amount : Amount)
    (revocationKey delayedPaymentKey : PubKey) (csv : Blocks)
    (sig : ByteArray) (program : ByteArray) (hcsv : csv < 32768)
    (hr : revocationKey.bytes.size = 33) (hd : delayedPaymentKey.bytes.size = 33)
    (hsigsz : sig.size ≤ 520)
    (hps : program.size = 32)
    (hprog : hashSha256
      (serializeOpcodes (toLocalOps revocationKey delayedPaymentKey csv)) = program) :
    verifyWitnessProgram 10
        [sig, ByteArray.empty,
          serializeOpcodes (toLocalOps revocationKey delayedPaymentKey csv)]
        0 program ({ csv := true } : ScriptFlags) ({} : PolicyFlags)
        (Bitcoin.TxValidation.Full.txCheckerFor tx nIn (some amount)) false = .ok ↔
      verifyWitnessProgram 10
        [sig, ByteArray.empty,
          serializeOpcodes (toLocalOps revocationKey delayedPaymentKey csv)]
        0 program ({ csv := true } : ScriptFlags) ({} : PolicyFlags)
        (Bitcoin.Capstone.RealChecker.realCheckerOf tx nIn amount) false = .ok
```

This is the requested transfer: every delayed-branch result at
`realCheckerOf` lifts, on the exact witness, to `txCheckerFor (some amount)`.
No `nIn < tx.vin.length` premise is needed here because both checkers read
`RealChecker.dummyTxIn`.

### Exact delayed criterion at `txCheckerFor` (strongest form, no index premise)

```lean
theorem toLocal_delayed_txCheckerFor_refinement
    (tx : Bitcoin.Data.Tx) (nIn : Nat) (amount : Amount)
    (revocationKey delayedPaymentKey : PubKey) (csv : Blocks)
    (sig : ByteArray) (program : ByteArray) (hcsv : csv < 32768)
    (hr : revocationKey.bytes.size = 33) (hd : delayedPaymentKey.bytes.size = 33)
    (hsigsz : sig.size ≤ 520)
    (hps : program.size = 32)
    (hprog : hashSha256
      (serializeOpcodes (toLocalOps revocationKey delayedPaymentKey csv)) = program)
    (hpk : Bitcoin.Crypto.Seam.Der.isValidPubKey delayedPaymentKey.bytes = true)
    (hne : 0 < sig.size) :
    verifyWitnessProgram 10
      [sig, ByteArray.empty,
        serializeOpcodes (toLocalOps revocationKey delayedPaymentKey csv)]
      0 program ({ csv := true } : ScriptFlags) ({} : PolicyFlags)
      (Bitcoin.TxValidation.Full.txCheckerFor tx nIn (some amount)) false = .ok ↔
      ((¬ tx.version < 2) ∧
        ((tx.vin.getD nIn Bitcoin.Capstone.RealChecker.dummyTxIn).sequence.toNat &&&
            SEQUENCE_LOCKTIME_DISABLE_FLAG) = 0 ∧
        ((tx.vin.getD nIn Bitcoin.Capstone.RealChecker.dummyTxIn).sequence.toNat &&&
            (SEQUENCE_LOCKTIME_TYPE_FLAG ||| SEQUENCE_LOCKTIME_MASK)) <
          SEQUENCE_LOCKTIME_TYPE_FLAG ∧
        csv ≤ ((tx.vin.getD nIn Bitcoin.Capstone.RealChecker.dummyTxIn).sequence.toNat &&&
            (SEQUENCE_LOCKTIME_TYPE_FLAG ||| SEQUENCE_LOCKTIME_MASK)) ∧
        Bitcoin.Crypto.Ecdsa.Verify.verifyImpl (sig.extract 0 (sig.size - 1))
          delayedPaymentKey.bytes
          (LnLean.Bitcoin.Sighash.sighashWitnessV0 tx nIn
            (serializeOpcodes (toLocalOps revocationKey delayedPaymentKey csv))
            (hashtypeOf sig) amount) = true)
```

## Scope caveats

- **Positive-direction transfer only.** The theorem characterizes one P2WSH
  witness (the delayed `to_local` branch) under its exact script-shape premises;
  it is not an unconditional `ConsensusSpendBridge` and does not model
  transaction-level validity, finality, or mempool admission.
- **`some amount` is a fully-resolved prevout amount.** `none` is the
  pipeline's `-1`/`HandleMissingData` state and is proved rejecting, not
  silently defaulted to zero.
- **`csv < 32768`.** This is the faithful fixed-width delay range. The
  `csv ≥ 32768` / disable-bit policy edge is lane H06; the `minimalData` policy
  edge is lane H05. The statements fix `flags = { csv := true }` and
  `pol = {}` (the wave-7 bridge's defaults).
- **Script-shape premises.** `revocationKey.bytes.size = 33`,
  `delayedPaymentKey.bytes.size = 33`, `sig.size ≤ 520`,
  `program.size = 32`, and `(serializeOpcodes (toLocalOps …))` hashing to
  `program` remain explicit hypotheses. The clawback key enters only through
  the witness script; the delayed branch checks the delayed-payment key.
- **EC boundary.** `hpk` (`isValidPubKey`) and `hne` (`0 < sig.size`) are the
  vendored adapter's gates to the EC math. The verifier is the concrete lax
  secp256k1 `Bitcoin.Crypto.Ecdsa.Verify.verifyImpl` over the BIP 143 model
  digest; no computational security claim is made.
- **No `hIn` in the strongest theorem.** `txCheckerFor`-only statements use
  `RealChecker.dummyTxIn`; the `_of_lt` corollary rewrites it to the wave-7
  `dummyTxIn` under `nIn < tx.vin.length`. Thus both the strongest and the
  source-matching forms are available; there is no hidden index premise.
- **Schnorr field not equated.** The full records differ in
  `checkSchnorrSignature`; only the witness-v0-relevant ECDSA entry and the
  environment are proved equal. This is deliberate and is exactly why the
  literal whole-record H01 target is false.
