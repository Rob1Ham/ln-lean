## Scope caveats

- **Value-only boundary.**  The theorem is about the `List CommitmentOutput`
  a legacy consumer reads. `LnLean.Bitcoin.CommitmentOutput` additionally
  carries `scriptPubKey`; the legacy channel type has no script field, so
  script bytes, witnesses, sighash digests, signatures, and consensus validity
  are not claimed to be preserved. `CommitmentParams.HashesMatch` is untouched.
- **Zero-HTLC construction only.**  `CommitmentParams.commitmentOutputs` is the
  four-output template list. HTLC outputs and their second-stage fee/dust
  trimming live at the `CommitmentHTLCOutput.netAmountSat` record boundary and
  remain under `CommitmentTypesTargets`' explicit `NetConsistentOnRecords`
  hypothesis. `offeredHtlc`/`receivedHtlc`/`mutualClose` project to `none`.
- **Signed values.**  `BtcAmount = Int`, while `Channel.CommitmentOutput`
  stores `Nat`. The normal form therefore includes `0 ≤ toLocalValue` and
  `0 ≤ toRemoteValue`; a negative value has no faithful legacy counterpart and
  is dropped by the projection (wave-E `E45` boundary retained).
- **Normal form is not removable.**  `belowDust_migration_changes_params_boundary`
  mechanizes that a below-dust `to_local` changes the migrated list. The
  zero-value edge is separately retained by `zero_toLocal_params_not_legacy`.
  Both are consistent with the D12 and wave-4 `dust_trimming_not_perm`
  counterexamples, which remain untouched.
- **Pair/HTLC consumer sites are out of scope here.**  `CommitmentPair.migrateNet`
  and the `CoversMigratedOutputs` coverage predicate were already closed by
  wave 7; this lane adds only the downstream script-parameter boundary.
- **Construction-site fields.**  `paramsToCommitment` records
  `trimmedTotalSat := 0`; under the no-trim normal form this is exactly the
  migration result. `migrateForConsumer` recomputes the stored trim value
  otherwise.
- Only the lane module is built; no full-tree build is claimed.
