New helper lemmas (all `private`, so the module's public surface is
unchanged):

* `pushUInt32LE_size` — the fixed-width little-endian encoding is 4 bytes;
* `pushUInt32LE_get0` … `pushUInt32LE_get3` — bytes 0–3 are
  `n.toUInt8`, `(n >>> 8).toUInt8`, `(n >>> 16).toUInt8`,
  `(n >>> 24).toUInt8`;
* `pushScriptNum32_eq` — `pushScriptNum32 n = [4] ++ pushUInt32LE n`;
* `pushData_injective` — the one-byte length prefix can be cancelled;
* `receivedHtlcWitnessScript_decompose` — the received-HTLC script is
  `prefix ++ pushScriptNum32 cltv ++ suffix`;
* `offeredHtlcWitnessScript_decompose` — the offered-HTLC script is
  `prefix ++ pushData paymentHash ++ suffix`.

Proof outline. For (1), cancel the common `[4]` length prefix, read the four
`pushUInt32LE` bytes back out, and reconstruct `a = b` with `omega` from
`a < 2^32`, `b < 2^32` and the four byte/modulus equalities. For (2) and
(3), rewrite both scripts with the decomposition lemmas, cancel the common
parameter prefix and constant suffix (`ByteArray.append_right_inj` /
`append_left_inj`), then apply (1) or `pushData_injective`. No statement was
weakened; the size hypotheses in (3) are retained even though `pushData`
injectivity does not need them.
