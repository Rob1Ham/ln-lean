## 3. Proof approach and helper lemmas

The target theorem assumes the session is `pending`, but after the first
`.failed` outcome the session is no longer pending, so a direct induction with
`hk : state = .pending` does not go through. The proof therefore generalizes the
induction invariant to "the session has not succeeded":

1. `settle_failed_not_succeeded`: unfolding `Keysend.settle` and
   `PaymentSession.settle`, a pending session becomes `.failed` (not
   `.succeeded`), and a non-pending session is returned unchanged (so the
   hypothesis `≠ .succeeded` is preserved).
2. `applyOutcomes_failed_not_revealed`: induction on `os`.
   * `[]`: `applyOutcomes [] = k`, and `revealedPreimage` is `none` because the
     state is not `.succeeded` (definitional unfolding of `revealedPreimage`).
   * `o :: os`: `hall` forces `o = .failed`; the tail still consists only of
     failures; the induction hypothesis applies to `k.settle .failed` using
     the helper from step 1.
3. `all_failed_outcomes_never_reveal` instantiates step 2 with
   `hk : state = .pending`, which immediately gives `state ≠ .succeeded`.

No statement was weakened and no new imports were needed (the existing import
set `LnLean.Payment.Invoice`, `LnLean.Payment.HTLC` is unchanged).
