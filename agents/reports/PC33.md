## Summary

The new module formalises the composition from a funding output's P2WSH
script and two valid funding signatures to spendability.  The concrete
script-semantics obligation is an explicit field of `FundingSpendBridge`
(not a global postulate, not a `sorry`).  The composition is proved in both
directions: an accepted witness is exactly
`<> <sig1> <sig2> <witnessScript>` with both signatures valid, and that
witness is accepted exactly when both funding keys sign.

## Import note

The module imports `LnLean.Proofs.Bitcoin.FundingProps` rather than the root
`LnLean`.  This is a clearly sufficient narrower import (it supplies
`FundingParams`, `FundingOutput`, `p2wsh`, `fundingScriptPubKey`,
`Script`/`Tx` aliases and the parser theorem).  At the time of the build the
root `LnLean` was not compiling because of another agent's in-progress
`LnLean/Proofs/Channel/ReserveProps.lean` (PC18), which is outside this
mission.  The FundingBridge build itself is green and independent of that
file.  No existing import, `LnLean.lean`, or `lakefile.lean` was edited.

## Source theorems used

* `LnLean.Bitcoin.p2wsh_size` (`LnLean/Bitcoin/Seam.lean`) — P2WSH
  `scriptPubKey` is 34 bytes for a 32-byte program.
* `LnLean.Bitcoin.fundingScriptPubKey` / `FundingOutput.scriptPubKey` /
  `FundingParams.fundingScriptPubKey` / `FundingParams.toFundingOutput`
  (`LnLean/Bitcoin/Seam.lean`, `LnLean/Bitcoin/Funding.lean`) — the output
  construction.
* `LnLean.Proofs.Bitcoin.FundingProps.witnessScript_parse_eq_none_of_wellFormed`
  — the legacy `Script.parse` rejects the BOLT 3 witness script for
  well-formed (33-byte-key) parameters.
* Definitions `twoOfTwoWitness` and `BothKeysSign` mirror the BOLT 3 witness
  `<> <sig1> <sig2> <witnessScript>` and the two signature checks; the
  module does not assume them, it proves the composition.

## Remaining obligation and discovered gap

* `PC2-FUND-001` (not a `sorry`; it is the `script_semantics` field of
  `FundingSpendBridge`): instantiate `verify` with the concrete vendored
  byte-level semantics and prove that it accepts exactly the BOLT 3 2-of-2
  witness.  The smallest next step is to connect
  `Bitcoin.Data.Script.parse` (no `OP_CHECKMULTISIG` constructor,
  `vendor/btc-lean-core/Bitcoin/Data/Script.lean:31-41`) or the newer
  `Bitcoin.Interpreter.checkMultiSig`
  (`vendor/btc-lean-core/Bitcoin/Interpreter/Defs.lean:1027-1090`) to the
  four-element witness shape.  Nothing in `vendor/` was modified.
* Discovered gap: `FundingParams` does not itself connect
  `witnessScriptHash` to `SHA256(witnessScript)`; the module therefore states
  the exact P2WSH-of-script form conditionally on that hash equation
  (`fundingOutputOfParams_scriptPubKey_eq_p2wsh`).  The no-collision binding
  lemma already exists in `FundingProps`; it is not duplicated here.
