## Checker design

1. **Catalog parse.** `LnLean/Proofs/Obligations.lean` is read and comments are
   removed with offsets preserved. Record literals are found with a balanced
   brace scanner (braces inside strings are skipped), then `id`, `leanTarget`,
   and `status` are extracted from each record. Semicolon-separated targets
   (`LN-RT-001`, `LN-PM-001`) are split into individual names.
2. **Declaration map.** Every `LnLean/**/*.lean` file is scanned. The checker
   tracks `namespace` / `section` blocks (including dotted namespaces and
   nested namespaces), and records the fully-qualified name, declaration kind,
   module, line, and source body of each named declaration. Attributes,
   `private` / `protected` / `noncomputable` / `partial` / `unsafe` modifiers,
   and names containing `?` or `!` are handled. Private declarations are
   deliberately excluded: Lean mangles their real names, so a plain source
   name is not an exact target.
3. **Comment/string stripping.** Both nested `/- ... -/` comments and `--`
   line comments are blanked. String contents are blanked when looking for
   terms, so `"sorry"` in a string or comment cannot make a declaration look
   proved. Actual words `sorry` are detected with a word-boundary search.
4. **Exact resolution.** A target is accepted only if its full dotted name is
   in the map exactly once. A same-named declaration in another namespace, a
   substring, a comment, or a string is never accepted. Missing and ambiguous
   targets are errors.
5. **`proved` rows.** Every target of a `proved` row must resolve exactly. If
   the target is a `theorem` or `lemma`, its source body must contain no actual
   `sorry`. A target that is an `axiom`, `constant`, or `opaque` is also an
   error for a `proved` row.
6. **Promotion audit.** A `statementOnly` row is listed as a promotion
   candidate only when *all* of its targets resolve exactly to sorry-free
   `theorem`/`lemma` declarations. The checker only reports candidates; it
   never rewrites statuses.
7. **Exit status.** `0` when all targets resolve and no `proved` row fails;
   `1` for an unresolved/ambiguous target, a failing `proved` row, a duplicate
   id, or an incomplete catalog row; `2` for a missing input tree.

## Limitations

* This is source-level parsing, not a kernel or `Environment` query. It sees
  only declarations written in `LnLean/**/*.lean`; it cannot see imported
  declarations outside the tree, declarations generated by macros/attributes
  under names not present in the source, or Lean's private-name mangling (so
  private declarations are intentionally not accepted).
* A declaration body is taken to run from its source line to the next
  top-level declaration. This matches the current tree, where every top-level
  declaration starts in column 0, but it is a lexical approximation rather
  than a full Lean parser.
* The checker proves only that the named declaration exists, has the recorded
  kind, and has no source-level `sorry`. It does **not** prove that the
  theorem statement entails the English `claim`; that semantic check remains
  human review.
* Ambiguous duplicate full names are errors only when a catalog target hits
  them. The current tree has no duplicate non-private full names among the
  declarations that could collide with a target.
* `sorry` detection covers named declaration bodies. A `sorry` in an
  `example` or other unnamed command would not be attributed to a catalog
  target, though it would still be a policy issue for other checkers.
* Semicolon-separated targets are treated as a conjunction: all named
  declarations must resolve and, for `proved` rows, all must be sorry-free.
