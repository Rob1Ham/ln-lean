- Added hypotheses:

  - `waveD_d03_toLocalScript_size_valid` assumes `revocationPubKey.Valid`
    (33-byte key) to conclude the concrete 39-byte size; the general size
    theorem is unconditional.
  - `waveD_d03_toLocalScript_delay_recoverable` assumes `csv < 256` and
    `csv' < 256`; without these bounds the encoded value is only `csv % 256`.

- Statement fidelity: the target is the seam definition
  `LnLean.Bitcoin.toLocalScript`, whose template is
  `<csv> OP_CSV OP_DROP <revocation_pubkey> OP_CHECKSIG`. The proofs are about
  the exact bytes produced by that definition; no hashing, key derivation,
  script execution, or spendability is assumed. The seam places the
  `revocationPubKey` parameter directly before `OP_CHECKSIG`; BOLT 3 instead
  places the revocation key in the `OP_IF` penalty branch and the delayed
  payment key in the `OP_ELSE` branch. The full BOLT 3 P2WSH witness script
  (with the `OP_IF <revocationpubkey> OP_ELSE <to_self_delay> OP_CSV OP_DROP
  <local_delayedpubkey> OP_ENDIF OP_CHECKSIG` branches) is a separate model
  (`LnLean.Bitcoin.ScriptTemplates.toLocalWitnessScript`); this module proves
  the delay/key payload of the seam's commitment-output fragment under the
  seam's naming.

## Remaining gap / next step

The seam's delay encoding is `Nat.toUInt8`:

```lean
pushData (ByteArray.mk #[csv.toUInt8])
```

so delays ≥ 256 are truncated to their low byte. This is a model gap, not a
failed proof: the counterexample `0` vs `256` is mechanized. Closing it would
require changing `LnLean.Bitcoin.toLocalScript` to a minimal script-number
encoding (the `ScriptTemplates.pushScriptNum16` style) or adding a model
predicate/invariant `0 < csv ∧ csv < 256` at every call site. No model file
was modified in this task. The remaining BOLT 3 gap is the full witness script
(revocation branch and delayed-payment key), which is outside the named
catalog target and already has its own template.
