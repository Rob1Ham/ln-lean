# D12 — Commitment outputs are ordered by value then script, and dust HTLCs are trimmed.

## Target

- Parent/catalog: `LN-CH-003`
- Module: `LnLean.Proofs.WaveD.D12`
- File: `LnLean/Proofs/WaveD/D12.lean`

## Result

- Status: counterexample
- Build: RC 0 (`flock -w 900 /tmp/ln-build.lock lake build LnLean.Proofs.WaveD.D12`)
- Theorems/definitions:
  - `unsortedCommitment`, `waveD_d12_commitmentOutputs_not_value_sorted`,
    `waveD_d12_output_ordering_fails`, `waveD_d12_exists_unsorted_commitment`
    — `Commitment.commitmentOutputs` emits `to_local` before `to_remote`, so a
    500-sat output precedes a 200-sat output.  The unconditional ordering claim
    is false.
  - `cltvOrderLeft`, `cltvOrderRight`, `waveD_d12_cltv_tiebreak_not_recoverable`
    — two commitments with the same direction/value HTLCs but opposite
    `cltv_expiry` orders have identical `commitmentOutputs`; the CLTV tiebreak
    is erased by the output type.
  - `OutputSortKey` (`valueSat`, `scriptRank`, `cltvExpiry`),
    `OutputSortKey.Le` with `le_refl`/`le_trans`/`le_total`,
    `sortByKey`, `sortByKey_perm`, `sortByKey_pairwise`,
    `sortByKey_pairwise_components`, `waveD_d12_output_ordering_conditional`
    — conditional repair: given an external per-output BOLT key, `mergeSort`
    yields a permutation whose value sequence is nondecreasing and whose
    equal-value pairs are ordered by script rank and then CLTV.
  - `sortByValue`, `sortByValue_perm`, `sortByValue_sorted`,
    `waveD_d12_commitmentOutputs_value_sort` — value-only repair of the
    model's output list (permutation, nondecreasing values), unconditional.
  - `CommitmentHTLCOutput.ofRecord`, `survivingHTLCs`, `htlcOutputsOf`,
    `trimCommitmentHTLCs`, `map_ofRecord_eq`, `waveD_d12_mem_survivingHTLCs`,
    `waveD_d12_dust_htlc_trimmed`, `waveD_d12_nonDust_htlc_kept`,
    `waveD_d12_surviving_value_ge_dust`, `waveD_d12_mem_htlcOutputsOf`,
    `waveD_d12_htlcOutput_value_ge_dust`, `waveD_d12_nonDust_output_mem`,
    `waveD_d12_htlc_output_present_iff`, `waveD_d12_dust_output_absent`,
    `waveD_d12_htlcOutputsOf_length_eq_filter`, `waveD_d12_trimHTLCs_outputs`
    — dust half over `HTLCRecord`: a record produces its output exactly when
    `isDustHTLC` is false; dust and sub-limit outputs are absent; the trimmed
    commitment refines `commitmentOutputs`.
  - `zeroValueHtlcCommitment`, `waveD_d12_zero_value_htlc_emitted`,
    `waveD_d12_zero_value_htlc_is_dust`,
    `waveD_d12_dust_trimming_requires_filter` — `commitmentOutputs` itself
    emits a zero-valued (dust) HTLC output, so trimming is not a property of
    the model's output function.
- Added hypotheses:
  - `waveD_d12_output_ordering_conditional` assumes a tag
    `key : CommitmentOutput → OutputSortKey` and
    `hval : (key o).valueSat = o.value`.  The model cannot supply the script
    rank or the HTLC CLTV: `CommitmentOutput` has no `scriptPubKey` field, and
    `CommitmentOutput.htlc` stores only `direction` and `valueSat`.
  - The dust construction takes the input as `List HTLCRecord` plus the
    broadcaster's dust limit and the two second-stage fees.  The model's
    `Commitment.htlcs : List CommitmentHTLCOutput` is already projected and
    carries no dust flag, so `trimCommitmentHTLCs` is a separate refinement,
    not a change to the model.
- Statement fidelity: the catalog target is conjunctive.
  (a) “ordered by value then script” is **false** of
  `LnLean.Channel.Commitment.commitmentOutputs` as modelled: it uses the fixed
  group order `to_local, to_remote, HTLCs, anchors`, and neither script bytes
  nor CLTV expiry is present on `CommitmentOutput`.  The file states the
  mechanized counterexample and the strongest conditional sorting theorem.
  (b) “dust HTLCs are trimmed” is true for the `isDustHTLC` /
  `survivingHTLCs` construction, whose criterion is BOLT 3's
  `amount - second_stage_fee < dust_limit_satoshis`; it is **not** true of
  `commitmentOutputs` alone, which emits whatever records it is given
  (including a zero-valued one).  No claim was weakened silently.

## Remaining gap / next step

- Add `scriptPubKey` and `cltvExpiry` to the channel commitment-output
  representation (or a tagged output type), and implement BOLT 3's memcmp
  script comparison there.  Then the `key` and `hval` hypotheses of
  `waveD_d12_output_ordering_conditional` can be discharged and the sorted
  construction can replace the model's fixed group order.
- Add the dust limit and second-stage fees to `Commitment` (or make
  `commitmentOutputs` consume `List HTLCRecord`), so
  `waveD_d12_trimHTLCs_outputs` becomes an equation about the model's own
  output function rather than a refinement.
- The LDK `payment_hash` fallback in `is_left_greater` (fuzz determinism) is
  documented but not included in `OutputSortKey`; BOLT's three keys are
  modelled.
