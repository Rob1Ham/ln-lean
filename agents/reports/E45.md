- Parent/catalog: `LN-CH-002`

## Result

- Status: proved
- Build: RC 0 (`flock -w 900 /tmp/ln-build.lock lake build LnLean.Proofs.WaveE.E45`)
- Theorems/definitions:
  - `waveE_e45_output_value_nonneg` — every `CommitmentOutput.value` is `≥ 0` as an `Int`.
  - `waveE_e45_output_value_nat_nonneg` — the same in `Nat`.
  - `waveE_e45_commitmentOutputs_value_nonneg` — every output in
    `Commitment.commitmentOutputs c` has a nonnegative value.
  - `waveE_e45_commitmentOutputs_sum_eq_total` — the sum of the emitted
    output values equals `c.totalOutputValue` (imported
    `Commitment.outputsValue_commitmentOutputs`).
  - `waveE_e45_commitmentOutputs_sum_nonneg` and
    `waveE_e45_totalOutputValue_nonneg` — the total emitted value is
    nonnegative.
  - `waveE_e45_anchor_outputs_pos` — both anchors are strictly positive
    (330 sat).
  - `waveE_e45_script_commitmentOutputs_nonneg` — conditional nonnegativity
    for the signed L1-facing template model.
  - `negativeScriptParams`, `negativeScriptOutput`,
    `waveE_e45_script_outputs_unconditional_false` — mechanized counterexample
    to the unconditional template-level claim.
- Added hypotheses: none for the channel target.  The template companion
  assumes `0 ≤ p.toLocalValue` and `0 ≤ p.toRemoteValue`; the counterexample
  shows these are necessary.
- Statement fidelity: the catalog's named target
  `LnLean.Channel.Commitment.outputs_nonnegative` does not exist in the model,
  so it is re-derived from `LnLean.Channel.Commitment.commitmentOutputs`.
  `CommitmentOutput.value : CommitmentOutput → Nat` and all satoshi fields of
  `Commitment`/`CommitmentHTLCOutput` are `Nat`, so no well-formedness or range
  predicate is needed: a negative channel output value is unrepresentable.
  This is a structural fact about the encoding, not a proof that signed wire
  amounts were bounded.  The model's separate signed representation
  `LnLean.Bitcoin.CommitmentOutput.value : BtcAmount = Int` is copied from
  `CommitmentParams.toLocalValue` / `toRemoteValue`; there the claim is false
  unconditionally (counterexample included), and the missing invariant is
  exactly those two bounds.  That invariant belongs to the template layer, not
  to `LnLean.Channel.Commitment`.

## Remaining gap / next step

The channel-level claim is complete and needs no added assumption.  The
L1-facing template layer should add a `CommitmentParams` well-formedness
predicate containing `0 ≤ toLocalValue` and `0 ≤ toRemoteValue` (and ideally
`moneyRange` bounds), then derive the unconditional template statement from
`waveE_e45_script_commitmentOutputs_nonneg`.  No `sorry` remains.
