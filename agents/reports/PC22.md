# PC22 — `LnLean.Proofs.PhaseC2.HTLCPartition`

Target: `LnLean/Proofs/PhaseC2/HTLCPartition.lean` (new module).
Mission: prove the HTLC state partition, the partition/whole-list sum identity,
the offered-append in-flight increment, and the settled-plus-in-flight ledger
identity used by `ReserveProps`.

## Result

All declarations below are **proved**; the module contains no `sorry`,
`axiom`, `admit`, `native_decide`, `unsafe`, or `@[implemented_by]`.

The module imports `LnLean.Channel.Types` rather than the root `LnLean`.
This is a deliberate narrower import: the module needs only `HTLC`, `Channel`,
`Msat`, `Balance`, and `HTLCState`, all supplied by `Types`.  At commit time
the root import also pulls `LnLean.Proofs.Channel.ReserveProps`, which another
lane was actively repairing (uncommitted `committed_update_preserves_ledger_deficit`
proof), so importing the root would have made this independent arithmetic
module fail for an unrelated reason.  The same definitions
`htlcInFlightValue` and `spendLocalBalance` as in `ReserveProps` are mirrored
in this module.

## Newly discovered gap / open integration item

- Not a false model claim in this module.  The integration gap is that the
  root `LnLean` import was temporarily unbuildable because
  `LnLean.Proofs.Channel.ReserveProps` had an uncommitted in-progress repair
  (`committed_update_preserves_ledger_deficit`, `Nat.min` rewrite mismatch).
  The narrow import keeps this module buildable; when the reserve lane is
  green again, the integrator may either keep the narrow import or add
  `import LnLean` if a uniform root import is required.
- The list-level partition is order-insensitive: `pendingHTLCs l` is not
  syntactically `offeredHTLCs l ++ receivedHTLCs l` because filtering groups
  states; the proved statement is the correct membership partition plus the
  additive sum identity, not a false list-equality claim.
