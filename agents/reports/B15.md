## 4. Mission coverage and the one corrected claim

* **Both old outputs → one sweep output**: `penaltyValid_spends_both_and_sweeps_one`.
* **Sweep value = input value − fee**: `penaltyValid_sweep_eq_total_sub_fee`,
  `penaltyValid_sweep_add_fee`, plus non-negativity bounds
  (`penaltyValid_sweep_le_total`, `penaltyValid_sweep_nonneg`).
* **Only valid before the window closes**: `penaltyWindowClosed`,
  `penaltyValid_before_window_closes`, `not_penaltyValid_of_window_closed`.
  The exact predicate is `¬ (c.breachHeight + window ≤ confirm)`, i.e.
  `confirm < c.breachHeight + window` with the lower bound from
  `timelyL1Confirmation`.
* **No double spend by the breacher**: `penaltyValid_no_breacher_spend`,
  `penaltyValid_blocks_toLocal_spend`, `penaltyValid_blocks_toRemote_spend`,
  relative to `L1ScriptBridge.noDoubleSpend`.
* **No current commitment key required**: `penaltyValid_current_key_independent`
  and `penaltyValid_ignores_current_keys`; `PenaltyWitness` contains only the
  old secret and the punisher's revocation basepoint.
* **“`penaltyValid` implies the witness secret is the breached commitment's
  secret” — corrected/conditional.** The raw `penaltyValid` definition cannot
  entail this: `RevokedCommitment` has no target revocation key and no secret
  index, and its key conjunct
  `deriveRevocationPubkey … = scheme.derivePrivkey …` is exactly
  `RevocationScheme.consistent`, which holds for every secret. The module
  therefore introduces `penaltyValidBindsSecret`, which adds the old output's
  target-key binding, and proves
  `penaltyValidBindsSecret_secret_eq` from that binding plus injectivity of
  revocation-key derivation on secrets. This is the honest conditional form
  of the mission claim; the model gap is not hidden.

## 5. What remains open / next smallest proof step

1. **Close the secret-binding gap in the model (A4-owned).** Add a target
   revocation key (or the old commitment's `per_commitment_point`) and a
   secret index to `RevokedCommitment`, then make `penaltyValid` require
   `target = revocationPubkeyOfSecret scheme base w.secret` and
   `w.secret = revocationSecret sh c.number`. The proof of
   `penaltyValidBindsSecret_secret_eq` then becomes the raw-model theorem.
2. **Discharge key injectivity.** `penaltyValidBindsSecret_secret_eq` assumes
   `∀ s t, revocationPubkeyOfSecret base s = revocationPubkeyOfSecret base t →
   s = t`. The next smallest step is to derive it in the crypto layer from
   the concrete secp256k1 blinding equation (BOLT 3 `:817`), or add it as an
   explicit `RevocationScheme` field in a future model revision.
3. **Tie `window` to the old commitment's CSV.** The current `window` is a
   parameter; it is not read from `toLocalScript`/`to_self_delay`. Next step:
   add the old commitment's `to_self_delay` to `RevokedCommitment` and prove
   `penaltyWindowClosed` equivalent to `breachHeight + toSelfDelay ≤ confirm`.
4. **HTLC outputs.** Only the two main outputs are modelled. Per-HTLC
   penalty outputs and second-stage revoked HTLC transactions remain an
   obligation for the HTLC/penalty integration wave.
5. **Script/signature execution.** `L1ScriptBridge.confirms` is still an
   abstract predicate; no signature or script semantics is proved.
