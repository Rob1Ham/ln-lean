## Reasoning

**Target 45 — E45 over D45 (medium confidence).**

Both files prove the catalog nonnegativity claim, both compile, and both have
zero `sorry`.  So the decision turns on supporting analysis and fidelity.

`D45` is the richer file by declaration count (`waveD_d45_signedToRemote`,
`waveD_d45_NoUnderflow`, the zero-HTLC and pair bridges, and
`waveD_d45_underflow_witness`), but its central differentiator is misstated:

- `D45.lean:103-108` defines the "signed BOLT 3 residual" as
  `funding - fee - to_local - anchors`, dropping the HTLC-output term.  BOLT 3
  (and LDK, `chan_utils.rs:1887-1910`) subtracts the untrimmed HTLC value as
  well; the model does too (`Laws.lean:69`).  Consequently
  `waveD_d45_signedToRemote` is *not* the value BOLT 3 computes whenever
  `c.htlcs ≠ []`, and the module's prose ("exactly the condition under which
  BOLT 3's `to_remote` is non-negative and the `Nat` subtraction … does not
  underflow", `D45.lean:110-113`) is false in general.  Hand computation: with
  `funding = 1000`, `fee = 100`, `toLocal = 100`, one 900-sat HTLC and no
  anchors, `waveD_d45_NoUnderflow` holds (200 ≤ 1000), yet the stored
  `toRemoteSat` under `settledCommitment` is `0` while the BOLT 3 residual is
  `-100`.  This is the invariant the module recommends to the integrator, and
  it is too weak for the general claim.
- `waveD_d45_pair_outputs_nonneg` (`D45.lean:206-211`) states
  `¬ ∃ o ∈ c.commitmentOutputs, o.value < 0` on `Nat` values.  It is true for
  every list and every `c` by `Nat.not_lt_zero`, i.e. vacuous, and it reads as
  a substantive result in the report.
- `D45` never touches the only representation in the tree where the claim can
  actually fail, `LnLean.Bitcoin.CommitmentOutput.value : BtcAmount = Int`
  (`ScriptTemplates.lean:117-121`, `Seam.lean:35`).

`E45` is leaner but accurate.  It proves the same channel-level claim, links it
to the declared total via the existing
`Commitment.outputsValue_commitmentOutputs`, proves anchor positivity, and then
does the one thing `D45` does not: it states the conditional theorem for the
signed L1 template model (`waveE_e45_script_commitmentOutputs_nonneg`,
`E45.lean:103-114`) and mechanizes the failure of the unconditional form
(`waveE_e45_script_outputs_unconditional_false`, `E45.lean:142-149`, using
`negativeScriptParams.toLocalValue = -1`).  That is the honest fidelity result
for `LN-CH-002`: nonnegativity is structural in the `Nat` channel model and
false in the `Int` template seam unless `0 ≤ toLocalValue`/`0 ≤ toRemoteValue`
are assumed.  Its report also states the catalog target name does not exist,
which `D45`'s report does not mention.

Counterargument, recorded: `D45`'s `waveD_d45_underflow_witness`
(`D45.lean:219-229`: stored `0`, true residual `-30`, `NoUnderflow` false) is a
better *counterexample* than anything in `E45`, and it is the only mechanized
demonstration that nonnegativity can coexist with an over-committed
commitment.  If the parent prefers depth on the channel model over the template
seam, `D45` is defensible — but only after replacing `waveD_d45_signedToRemote`
with an HTLC-aware residual (or restricting the module to zero-HTLC
commitments) and dropping the vacuous pair theorem.  As written, I would not
recommend shipping `D45` as the sole 45 file.

**Target 46 — D46, decisively (high confidence).**

- `E46` has no build evidence at all (no `.olean`; only a `setup.json` from an
  abandoned attempt) and no report, contrary to its brief
  (`agents/briefs/E46.md:5-9, 72-77`).  Its source is newer than that attempt.
  It also contains a demonstrably stale claim in its docstring
  (`E46.lean:275-277`: "`zeroHtlcCommitment`'s `to_remoteSat` does not subtract
  the anchors"), which is false for the model on disk —
  `Commitment.lean:191` subtracts `anchorTotal`.  The theorem statement is
  nevertheless true (the anchor term is subtracted *and* added back), but the
  explanation is wrong, which is consistent with an unverified, abandoned file.
- `E46`'s main constructor `waveE_e46_commitmentFromParts` (`E46.lean:135-148`)
  is a private duplicate of the model's `settledCommitment`
  (`Laws.lean:62-73`).  Its conservation/fee-isolation theorems therefore talk
  about a local copy rather than the model definition, unlike `D46`, which
  imports `LnLean.Channel.Laws` and applies `conservation_with_htlcs` directly
  (`D46.lean:180-236`).
- `D46` covers strictly more of the claim: emitted-list/total identity
  (`waveD_d46_emittedValue_eq_total`, `:133-152`), a general budget theorem
  (`:159-172`), exact residual and bound for `settledCommitment` and
  `zeroHtlcCommitment` (`:180-250`), a dust-trimming abstraction with a proved
  filter monotonicity lemma (`waveD_d46_applyDustTrim`,
  `waveD_d46_dustTrim_total_le`, `:270-357`), and one pair theorem that needs
  **no** affordability hypothesis when anchors are off (`:367-382`).
- Counterexample quality: `D46` has two.  `waveD_d46_unconditional_counterexample`
  (`:404-410`) refutes the bare record-level statement, and
  `waveD_d46_pair_anchor_counterexample` (`:434-438`, `decide` on
  `60000/39000` sat with anchors enabled and zero fee) is a concrete, mechanized
  instances of the Wave-A builder gap (outputs exceed funding by 660 sat).
  `E46` only has the record-level counterexample
  (`waveE_e46_unconditional_false`, `:402-411`) in two syntactic forms.
- `E46`'s one genuine advantage: its pair theorems handle `anchorOutputs = true`
  under `2 * anchorOutputSat ≤ fee` (`E46.lean:352-381`), whereas `D46` only
  *refutes* the anchor case.  If the parent keeps `D46`, port that conditional
  anchor theorem (and the fee-antitonicity lemma,
  `waveE_e46_fromParts_total_antitone_fee`, `:253-269`) as follow-up; do not
  swap files for it, because it is unbuilt and stated about a duplicate
  constructor.
- Weakness in `E46`'s extra hypotheses: the `hbal : fee ≤ (if funder = .local
  then b.localSat else b.remoteSat)` premise in the no-anchor pair theorems
  (`E46.lean:321,337`) is unnecessary — truncated `Nat` subtraction already
  keeps `(b.localSat - fee) + b.remoteSat ≤ b.localSat + b.remoteSat`.
  `D46`'s pair theorem proves the stronger, hypothesis-free (anchors-off) form.

**Cross-cutting notes for the parent.**
- The catalog claim is still `statementOnly` in
  `agents/status/obligations.json:366-375`; neither lane adds the missing
  `Commitment` well-formedness/conservation field, so both 46 files are
  legitimately conditional.  `D46`'s `waveD_d46_OutputBudget` is the better
  named invariant because it is HTLC-aware.
- The anchor-emission rule is approximate in the model relative to LDK
  (`chan_utils.rs:1932-1948`): `anchorOutputValue` adds 660 sat whenever the
  flag is set, regardless of whether either side's output is non-zero or HTLCs
  exist.  This is the root of `D46`'s pair counterexample and should be fixed
  in the model, not in the proof file.
- `F09` (Wave F) formalises the BOLT 3 "trimmed value is added to the fee" rule
  and carries one `sorry` (`LnLean/Proofs/ModelHardening/F09.lean:29-31`).
  `D46`'s dust-trim section deliberately does not credit trimmed value back to
  `feeSat` (`D46.lean:265-269`), so `D46` and `F09` are complementary, not
  duplicative; no statement conflict.
- All four files are untracked; none of the reports has been committed.  A
  "keep" decision must therefore include adding the chosen files to the tree
  and regenerating any index, which is outside this audit.
