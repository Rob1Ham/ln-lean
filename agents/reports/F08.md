# F08 — BIP69+CLTV output ordering

## Target
- Marker: `LN-WF-F08`
- Module: `LnLean.Proofs.ModelHardening.F08`
- Parent obligation: `LN-CH-ORDER`

## Result
- Status: counterexample
- Build: RC 0 (`flock -w 900 /tmp/ln-build.lock lake build LnLean.Proofs.ModelHardening.F08`)
- New definitions:
  - `OutputEntry` — a `CommitmentOutput` paired with its HTLC `cltvExpiry`
    (`0` for non-HTLC outputs), with `OutputEntry.ofOutput`, `ofHtlc`,
    `OutputEntry.key`.
  - `waveF_f08_commitmentOutputEntries` — the fixed document order
    (`to_local, to_remote, HTLCs, anchors`) annotated with CLTV expiries.
  - `waveF_f08_scriptRank` — canonical kind-level script rank
    (`to_local=0`, `to_remote=1`, offered HTLC=2, received HTLC=3,
    local anchor=4, remote anchor=5).
  - `OutputKey` (`valueSat`, `scriptRank`, `cltvExpiry`) with
    `OutputKey.lexLeProp` (value, then script, then CLTV) and
    `OutputKey.lexLe` (Bool form), plus `instDecidableLexLeProp`.
  - `Bip69CltvSorted script l` — `l.Pairwise` under the BOLT 3 key.
  - `bip69Sort script l` — `List.mergeSort` of the entries under the key.
  - `waveF_f08_bip69Outputs script c` — sorted outputs of a commitment.
  - Witnesses `waveF_f08_descendingCommitment`,
    `waveF_f08_oneHtlcCommitment`.
- Main theorems:
  - `bip69Sort_sorted` — for **every** script rank `script` and every entry
    list `l`, `Bip69CltvSorted script (bip69Sort script l)`.  This is the
    positive half: a sorted-output construction satisfies BOLT 3 ordering.
  - `bip69Sort_perm` / `bip69Sort_length` / `bip69Sort_idempotent` — sorting
    is a permutation, preserves length, and fixes sorted lists.
  - `Bip69CltvSorted.value_mono` — sorted entries have non-decreasing values.
  - `waveF_f08_commitmentOutputEntries_map_output` — forgetting the CLTV
    annotation recovers `Commitment.commitmentOutputs` exactly; the new
    predicate is about the model's output set, not a different one.
  - `waveF_f08_commitmentOutputEntries_not_sorted_of_toLocal_gt_toRemote` —
    if both `toLocalSat` and `toRemoteSat` are non-zero and
    `toRemoteSat < toLocalSat`, the fixed document order is **not**
    BIP 69+CLTV sorted for **any** script rank.
  - `waveF_f08_documentOrder_not_bip69` — there exists a commitment
    (`to_local = 1000`, `to_remote = 500`) that fails the predicate for every
    script rank assignment.
  - `waveF_f08_cltvExpiry_not_visible_in_commitmentOutputs` — two
    commitments with identical `commitmentOutputs` can have different HTLC
    `cltv_expiry`; the existing output list cannot express the third key.
  - `waveF_f08_cltvExpiry_changes_commitmentOutputEntries` — the annotated
    (and therefore sorted) output sequence does distinguish those two
    commitments.
  - `waveF_f08_sorted_three_entry_example`,
    `waveF_f08_sorted_cltv_tiebreak_example`,
    `waveF_f08_unsorted_cltv_tiebreak_example` — concrete checks of the value
    key and of the CLTV tie-break.
- Added hypotheses:
  - The ordering predicate takes an explicit script rank
    `script : CommitmentOutput → Nat`.  This is forced by the model: scripts,
    payment hashes, and keys are absent from `CommitmentOutput`.  The positive
    theorem is proved for all such assignments; the negative theorem is
    assignment-independent.
  - The conditional negative theorem assumes both balances non-zero and
    `toRemoteSat < toLocalSat`.  The existential negative theorem assumes
    nothing.
- Statement fidelity:
  - `Bip69CltvSorted` is exactly the three BOLT 3 keys
    (`03-transactions.md:54-59`): value in whole satoshis, then
    `scriptpubkey`, then (when value and script agree) increasing
    `cltv_expiry`.  HTLC millisatoshis are already discarded by
    `CommitmentHTLCOutput.amountSat`, matching the spec.
  - No claim was weakened.  The conditional sorted-construction theorem is
    universal in the script rank and in the entry list.  The fixed document
    order is proved *not* sorted, so no `sorry` is needed or present.
  - The only modelling abstraction is the middle key: an abstract `Nat` rank
    in place of `scriptpubkey` bytes.  Distinct output kinds are given
    distinct ranks; same-direction HTLCs share a rank because the model has no
    payment hash, so their relative order is delegated to the CLTV key (and to
    `bip69Sort`, which uses the supplied rank).

## Missing model field / next step

`CommitmentOutput.htlc` carries only `(direction, valueSat)`; it drops the
`cltvExpiry` present in `CommitmentHTLCOutput`, and it has no script bytes or
payment hash.  `Commitment.commitmentOutputs` additionally emits a fixed
group order.  To close `LN-CH-ORDER` in the model itself:

1. Add `cltvExpiry` (and ideally a script identity / payment hash) to the
   commitment output representation, or emit `CommitmentHTLCOutput` directly.
2. Replace the fixed concatenation in `Commitment.commitmentOutputs` by the
   sorted construction, or add `outputs_sorted` as a model obligation.
3. Then derive `commitmentOutputs = (bip69Sort ...).map output` rather than
   only the negative direction proved here.

Until then, `LN-CH-003` (`LnLean.Channel.Commitment.output_ordering`) remains
statement-only, but its content is now mechanized here: the fixed order is
unsound under BOLT 3 whenever `to_local > to_remote`, and a concrete sorted
construction exists and is proved correct.
