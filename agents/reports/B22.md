## 4. What remains open, and the next smallest step

1. **Wave-A `applyGossip` is ungated.**  `GossipState.applyUpdate` /
   `applyGossip` accept any message without checking a signature.  This
   module supplies the gated wrappers `acceptChannelUpdate`,
   `applyGossipChecked`, and `bindChannel`, with the lemmas
   "change ⇒ signature predicate".  These wrappers are *not* aliases of
   `applyGossip`; the model still contains the ungated function.
   *Next smallest step:* add a verifier field to `GossipState` (or change
   `applyGossip` to take a `SigVerifier`) and prove
   `applyGossip = applyGossipChecked` on valid messages.  This changes A6's
   file, so it is an integrator decision, not a B22 edit.
2. **LN-GOSSIP-001 (signing-key attribution).**  `ChannelUpdate.signingKey`
   is unrelated to the stored `ChannelAnnellation.nodeKey1/2`; BOLT 7 takes
   the verification key from the announcement.  *Next smallest step:* add a
   `NodeRegistry` invariant `nodeKey1/2` belong to `node1/2` (or a
   `channelOfScid` lookup) and prove the obligation under it.
3. **LN-GOSSIP-002 (capacity positivity).**  `ChannelAnnellation.capacitySat`
   is an unconstrained `Nat`.  BOLT 7 defines it as the funding output
   value.  *Next smallest step:* add a `fundingValue : OutPoint → Nat`
   hypothesis from the L1 seam and require `capacitySat = fundingValue` at
   bind time.
4. **LN-GOSSIP-003 (signature length).**  `GossipSignature.Valid` exists but
   `SigVerifier` does not require it.  *Next smallest step:* add
   `u.signature.Valid` to the `acceptChannelUpdate` guard
   (`if u.signature.Valid ∧ u.signatureValid verify then ...`) and prove the
   obligation by `cases`.
5. **Global vs per-direction clock.**  Wave A has one global
   `latestUpdateTimestamp`, and `ChannelView` is keyed by `scid` only; the
   `direction` bit (`channel_flags` bit 0) is not decoded.  BOLT 7's rule is
   per `(short_channel_id, node_id)`.  *Next smallest step:* add
   `direction : Bool` to `ChannelView`, split the view list into two
   directional entries, and prove two updates with different direction bits
   do not affect each other.
6. **Announcement → view insertion is not implemented.**  `GossipNetwork`
   records announcements in the store but does not create `ChannelView`s
   from them; `ChannelBinding.edge` only materialises a single edge with
   zero fee defaults.  *Next smallest step:* in `applyMessage`, on a
   4-signature-valid announcement, create the two directional views
   (`node1 → node2` and `node2 → node1`) with `disabled := true` until a
   `channel_update` arrives, then reuse
   `applyMessage_preserves_graphWellFormed`.
7. **Conflicting re-announcement.**  The append-only store accepts a second
   announcement for the same scid with different node ids; only the
   compatible case preserves `uniqueBindings`.  *Next smallest step:* define
   a keyed store (`scid → ChannelBinding`) with a rejection rule and prove
   lookup returns the first binding.
8. **`noncomputable` defs.**  The gated definitions use `Classical.choice`
   because `signatureValid` is `Prop`-valued with no `Decidable` instance.
   This is permitted by the assumptions, but a production extraction would
   want a `Bool`-valued verifier.  *Next smallest step:* add
   `sigOK : Bool` alongside `signatureValid` and prove
   `sigOK = true ↔ signatureValid`.
