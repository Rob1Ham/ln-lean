# G27 — Cross-lane declaration, namespace, and catalog-ID collision audit

**Scope.** Read-only comparison of
`ln-lean/LnLean/Proofs/WaveD/D01..D48.lean`,
`ln-lean-wavee/LnLean/Proofs/WaveE/E01..E48.lean`,
`ln-lean-wavef/LnLean/Proofs/ModelHardening/F01..F16.lean`,
and the base model tree (`LnLean/**` excluding lane directories), with
`LnLean/Proofs/Obligations.lean`, `LnLean/Proofs/Traceability.lean`,
`scripts/collect-obligations.py`, `scripts/check.py`, and `scripts/regen-root.sh`
as the integration context.

**Snapshot.** 2026-10-18, 112 lane modules (48 D + 48 E + 16 F), 69 base
modules, 3,167 fully-qualified declaration sites (3,166 unique names),
112 lane `-- OBLIGATION:` markers, 48 catalog rows. No Lean edits and no
`lake build` were performed; all findings are static and reproducible with the
commands in §1.

---

## 1. Method

1. Parsed every `.lean` in the three lane trees and the base tree with a
   namespace-stack parser that understands nested `namespace`/`end`, dotted
   declaration names (`theorem Invoice.foo`), and all declaration kinds
   (`theorem`, `lemma`, `def`, `abbrev`, `structure`, `inductive`, `class`,
   `instance`, `opaque`), producing fully-qualified names.
2. Diffed the three worktrees' non-lane trees with `diff -rq`; the base model
   is byte-identical in all three (`Only in ... WaveD/WaveE/ModelHardening`
   differences only). Cross-lane imports were enumerated: **0** lane module
   imports another lane module; every import resolves in the 69-module base.
3. Extracted `-- OBLIGATION:` marker IDs, catalog IDs (`LN-XXX-NNN`), and
   `Catalog:`/`English claim (catalog ...)` strings; compared with
   `Obligations.lean` and `Traceability.lean`.
4. Checked the combined-tree mechanics: `scripts/regen-root.sh` does
   `find LnLean -name '*.lean'` and imports **every** module; `scripts/check.py`
   deduplicates only `-- OBLIGATION:` marker IDs, never catalog IDs.

**Duplicate module names: none.** The module paths are disjoint:
`LnLean.Proofs.WaveD.DNN`, `LnLean.Proofs.WaveE.ENN`,
`LnLean.Proofs.ModelHardening.FNN`. The only name that repeats is a
*namespace* and a *declaration*, below. (Do not rename an E winner to a
`DNN.lean` path: the module name would no longer match its
`LnLean.Proofs.WaveE.ENN` namespace and the traceability convention.)

## 2. Collision table — hard Lean declarations

Severity: **Critical** = combined root build fails; **High** = duplicate target
or silent second declaration; **Medium** = wrong namespace/alias, catalog
string unresolved; **Low** = API-surface/future risk.

| File A | File B | Symbol | Kind | Severity |
|---|---|---|---|---|
| `WaveD/D14.lean:404` | `WaveE/E14.lean:579` | `LnLean.Channel.Reserve.bounds` | theorem, **same FQN**, incompatible types (`AdmissibleAdd c p h → …` vs `addHtlc? c h = some c' → Bounds c → Bounds c'`) | **Critical** |

This is the **only** hard declaration collision in the 112 modules. Both files
compile standalone (each declares the name in its own module), but
`regen-root.sh` imports every `.lean`, so a combined root that contains both
fails with `LnLean.Channel.Reserve.bounds` already declared. `check.py` does
**not** catch this: the markers are `LN-WD-D14` and `LN-WE-E14`, which are
unique. `scripts/check.sh` therefore reports green while `lake build` fails.

No other FQN overlaps were found: `D01..D40` contribute 1,092 declarations and
`D41..D48` contribute 277, with **0 overlap**; E is internally clean (1,010 +
257, 0 overlap); F is internally clean (531). The global unique count is
3,166 because of the single `Reserve.bounds` duplicate.

**Namespace-level finding.** `namespace LnLean.Channel.Reserve` is created by
both `D14` and `E14`; only `bounds` actually overlaps (D14's other 30 names —
`ExposurePolicy`, `AdmissibleAdd`, `applyAddHtlc`, … — exist only in D14; E14's
`Bounds`, `ExposureWithinCaps`, … live in `LnLean.Proofs.WaveE.E14`). The
namespace duplication itself is harmless once one file is removed.

Notes:
- `D13` deliberately declares the literal catalog name
  `LnLean.Channel.Fee.feeInsufficient`; `E13` declares a *different* predicate
  `LnLean.Channel.feeInsufficient`. Keeping both is Lean-legal but leaves two
  incompatible `feeInsufficient` notions; unqualified use after
  `open LnLean.Channel` + `open LnLean.Channel.Fee` becomes ambiguous. G07
  recommends D13, which also resolves the catalog string.
- `D26` appends `namespace LnLean.Routing.Route` where `Route` is the base

- `F04` is the only F module that writes into a model namespace. Its three
  names do not collide today, but they are not catalog targets and should not

## 4. Catalog-ID duplication — D41..D48 vs D01..D40

Every one of D41..D48 duplicates a catalog ID already used by an earlier D
module. The affected IDs are **5**, covered by **8** refinement modules:

| Refinement | Catalog ID | Also covered by | Duplicate count |
|---|---|---|---|
| `D41` | `LN-L1-001` | `D01` | 2 D modules |
| `D42` | `LN-L1-004` | `D03`, `D43` | 3 D modules |
| `D43` | `LN-L1-004` | `D03`, `D42` | 3 D modules |
| `D44` | `LN-L1-006` | `D04` | 2 D modules |
| `D45` | `LN-CH-002` | `D11`, `D46` | 3 D modules |
| `D46` | `LN-CH-002` | `D11`, `D45` | 3 D modules |
| `D47` | `LN-CH-003` | `D12`, `D48` | 3 D modules |
| `D48` | `LN-CH-003` | `D12`, `D47` | 3 D modules |

Wave E has the identical structure: `E41`→`E01`, `E42/E43`→`E03`,
`E44`→`E04`, `E45/E46`→`E11`, `E47/E48`→`E12`. Across lanes, all 48 target
slots carry the same catalog ID as their D/E counterpart (1:1 pairing), so a
tree that imports both complete lanes has **48 duplicate catalog IDs**, not
just the 8 refinements.

**Lean consequence: none.** D41..D48 are isolated in
`namespace LnLean.Proofs.WaveD.D41..D48`; the measured overlap with D01..D40 is
zero. Importing D41 plus D01 into one root is Lean-safe.

**Traceability consequence: yes.** `Obligations.lean` has exactly 48 rows;
`Traceability.lean` asserts six IDs per area, one `leanTarget` per ID, and a
transcribed target table of length 48. With the refinement modules present:

- one ID has two or three implementing modules, so `THEOREM-INDEX.md` /
  `TRACEABILITY.md` can no longer show one module per row without a new
  "refines"/"also" column;
- `collect-obligations.py` keys rows on the unique `LN-WD-DNN` /
  `LN-WE-ENN` markers, so it produces extra rows with **different** marker IDs
  and reports `duplicate_ids: []`; the duplication is silent;
- `check.py` likewise checks only marker IDs, so a green gate does not mean the
  catalog is 1:1.

This is the intended design of WAVE-D-PLAN §"D41–D48: decomposition lemmas",
but the catalog layer has not been told that the mapping is now many-to-one.
If the release requires 1:1, D41..D48 must be excluded (targets 41–48 then have
no module) or given distinct synthetic IDs (e.g. `LN-WD-D41` as the catalog key
and `LN-L1-001` as the `refines` field).

(direct catalog IDs first, then claim-level aliases):

## 6. Recommended final-tree layout

**Principle:** one whole-file module per target slot (01..48), never two
modules for the same target, and no lane directory copied wholesale.

```
ln-lean-final/
  LnLean/
    <69 base modules, unchanged>
    Proofs/
      WaveD/DNN.lean            # D winners for target slots 01..48
      WaveE/ENN.lean            # E winners only where G selects E; original names
      ModelHardening/FNN.lean   # F modules only where F is the selected hardening
  audit-lane/                   # NOT under LnLean -> never auto-imported
    WaveD/DNN.lean              # losing D versions, for provenance
    WaveE/ENN.lean              # losing E versions, including E14
    ModelHardening/FNN.lean
  agents/status/selection.tsv   # target | catalog_id | chosen module | G report | reason
```

Rules:

1. **One module per target slot.** For each `NN` in 01..48 choose exactly one
   of `WaveD/DNN.lean`, `WaveE/ENN.lean`, or an F replacement. Do not import
   the loser, even if it builds.
2. **Never import both `D14` and `E14`.** G07 selects D14. This single rule
   removes the only hard Lean collision.
3. **Keep `D41..D48` as a refinement layer.** Their paths and namespaces are
   fine and must not be renamed for Lean reasons. Record them in
   `selection.tsv` with `catalog_id` plus `refines=true`, and extend
   `docs/THEOREM-INDEX.md` / `TRACEABILITY.md` (or `Traceability.lean` with a
   `refines` field) so a catalog ID may have a coarse module and one or two
   refinements. Do not add them as new catalog rows.
4. **F modules are hardening, not automatic catalog closures.** Keep only the
   F module selected for a target (if any); do not count `F05..F09`, `F12`,
   `F16` as closing catalog IDs. `F10/F11/F13/F14/F15` must be dropped when the
   corresponding D/E winner is kept.
5. **Regenerate the root from the selected set only.** `regen-root.sh` uses
   `find LnLean -name '*.lean'`; therefore losers must live outside `LnLean/`
   (the `audit-lane/` directory above). An explicit allowlist in
   `regen-root.sh` or a `selection.tsv` filter is the safer long-term fix.
6. **Do not rename an E winner to a `DNN.lean` filename.** Keep the original
   `WaveE/ENN.lean` path and `LnLean.Proofs.WaveE.ENN` namespace. Mixed
   `WaveD`/`WaveE` directories are fine; module names remain unique.

**Files that must be renamed or excluded if their lane is not selected:**

| File | Action | Reason |
|---|---|---|
| `WaveE/E14.lean` | **Exclude** (recommended) or rename `bounds` → `bounds_of_add` and drop the `LnLean.Channel.Reserve` wrapper | Hard collision with D14 |
| `WaveE/E13.lean` | Exclude if D13 wins; if E13 wins, move its predicates into `LnLean.Channel.Fee` | Catalog target/name mismatch and duplicate `feeInsufficient` concept |
| `WaveE/E18.lean` | Exclude if D18 wins; if E18 wins, move `channel_ready_gate` to `LnLean.Protocol.Handshake` | Wrong namespace for `LN-PR-002` |
| `WaveE/E26.lean`, `E27.lean`, `E29.lean` | Exclude if D wins; if E wins, add the catalog-namespace wrapper | Catalog strings unresolved |
| `ModelHardening/F04.lean` | Exclude from the root, or move `Conserves` / `FunderDebited` / `AnchorDebitRule` into `LnLean.Proofs.ModelHardening.F04` | Only F file that mutates a model namespace |
| `ModelHardening/F09.lean` | Exclude from the root | Contains a real `sorry` |
| `ModelHardening/F10/F11/F13/F14/F15.lean` | Exclude when D/E winner kept | Duplicate catalog IDs/claims |
| `WaveD/D41..D48.lean` | Keep; mark `refines` in metadata; no Lean rename | Duplicate catalog IDs are intentional refinements |
| Losing `D`/`E` modules | Move outside `LnLean/` | `regen-root.sh` auto-imports everything |

No file needs a *module-name* rename; all exclusions above are declaration- or
placement-level.

## 7. Residual risks

- **Static-only evidence.** No kernel build was run (audit rules). Macro- or
  `deriving`-generated names and `where`-clause auxiliaries are not in the
  parser's inventory; they are module-local and unlikely to collide, but the
  `Reserve.bounds` result is the one finding a build would confirm immediately.
- **Model-namespace pollution is permanent.** D13, D14, D18, D26, D27, D29,
  E31, and F04 add declarations under `LnLean.Channel*`, `LnLean.Protocol*`,
  `LnLean.Routing*`, or `LnLean.Payment*`. They are collision-free today; a
  future model edit with the same name becomes a base-vs-proof collision.
- **`LnLean.Channel.Reserve` has no model module.** If a later model adds one,
  D14's 30 declarations may conflict with it. The same applies to
  `LnLean.Channel.Fee` (currently only a module name, not a namespace).
- **The gate is blind to catalog-ID duplication.** `check.py` deduplicates
  markers only; `collect-obligations.py` keys on markers. A green `check.sh`
  does not detect 8 refinements over 5 IDs or 48 D/E duplicate IDs. Add a
  catalog-ID coverage/duplication check before release.
- **`regen-root.sh` auto-imports any stray `.lean`.** A single forgotten loser
  file (especially `E14`) re-introduces the Critical collision; `check.py`
  will still pass, and only `lake build` will fail.
- **Traceability invariant drift.** `Traceability.lean`'s 48-row/6-per-area
  assertions still build (the lists are static), so the many-to-one mapping is
  not machine-checked; docs can silently diverge.
- **Lane drift.** The three base trees are byte-identical at this snapshot, so
  copying an E/F winner into the D-based final tree is dependency-safe today.
  Re-verify with `diff -rq` after any further lane edits.
- **Selection dependence.** The layout assumes G07 picks D14/D13, G23 picks
  E45/D46, and G24 picks D47/E48. If a different mix is chosen, the exclusion
  rules above still apply; only the winner labels change.

## 8. Confidence

- **High** on the collision inventory: 112 modules and 3,167 declaration sites
  were exhaustively parsed; the single hard FQN duplicate is
  `LnLean.Channel.Reserve.bounds`, and the catalog-ID duplication set is fully
  enumerated.
- **High** that excluding one of D14/E14 removes the only build-breaking
  collision.
- **Medium** on the per-target layout, because it depends on G01–G24/G29
  selections that are outside this audit; the file-level exclusion rules are
  independent of which lane wins.
- **High** that D41..D48 are Lean-safe to import alongside D01..D40 and that
  their conflict is purely traceability-level.

## Summary (6 lines)

1. 112 lane modules, 3,167 declaration sites, zero duplicate module names; one hard Lean collision: `LnLean.Channel.Reserve.bounds` in both D14 and E14.
2. D41–D48 are Lean-isolated (0 FQN overlap with D01–D40) but duplicate 5 catalog IDs across 8 modules; E mirrors the same pattern, so importing both lanes duplicates all 48 IDs.
3. Other cross-lane conflicts are namespace/alias-level: D13/E13 `feeInsufficient`, D18/E18 `channel_ready_gate`, D26/E26 `cltv_accumulates`, D27/E27 `announcement_valid`, D29/E29 `payment_secret_match`, D31/E31 `preimage_binding`.
4. F overlaps 16 D/E targets; only `F06/F10/F13/F14/F15` carry literal catalog IDs, the rest use unresolvable aliases (`LN-CH-DUST`, `LN-GOSSIP-SIG`, `LN-SEC-ASYNC`, …); `F04` alone mutates a model namespace.
5. Recommended layout: one winner per target slot 01–48 under original `WaveD`/`WaveE` paths, `D41–D48` marked as refinements, F only where selected, losers moved outside `LnLean/`, and E14 excluded (or `bounds` renamed).
6. Marker IDs are all unique (0 duplicates), but `check.py`/`collect-obligations.py` are blind to catalog-ID duplication and `regen-root.sh` auto-imports every file — add a selection manifest and a catalog-ID uniqueness check before the final gate.
