- Added hypotheses (all documented in the module docstring):
  1. `hbal : b.localBalance.val + b.remoteBalance.val + htlcAmountSum (htlcSet hs) = funding.val`.
     This is the missing model invariant: `Balance` and `Channel.fundingValue`
     are independent fields and nothing in the model links them to the HTLC
     list. Without it the claim is false (checked counterexample).
  2. `hwhole` / `hwholeLocal` / `hwholeRemote` / `hwholeFunding`: all HTLC
     amounts and both balances are whole satoshis, so BOLT 3's floor division
     loses nothing in the equality. The exact msat theorem
     (`waveD_d15_amount_conservation_msat`) needs no such hypothesis.
  3. `hdust : 0 < dustLimit`: keeps an untrimmed HTLC's second-stage fee from
     exceeding its amount (otherwise the saturating subtraction in
     `htlcOutputValue` would make the output zero and the HTLC dust).
  4. `hfund : commitmentDeduction baseFee anchors ≤` the funder's own output:
     the funder must be able to pay the base fee plus anchor outputs out of
     its own balance (BOLT 3 §Fees).
- Statement fidelity: the main equation is exactly `totalOutputValue + feeSat
  = fundingValueSat`. `commitmentOf` assigns `to_local`/`to_remote` from the
  balances with the deduction taken from the funder, emits one output per
  untrimmed offered/received HTLC at `htlcOutputValue` (floored amount minus
  its second-stage fee), adds the two 330-sat anchors when requested, and
  defines the fee as base fee + withheld second-stage fees + floored value of
  the trimmed HTLCs. Thus BOLT 3's "trimmed value is added to the fee" and
  "amount minus second-stage fee" rules are both explicit. The catalog target
  name `LnLean.Channel.HTLC.amount_conservation` is a statement-only catalog
  entry; this module proves the claim without editing the model module.

## Remaining gap / next step

The model has no channel-level conservation invariant (the exact missing
field/invariant is `balance.local + balance.remote + Σ live HTLC amounts =
fundingValue`, stated here as `hbal`). It also has two HTLC record types:
`LnLean.Channel.HTLC` uses `HTLCRecord`, while `LnLean.Channel.Channel.htlcs`
is `List HTLC` from `LnLean.Channel.Types`; there is no conversion or
balance-assignment function to a `Commitment`. Next step: add that invariant
and a model-level `commitmentOf` (or balance projection), unify/reuse the two
HTLC record types, then restate the theorem directly on `Channel` without
`hbal`/`hwhole`. A further refinement is to absorb the msat-to-sat rounding
residue into `feeSat`, which would remove the whole-satoshi hypotheses.
