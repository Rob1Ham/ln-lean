# F07 — Gossip signature-validity admission

## Target
- Marker: `LN-WF-F07`
- Module: `LnLean.Proofs.ModelHardening.F07`
- Parent obligation: `LN-GOSSIP-SIG`

## Result
- Status: counterexample (conditional theorem + mechanized counterexample)
- Build: RC 0
- New definitions:
  - `lengthRespecting (verify : SigVerifier) : Prop` — the admission
    contract: every signature accepted by `verify` is a `Valid` (64-byte)
    `GossipSignature`.
  - `channelAnnouncementSignatures64` — all four announcement signatures are
    `Valid`.
  - `channelUpdateSignature64`, `nodeAnnouncementSignature64` — the single
    signature of each message type is `Valid`.
  - `gossipMessageSignatures64 : GossipMessage → Prop` — combines the three
    per-message predicates.
- Main theorems:
  - `valid_of_lengthRespecting` — unpack the contract at one verification
    site.
  - `announcement_signatures64_of_signaturesValid` — a fully verified
    announcement has four 64-byte signatures under the contract.
  - `accepted_update_signature_64` — an update accepted by
    `acceptChannelUpdate` has a 64-byte signature under the contract.
  - `accepted_announcement_signatures_64` — an announcement accepted by
    `applyGossipChecked` has four 64-byte signatures under the contract.
  - `accepted_node_announcement_signature_64` — likewise for a node
    announcement.
  - `accepted_message_signatures_64_of_lengthRespecting` — every signature of
    any accepted gossip message is 64 bytes under the contract.
  - `bound_announcement_signatures_64` — a successful `bindChannel` produces
    four 64-byte signatures under the contract.
  - `acceptAll_not_lengthRespecting` — the always-accepting verifier does not
    satisfy the contract.
  - `accepted_update_signature_64_counterexample` — the always-accepting
    verifier accepts a `channel_update` with an empty signature, changing the
    store.
  - `accepted_message_signatures_64_counterexample` — the same verifier stores
    a `channel_announcement` all four of whose signatures are empty.
  - `lengthRespecting_not_universal` — the contract is not a theorem about all
    verifiers.
  - `accepted_message_signatures_64` — the faithful unconditional statement,
    retained with one `sorry` and the `LN-WF-F07` marker directly above it.
- Added hypotheses: the conditional theorems take
  `hl : lengthRespecting verify`.  No hypothesis is added to the faithful
  unconditional statement; it remains false in the wave-A model.
- Statement fidelity: the target claim ("accepted update/announcement
  signatures are 64 bytes") is stated unconditionally as
  `accepted_message_signatures_64` and kept with one `sorry`, because the
  wave-A `SigVerifier` is an arbitrary function.  It is proved in the strongest
  true conditional form for the signature-gated admission paths
  (`acceptChannelUpdate` and `applyGossipChecked`), and the failure is
  mechanized by an accepting-empty-signature counterexample.  No claim was
  silently weakened.

## Missing model field / next step

The model lacks a byte-length admission check on the `SigVerifier` result.
`GossipSignature.Valid` exists in `LnLean.Routing.Gossip` but is never required
by `signatureValid`, `acceptChannelUpdate`, `applyGossipChecked`, or
`bindChannel`.  A production fix is one of:

1. add a length check to the admission path, e.g. accept only when
   `sig.Valid ∧ signatureValid verify key digest sig`, or
2. constrain the verifier interface with `lengthRespecting` at construction
   time.

Either change closes the unconditional obligation; until then the gap is
exactly `lengthRespecting`.
