## Method

### Scope and scanner

I scanned, read-only:

- `/home/ubuntu/ln-lean/LnLean/Proofs/WaveD/` — 48 modules;
- `/home/ubuntu/ln-lean-wavee/LnLean/Proofs/WaveE/` — 48 modules;
- `/home/ubuntu/ln-lean-wavef/LnLean/Proofs/ModelHardening/` — 16 modules;
- `/home/ubuntu/ln-lean/LnLean/Proofs/` excluding `WaveD/` — 33 proof modules.

That is **145 Lean files** in the union (the model copies in the three
worktrees are duplicates and were only used to resolve declarations).  I did
not run `lake build`, edit Lean, or run a git write command.

The `sorry` scan reuses the repository’s own `strip_comments` routine from
`scripts/check.py`: it removes line comments, nested block comments, and
string literals while preserving line numbers.  A real `sorry` is a
`\bsorry\b` match in the stripped code.  Raw-only matches are recorded
separately; there are **35** such prose/docstring tokens (14 in D, 11 in E,
10 in F, 0 in the Wave-C base).  I also checked the stripped code for
`axiom`, `admit`, `native_decide`, `unsafe`, and `@[implemented_by]`; there
are no hits in any of the four scanned trees.

Marker collectability uses the exact strict regex from
`scripts/collect-obligations.py`:

```text
--\s*OBLIGATION:\s*(LN-[A-Za-z0-9_-]+)\s+(.*)$
```

It requires a claim after the id.  The lane checkers use the looser
`MARKER = re.compile(r"--\s*OBLIGATION:\s*(LN-\S+)")`, which is why their
reports say “48/48 markers” while the generated index contains only 34 rows.
I also tracked whether a marker is a real line comment or only text inside a
`/-! ... -/` docstring.

Catalog resolution was namespace-aware: I reconstructed fully qualified
declaration names from `namespace`/`end` nesting plus declaration headers,
then matched the exact `leanTarget` strings.  A suffix-only match is recorded
as a different declaration, not as an exact target.

### What counts as false, conditional, or blocked

For each `sorry` I read the theorem statement, its marker, the report’s
`Status:` line, and the in-file counterexample/conditional companion.  A
statement is marked **false** only when the module contains a mechanized
negation or a concrete counterexample (usually a `*_counterexample`,
`*_false`, or `*_not_*` theorem).  “Blocked” means the honest repair requires
a model/admission field that the current model does not have, not a longer
tactic proof.

### Why the lane reports and the generated index disagree

The strict collector needs id **plus claim text**:

```lean
-- OBLIGATION: LN-WD-D01
```

does **not** match, while

```lean
-- OBLIGATION: LN-GOSSIP-001 an accepted channel_update ...
```

does.  Almost all D and F modules, and most E modules, use the bare form.
The generated indexes therefore contain:

- D: **34** markers (32 base + `LN-WD-D36` + `LN-WD-D39`), not 48;
- E: **34** markers (32 base + `LN-WE-E01` + `LN-WE-E40`), not 48;
- F: **32** markers (the unchanged base index), not 16 F rows;
- audit base: **32** markers (the Wave-C index), not the 19-site union.

That is why `D37` is a real `sorry` but is absent from the D index, and why
`E27` is absent from the E index.  The lane checkers report `markers=1`
because they accept `LN-\S+` without claim text.

### Special cases affecting release gates

- **F10** — `sorry -- OBLIGATION: LN-WF-F10` puts the marker after the
  `sorry` on the same line.  `scripts/check.py` requires the marker to begin a
  line (`^\s*--`), so it would report “sorry without any OBLIGATION marker”
  if F10 were imported into the root.  The strict collector also misses it.
- **F15** — `-- OBLIGATION: LN-WF-F15: ...` has a colon immediately after the
  id.  The strict regex requires whitespace there, so the row is not
  collected; `check.py` accepts the id with the colon.
- **F06** — the bare marker is inside the proof body, not above the theorem.
  It is adjacent to the `sorry` but is not a declaration-level marker.
- **D14/E14/E15/E30** — markers exist only in module docstrings.  They are
  documentation text, not declaration markers.
- **D39/E26/F14/GossipProps** — backticked prose such as
  `` `-- OBLIGATION:` `` is correctly ignored; it is not a marker.
- All other real-`sorry` markers are adjacent to their declaration or proof
  body.  Adjacency is not the systemic defect; claim text and placement are.

## Release recommendation

1. **Do not ship a “sorry-free” or “catalog closed” claim.**  The union has 19
   real `sorry`s and the catalog is still 13/48 `proved`; 35 rows remain
   `statementOnly`.
2. **Select the no-`sorry` lane where possible.**  For the four D/E collisions:
   - `LN-CH-101`: keep **E37** (0 `sorry`), not D37.
   - `LN-GOSSIP-002`: keep **E39** (0 `sorry`) and port D39’s store invariant
     as a separate proved lemma; do not import D39’s `sorry`.
   - `LN-RT-006`: keep **D27** (0 `sorry`, exact alias), not E27.
   - `LN-GOSSIP-003`: keep **E40** only as a documented false statement; its
     `sorry` is the one unavoidable D/E addition unless D40 is rebuilt and
     its missing declaration restored.
   That gives **5 base + 1 E40 = 6** real `sorry`s, not 19, for a one-version
   D/E selection.
3. **Treat Wave-F as optional model-hardening, not closure.**  F is not
   imported by its root and adds 10 more false-statement `sorry`s.  If F is
   shipped, the count is **16** and every F site must be allowlisted and
   labelled open; do not count any F module as closing its parent catalog row.
4. **Repair markers before the final gate.**  Either add claim text to the 101
   bare markers and move the four docstring-only markers, or add a deliberate
   compatibility path to the collector.  Do not simplify the regex so that
   bare ids look collected; that would hide the same obligations the index is
   supposed to expose.  In particular, fix F10’s inline marker before adding
   F to the root.
5. **Rebuild D40 if it is selected.**  Its current artifact predates its
   source.  If it is not selected, keep E40 and record the `LN-GOSSIP-003`
   `sorry` explicitly.
6. **Correct status documents.**  Relabel D20 as “local canonical
   construction; `LN-PR-004` not closed,” regenerate
   `agents/status/obligations.json`, and update `docs/WAVE-STATUS.md` with the
   D/E/F selection and the 6-site (or 16-site with F) count.
