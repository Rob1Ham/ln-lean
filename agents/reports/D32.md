- Added hypotheses:
  - `Network.AllConserved`: every channel's every commitment shares the channel funding value and satisfies `CommitmentConserved`. This is the per-channel wave-A theorem lifted over a list.
  - `n.l1.AllConserved`: every L1 spend satisfies `input = output + fee`.
  - `Network.L1SpendsChannels` (only when the L1 spend set is supplied independently): the L1 inputs are exactly the channel funding outputs, with the same outpoints and values. This is the bridge the existing model cannot state because `L1Ledger` has no value field.
  - No bridge hypothesis is needed in `waveD_d32_ofChannels_global_conservation`, where `Network.ofChannels` builds one L1 funding spend per channel; the bridge is proved by `waveD_d32_ofChannels_l1SpendsChannels`.
  - `waveD_d32_l1SpendSet_add_noDoubleSpend` takes the standard freshness premise `x.spentOutpoint ∉ s.spentOutpoints`.
- Statement fidelity: the catalog target `LnLean.Proofs.Conservation.global_conservation` is statement-only and does not exist in the committed `Conservation` module; D32 supplies `waveD_d32_global_conservation` and the unconditional `waveD_d32_ofChannels_global_conservation`. The claim is stated literally as an accounting equation: the sum over all channels of the current commitment's outputs plus fee equals the sum over the L1 spend set of outputs plus fee, and both equal the summed funding values. `history` is used for the "no historical commitment creates value" bound; the aggregate equation counts each channel's single `current` commitment so that one funding output is counted exactly once. The BOLT 3 per-commitment equation is reused from `LnLean.Proofs.Conservation.CommitmentConserved`; the L1 equation is the BOLT 3/5 input/output/fee equation. `decide` (not `native_decide`) checks the concrete instance. No `sorry`, `admit`, `axiom` declaration, `native_decide`, `unsafe`, `@[implemented_by]`, Mathlib, new dependency, or Wave-D import. The unique marker `-- OBLIGATION: LN-WD-D32` is present.

## Remaining gap / next step

The existing `L1Ledger` records only `(txid, index)` outpoints and a height; it has no satoshi value, so the link "these L1 inputs are these channel funding outputs with these values" is a field-level assumption for an externally supplied spend set. `L1Spend` closes that gap inside this module, and `Network.ofChannels` closes it definitionally for the canonical construction. Next step: add a value field (or a `value : OutRef → Nat` UTXO map) to the shared L1 ledger and prove `Network.L1SpendsChannels` from an on-chain UTXO lookup, then extend the spend set to closing, HTLC-second-stage, and penalty spends (each already conserves individually by `L1Spend.Conserves`). Also not modelled: transaction serialisation/scripts, miner fees as a distinct entity, and multiple historical commitments counted simultaneously.
