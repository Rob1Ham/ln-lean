### 6. Statement fidelity and added hypotheses

**Target 41.** Both modules prove the literal byte shape
`OP_0 <0x20> <stored hash>` unconditionally. The SHA-256 identification is
conditional in both on

`p.witnessScriptHash = M.sha256 p.witnessScript.bytes`

because `FundingParams.witnessScriptHash` is an unconstrained `ByteArray`
(`Funding.lean:32-35` explicitly declines to assert SHA-256). D41 additionally
formalizes the negative direction: two well-formed parameter records can share
the same witness script while carrying different hashes, and no single
`sha256 : ByteArray → ByteArray` can satisfy the bridge for every well-formed
record. E41 does not prove either negative result; it states the bridge as an
explicit hypothesis and moves on.

D41’s only material fidelity deficit is that it never proves
`p.witnessScript.bytes` is the BOLT 3 2-of-2 template. E41 does, and also
proves its 71-byte size. Adding E41’s two lemmas to D41 is sufficient.

**Target 42.** Both modules work at `LnLean.Bitcoin.ScriptTemplates.toLocalWitnessScript`
and prove the fixed-width delay push
`0x02 (d % 256) ((d / 256) % 256)` followed by `OP_CSV`/`OP_DROP`. The
witness-script-level result is unconditional for in-range delays; the
P2WSH/output-level result is conditional on `CommitmentParams.HashesMatch`
plus injectivity of the supplied `sha256 : Script → ByteArray`. D42’s fixed
offset theorems add `revocationKey.bytes.size = 33` (the model’s compressed-key
size; `PubKey.Valid` is exactly that). D42’s `contestDelay_delayBytes` also
adds `p.toSelfDelay = c.contestDelay`, because `Commitment` is a value record
with no script builder; E42 avoids that particular linking hypothesis by
stating its `Commitment.contestDelay` theorem directly. Neither is a protocol
hypothesis; both are documented model-layout facts.

Neither module proves the revocation-key half of the catalog claim at fixed
offsets. D42’s prefix decomposition contains `pushData revocationKey.bytes`,
but the dedicated revocation-key result is D43. Keep D43 alongside D42.

Both D42 and E42 use the scaffold’s fixed 16-bit encoding, not minimal
`CScriptNum`. The model’s three-byte push coincides with a minimal `CScriptNum`
encoding only on `128 ≤ d ≤ 32767`; it differs for `d < 128` (extra length
byte / trailing zero) and also for `32768 ≤ d ≤ 65535` (minimal encoding needs
a trailing sign byte, so the model is one byte short). D42’s report’s blanket
“`d ≥ 128` is byte-identical to minimal encoding” claim is therefore too
broad; the Lean code itself does not claim minimal-CScriptNum bit-exactness.
E42’s report is safer on this point. Both prove the `0`/`65536` collision, so
the `d < 2^16` boundary is necessary rather than hidden.

- `LN-L1-004`’s `leanTarget` is `LnLean.Bitcoin.toLocalScript`
  (`Seam.lean:130-134`). That legacy definition is
  `pushData [csv.toUInt8] ++ OP_CSV OP_DROP ++ pushData revocationPubKey ++
  OP_CHECKSIG`, i.e. a simplified single-branch template with a one-byte CSV
  and **no** `OP_IF`/`OP_ELSE` or delayed-payment key. Both candidates instead
  prove about `toLocalWitnessScript` (`ScriptTemplates.lean:128-139`), which is
  the BOLT 3 two-branch template. The catalog alias is stale/inconsistent with
  the model the proofs use; update it (or add an alias theorem) before
  promoting `LN-L1-004`.
- Both catalog rows remain `.statementOnly` in `Obligations.lean:80-85` and
  `:98-103`; `docs/OBLIGATIONS-GENERATED.md:66,69` agrees. This audit does not
  promote them.
- **Marker collectability:** all four markers are exactly the brief-mandated
  `-- OBLIGATION: LN-W?-?NN` form with no trailing claim text. The wave checker
  `scripts/check-wave-d.py` accepts them, but the obligation collector
  `scripts/collect-obligations.py` uses
  `--\s*OBLIGATION:\s*(LN-[A-Za-z0-9_-]+)\s+(.*)$` and therefore **does not
  match any of them**. They are brief-compliant but invisible to the generated
  obligation index. This is shared by most D/E files and is not a D-vs-E
  differentiator; the integrator should append a short English claim to each
  kept marker if the index is expected to list it.
- No duplicate markers, no detached markers, and no marker inside a tactic
  block in these four files. E42’s marker is before the module docstring
  (line 5) rather than inside the namespace; still valid and unique.

## Caveats

1. **No independent build.** All four reports claim `RC 0`; the stored
   `.olean`/`.ilean`/`.trace` triples are newer than their sources and
   internally consistent, but this audit did not run `lake build`. A combined
   tree rebuild is still required, ideally with `#print axioms` on the selected
   headline theorems.
2. **D41’s missing 2-of-2 lemma.** D41 does not prove that
   `p.witnessScript` is literally `OP_2 <key1> <key2> OP_2 OP_CHECKMULTISIG`.
   E41 does (`waveE_e41_witness_script_2of2`, `waveE_e41_witness_script_size`).
   Transplant these into D41 (or add equivalents) before declaring
   `LN-L1-001` fully covered.
3. **D41’s negative witness is model-level, not protocol-valid.** The
   counterexample uses `fundingSatoshis := 0` and 33 zero bytes for both keys;
   `PubKey.Valid` only checks `bytes.size = 33`, so this is accepted by the
   model but is not a real secp256k1 compressed key. The underdetermination
   result is still structurally correct because `witnessScriptHash` is a free
   field and the argument works for any fixed key; the all-zero witness simply
   should not be described as a protocol-valid channel.
4. **D41’s auxiliary global-injectivity theorem is not usable with a 32-byte
   hash.** `waveD_d41_revealed_script_eq_witnessScript` assumes
   `∀ a b : ByteArray, sha256 a = sha256 b → a = b` for an arbitrary
   `sha256 : ByteArray → ByteArray`. That is incompatible with a 32-byte
   codomain (cf. `LnLean.Proofs.Crypto.no_injective_hash_into_32_bytes`), so it
   is a vacuous conditional if instantiated with `PrimitiveModel.sha256`. The
   main SHA-256 shape theorem uses only `hcommit`, not this hypothesis; do not
   cite the reveal theorem as evidence of a model-level hash commitment.
5. **D42’s status label overstates the output-level result.** The report says
   “proved” and describes the output theorem as “unconditionally … under
   `HashesMatch`”, but the P2WSH output commitment is conditional on
   `HashesMatch` plus hash injectivity. The code is honest; the report wording
   should be changed to “proved at witness-script level; conditional at P2WSH
   output level”. E42’s report is more precise on this point.
6. **D42’s truncation counterexample is weaker than E42’s.** D42 proves
   existence with empty `PubKey`s; E42 proves the collision for arbitrary keys.
   The injectivity theorem covers arbitrary keys in both, so this is a witness
   quality difference, not a logical gap. E42’s arbitrary-key theorem is a
   cheap transplant.
7. **Revocation key is outside both target-42 modules.** D42/E42 cover the CSV
   delay; D43/E43 cover the revocation-key branch. The full `LN-L1-004` claim
   needs the D42+D43 pair (or E42+E43), not D42 alone.
8. **Encoding fidelity.** The model’s delay push is fixed-width 16-bit, not
   minimal `CScriptNum`; no script interpreter, signature check, or CSV
   spend-condition semantics is modelled. D42’s report overstates the range on
   which it matches minimal encoding: the match is only `128 ≤ d ≤ 32767`, not
   all `d ≥ 128` (for `d ≥ 32768` minimal encoding needs a sign byte). The Lean
   code does not make that claim, so this is a report-wording defect, not a
   proof defect; E42’s report is more accurate. The 16-bit limitation itself is
   explicitly documented and not a hidden weakening.
9. **Catalog and marker cleanup.** The `LN-L1-004` alias
   `LnLean.Bitcoin.toLocalScript` is a stale simplified template; the catalog
   rows remain `.statementOnly`; and all four markers lack the claim text
   required by `collect-obligations.py`.

## Overall recommendation

1. **Adopt D41 for slot 41 / `LN-L1-001`** and **D42 for slot 42 /
   `LN-L1-004` (delay half)**. Do not take E41 or E42 as whole-file
   replacements.
2. Patch D41 with E41’s `waveE_e41_witness_script_2of2` and
   `waveE_e41_witness_script_size` (or exact equivalents) so the “2-of-2
   funding witness script” clause is explicit. Optionally add E41’s
   `IsP2WSH`/`eq_iff` vocabulary.
3. Optionally patch D42 with E42’s arbitrary-key
   `waveE_e42_delay_encoding_collision` and its intermediate
   `toLocal_hash_commits_delay`; these are the only content advantages E42 has
   over D42.
4. Keep **D43** (revocation-key decomposition) for the second half of
   `LN-L1-004`; D42+D43 is the natural pair. Do not promote `LN-L1-004` from
   D42 alone.
5. Fix integration bookkeeping: add claim text after each kept
   `-- OBLIGATION:` marker if the collector must see it; update the
   `LN-L1-004` `leanTarget`/alias away from the legacy `toLocalScript`; and
   add theorem aliases for the catalog names before changing
   `.statementOnly` to `.proved`.
6. Rebuild exactly the selected modules in the combined tree, record fresh
   `RC 0` and artifact hashes, and run `#print axioms` on the headline
   theorems to confirm no `sorryAx`. Treat the timestamp evidence in this
   report as provisional until that rebuild.
