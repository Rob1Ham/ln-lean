## What is proved

The main theorem `feeWeightDust_bounds` composes all five required bounds from
one bundled hypothesis structure:

* every emitted commitment output has a non-negative value;
* every emitted output value is at most `c.fundingValueSat`;
* `c.totalOutputValue ≤ c.fundingValueSat`;
* `(commitmentFee r c).val ≤ c.fundingValueSat`;
* `c.weight.val = commitmentBaseWeight c.anchorOutputs + 172 * htlcOutputCount c.commitmentOutputs`;
* every carried HTLC satisfies the dust precondition.

The preconditions are named exactly, not hidden:

```lean
structure CommitmentBudget (r : FeeRate) (dustLimitSat : Nat) (c : Commitment) : Prop where
  feeCovers    : FeeCoversWeight r c
  dustTrimmed  : ∀ h ∈ c.htlcs, ¬ isDust dustLimitSat h.amountSat
  valueBounded : c.totalOutputValue + c.feeSat ≤ c.fundingValueSat

def FeeCoversWeight (r : FeeRate) (c : Commitment) : Prop :=
  (feeForWeight r c.weight).val ≤ c.feeSat   -- = feerate * weight / 1000 (floored)
```

`FeeCoversWeight` is exactly the BOLT 3 floored requirement at the
commitment's own weight; `feeCoversWeight_iff_commitmentFee` identifies it with
`(commitmentFee r c).val ≤ c.feeSat`, and `feeCoversWeight_mul_le` /
`feeCoversWeight_of_mul_le` give the exact product characterisation
`x / 1000 ≤ f ↔ x ≤ f * 1000 + 999`.  `dustLimitSat` is the threshold at which
an HTLC is trimmed: `dust_limit_satoshis` when `CommitmentHTLCOutput.amountSat`
is already net of the second-stage fee, or `dust_limit_satoshis + htlc_tx_fee`
under the gross-amount convention of `Commitment.addHtlc`.

## Remaining obligations

None in this module.  The two hypotheses that are *not* derivable from the
wave-A/C model alone are explicit fields, not obligations:

1. `CommitmentBudget.valueBounded : c.totalOutputValue + c.feeSat ≤
   c.fundingValueSat`.  For an arbitrary `Commitment` record this cannot be
   derived: `toRemoteSat` is an unconstrained field.  It is discharged for the
   BOLT 3 construction by `CommitmentBudget.of_buildCommitment` and
   `buildCommitment_trimmed_budget`, whose only arithmetic input is the
   residual hypothesis `fee + toLocal + htlcOutputsValue htlcs +
   commitmentAnchorTotal anchors ≤ funding`.
2. `CommitmentBudget.dustTrimmed : ∀ h ∈ c.htlcs, ¬ isDust dustLimitSat
   h.amountSat`.  For an arbitrary record the HTLC list is unconstrained; the
   module supplies `trimDust` and `Commitment.trimmed_dust_free` so the
   construction path establishes it, and `Commitment.trimmed` preserves a
   budget.

The separate wave-A model gap `LN-COMMIT-005` (anchors not subtracted from the
funder in `commitmentPairOfBalances`) does not affect this module: the
construction theorems here use `buildCommitment`, which does subtract
`commitmentAnchorTotal`, and they state that subtraction explicitly in the
residual hypothesis.
