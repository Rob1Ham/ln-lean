# F01 — Funding hash bridge

## Target
- Marker: `LN-WF-F01`
- Module: `LnLean.Proofs.ModelHardening.F01`
- Parent obligation: `LN-FUND-HASH`

## Result
- Status: conditional (P2WSH binding proved under explicit hypotheses) plus a
  mechanized counterexample to the unconditional implication
- Build: RC 0
- New definitions:
  - `FundingHashLinked (sha256 : ByteArray → ByteArray) (p : FundingParams) :=
    p.witnessScriptHash = sha256 p.witnessScript.bytes`
  - `FundingScriptCollisionResistant (sha256) :=
    ∀ a b, a.size = 71 → b.size = 71 → sha256 a = sha256 b → a = b`
    (idealized collision resistance restricted to the 71-byte BOLT 3 funding
    witness scripts; consistent with a real 32-byte hash)
  - counterexample witnesses: `waveF_f01_cexKeyBytes`,
    `waveF_f01_cexZero32`, `waveF_f01_cexOne32`,
    `waveF_f01_cexParams`
- Main theorems:
  - `waveF_f01_witnessScriptHash_size_of_hashLinked`: the link plus
    `∀ b, (sha256 b).size = 32` recovers the hash-length conjunct of
    `WellFormed`.
  - `waveF_f01_hashLinked_program`: the funding `scriptPubKey` is
    `p2wsh (sha256 p.witnessScript.bytes)`.
  - `waveF_f01_hashLinked_scriptPubKey_bytes`: its bytes are
    `OP_0 <0x20> SHA256(witnessScript.bytes)` (BIP 141).
  - `waveF_f01_p2wsh_injective`: `p2wsh` is injective on programs.
  - `waveF_f01_p2wsh_binds_witnessScript`: under `FundingHashLinked`,
    `p.WellFormed`, collision resistance on 71-byte scripts, and
    `revealed.size = 71`, any revealed script with
    `p.witnessScriptHash = sha256 revealed` equals `p.witnessScript.bytes`.
  - `waveF_f01_p2wsh_binds_witnessScript_of_injective`: the same conclusion
    under full injectivity of `sha256`, with no size side conditions.
  - `waveF_f01_confirmed_script_commits_to_hash`: every `FundingConfirmed`
    output's script is the P2WSH wrapper over
    `SHA256(witnessScript.bytes)`.
  - `waveF_f01_confirmed_binds_witnessScript`: output-level version of the
    binding for the confirmed output at the funding index.
  - `waveF_f01_hashLinked_commits_to_2of2`: the linked hash is the hash of
    `OP_2 <key1> <key2> OP_2 OP_CHECKMULTISIG` in one of the two BOLT 3 key
    orders.
  - `waveF_f01_hashLinked_satisfiable`: for each `p` some `sha256` links it,
    so the invariant is not contradictory.
  - `waveF_f01_cexParams_wellFormed`: both counterexample records satisfy
    `WellFormed`.
  - `waveF_f01_no_sha256_links_both_cex`: no `sha256` can link both records.
  - `waveF_f01_wellFormed_not_implies_hashLinked`:
    `¬ ∀ sha256 p, p.WellFormed → FundingHashLinked sha256 p`.
- Added hypotheses:
  - `FundingHashLinked` is the missing invariant; it is not derivable from the
    wave-A model.
  - The binding adds `FundingScriptCollisionResistant` (or full injectivity in
    the corollary).  This is the standard idealization of SHA-256 collision
    resistance; it is needed because the wave-A hash is opaque.
  - `p.WellFormed` and `revealed.size = 71` appear only in the
    collision-resistance-restricted version, to match the limited domain of
    `FundingScriptCollisionResistant`.
- Statement fidelity:
  - Nothing is stated unconditionally: `FundingParams.WellFormed` checks only
    `witnessScriptHash.size = 32`, never its value.
  - The counterexample is faithful: two records with identical funding keys
    (hence identical `witnessScript`, proved by `rfl`) carry 32 zero bytes and
    32 one bytes as the stored hash; both are `WellFormed` under the wave-A
    length-only key/hash checks.  No single `sha256` can satisfy the link for
    both, so the model underdetermines the hash rather than implying the link.
  - The counterexample keys are 33 zero bytes: structurally valid for
    `FundingParams.WellFormed` (which is length-only), not claimed to be valid
    secp256k1 points.
  - Not claimed: a concrete SHA-256 computation, L1 consensus/confirmation,
    script execution, or that any concrete channel is actually hash-linked.
  - No `sorry`, `axiom`, `admit`, `native_decide`, `unsafe`, or Mathlib in this
    module.  `#print axioms` reports only `propext` / `Quot.sound`.

## Missing model field / next step

`LnLean.Bitcoin.Funding.FundingParams` has no equation tying
`witnessScriptHash` to `witnessScript`.  The next model change should add
`FundingHashLinked` (parameterized by `LnLean.Crypto.PrimitiveModel.sha256`)
as a field of the funding state or as a `WellFormed` conjunct, and carry it
through `FundingConfirmed` / channel establishment.  Downstream proofs could
then derive the binding without taking the equation as a hypothesis.  The
crypto workstream should also supply collision resistance on the actual
funding-script domain; `FundingScriptCollisionResistant` names the precise
obligation.  `LnLean.Bitcoin.ScriptTemplates.CommitmentParams.HashesMatch`
has the same missing-bridge shape for commitment outputs.
