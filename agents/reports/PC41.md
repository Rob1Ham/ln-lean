### Hypotheses, not axioms

`ErrorInterface` has four fields:

* `mac : Bytes → Bytes → Bytes`
* `verify : Bytes → Bytes → Bytes → Bool`
* `mac_length : ∀ key msg, (mac key msg).length = 32` (wire fact)
* `verify_mac : ∀ key msg, verify key msg (mac key msg) = true` (verifier
  completeness)

The cryptographic security assumption is the separate `Prop`-valued
hypothesis

```lean
def HmacBinding (I : ErrorInterface) : Prop :=
  ∀ key msg tag, I.verify key msg tag = true → tag = I.mac key msg
```

It is the C8 (HMAC PRF/binding) bridge corresponding to
`LnLean.Routing.OnionInterface.hmacBinding`; it is never introduced as an
axiom and never proved.  `parseError_sealError` and
`parseError_reject_bad_hmac` take it explicitly.  Forgery resistance,
PRF security, and collision resistance are not claimed.

## Model correspondence and remaining obligations

`OnionError.packetSize`: `failure_len(2) || padded failuremsg(256) ||
hmac(32)` = 290 bytes.  Exact BOLT 4 uses `hmac || failure_len || failuremsg
|| pad_len || pad` and is 292 bytes in the same padded case (already stated
as `OnionProps.bolt4FailurePacketSize_eq`).  The following are **not**
modelled; no `sorry` remains in the module, so these are scope obligations
rather than incomplete proofs:
