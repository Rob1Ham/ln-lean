### Corrections made to the mission wording

1. **"funding output value plus push amount equals the channel capacity"** is
   dimensionally wrong as literally stated (satoshis + millisatoshis) and
   contradicts BOLT 2, where `push_msat` is *part of* the channel value
   (`02-peer-protocol.md:727-729`).  Corrected to
   `capacity = (capacity - push_msat) + push_msat` under the wave-A
   well-formedness hypothesis `push_msat <= funding_satoshis * 1000`
   (`capacity_eq_funder_plus_push`, proved), plus the two independence laws
   showing that changing `push_msat` does not change capacity or the funding
   output value.
2. **Final channel id.** BOLT 2 defines it as the funding txid with a
   big-endian XOR of the output index (`02-peer-protocol.md:59-64`).  The
   wave-A model (`FinalChannelId.MatchesOutpoint`) compares only the txid, so
   this module proves the txid-derived and transition-stability laws, not the
   XOR.  This is recorded as an open item in §4.
3. **"a funding output cannot be spent by anyone other than the 2-of-2 path"**
   is *not* proved as a consensus theorem.  The file proves only the
   conditional predicate `fundingSpend_conditional_2of2_only` over an abstract
   L1 verifier, with `FundingSpendBridge` as an explicit hypothesis.  Third
   party exclusion additionally needs ECDSA EUF-CMA (C3) and key ownership,
   neither of which is in the tree.

## 4. What remains open and next smallest steps

1. **`LN-FUND-001` — concrete P2WSH/MULTISIG bridge.**
   `witnessScript_parse_eq_none` is stated but not proved.  It is true of the
   pinned L1 model: `decodeOp` has no branch for `0xae`, so parsing the
   2-of-2 script fails.  Next smallest step: unfold
   `Bitcoin.Data.Script.parse`/`decodeOp` with fuel `p.witnessScript.bytes.size`
   and show the byte at the trailing `OP_CHECKMULTISIG` position decodes to
   `none` (a pure `simp`/`decide`-style byte computation once the key bytes are
   abstracted as a 33-byte push).  The larger fix — adding `checkMultiSig` to
   `ScriptInstr` and `0xae` to `decodeOp` — belongs in `vendor/btc-lean-core`
   and is out of scope here (read-only L1 snapshot).
2. **Interpreter bridge is an explicit hypothesis, not a theorem.**
   `FundingSpendBridge` is never instantiated.  Next smallest step: define a
   concrete `verify : Script → WitnessStack → Tx → Bool` from the L1 model
   after item 1, prove the `→` direction from P2WSH witness-program matching
   plus `OP_CHECKMULTISIG` semantics, and the `←` direction by construction.
3. **`LN-FUND-002` — capacity bound.**  Next smallest step: rewrite
   `hmax : fundingSatoshis ≤ MAX_MONEY` with
   `simp only [channelCapacityMsat, Msat.MAX, Msat.SAT_PER_BTC,
   Msat.MSAT_PER_SAT, Bitcoin.Data.MAX_MONEY, Bitcoin.Data.COIN] at hmax ⊢`
   (note: the obligation needs rewriting in the *hypothesis*, which is why a
   bare `unfold` does not close it), then finish with `omega` (the remaining
   arithmetic is linear: `fundingSatoshis * 1000`).
4. **BOLT 2 channel-id index mixing.**  `FinalChannelId.fromFundingOutpoint`
   ignores the output index, while BOLT 2 XORs the index into the last two
   bytes big-endian.  Next smallest step: add a `ChannelId.xorIndex` function
   and a `MatchesOutpointIndex` predicate to wave-A `Funding.lean` (not owned
   here), then restate `confirm_finalChannelId_txid` for that predicate.
5. **SHA-256 is a parameter.**  The wave-A `FundingParams.witnessScriptHash`
   is never tied to `SHA256(witnessScript)` in the model.
   `p2wsh_program_binds_witnessScript` is therefore conditional on
   `hcommit` and on collision resistance `hcr` (assumption C1); no
   `sha256_collisionResistant` instance exists yet.
6. **No txid computation.**  `fundingOutpoint` takes the txid as a
   `ByteArray`; the model does not compute `SHA256d(serTx)`.
   `fundingOutpoint_pair`/`confirm_finalChannelId_txid` are therefore
   definitional, not claims about real transaction ids.
7. **Reserve accounting.**  LDK checks `push_msat` against channel value
   *minus* `channel_reserve_satoshis` (`channel.rs:4217-4220`), while
   `FundingParams.WellFormed` only checks against the full value.  This report
   does not strengthen the wave-A predicate; doing so would change another
   agent's file.
