- Build: RC 0

- Theorems/definitions:
  - `announcedKeyAdmitted s u` — reusable BOLT 7 admission predicate: a stored
    `channel_announcement` for `u.shortChannelId` names `u.signingKey` as
    `nodeKey1` or `nodeKey2`.  Proven definitionally equal (via `Iff.rfl`) to
    `GossipProps.updateKeyAnnounced`.
  - `channelUpdateAdmission verify s u` — signature validity plus
    `announcedKeyAdmitted`.
  - `applyUpdateIfAdmitted Admission s u` — generic admission-gated store step,
    with `..._eq_of_admission`, `..._eq_of_not_admission`, and
    `..._change_requires_admission`.
  - `acceptChannelUpdateAnnounced verify s u` — BOLT 7 instantiation of the
    gate.
  - `waveD_d38_accepted_update_signing_key_announced` — main conditional
    theorem: any change made by the gated step yields
    `∃ a ∈ s.announcements, a.shortChannelId = u.shortChannelId ∧
    (a.nodeKey1 = u.signingKey ∨ a.nodeKey2 = u.signingKey)`.
  - `waveD_d38_accepted_update_signature_valid`,
    `waveD_d38_accepted_update_newer`, and
    `waveD_d38_accepted_update_sound` — the accepted update also has a
    verifying signature and a strictly newer timestamp.
  - `waveD_d38_acceptChannelUpdateAnnounced_eq_acceptChannelUpdate` — on
    announced-key updates the gate coincides with wave-A
    `acceptChannelUpdate`; `..._rejects_unannounced` and
    `..._rejects_invalid` give the two rejection cases.
  - `waveD_d38_acceptChannelUpdateAnnounced_idempotent`,
    `..._stale`, and `announcedKeyAdmitted_applyUpdate` /
    `announcedKeyAdmitted_acceptChannelUpdateAnnounced` — stability lemmas.
  - `waveD_d38_unannounced_key_counterexample` — concrete verifier/store/update
    witnesses showing wave-A acceptance stores an update whose key is not
    announced (the store does contain an announcement for the same channel).
  - `waveD_d38_unconditional_attribution_false` — the corresponding universal
    statement is false in the wave-A model.
  - `waveD_d38_announced_key_admission_accepts` /
    `..._attributed` — positive witnesses: an announced-key update really is
    accepted and attributed, so the gate is not vacuous.
- Added hypotheses:
  - None to the counterexample or the negative theorem.
  - The conditional theorem is stated for `acceptChannelUpdateAnnounced`, whose
    gate is the missing admission check itself; it does not assume
    unforgeability or any new cryptographic fact.  The verifier remains the
    abstract `SigVerifier` parameter.
- Statement fidelity:
  - The literal unconditional `LN-GOSSIP-001` claim
    (`acceptChannelUpdate verify s u ≠ s → announcedKeyAdmitted s u`) is false:
    `ChannelUpdate.signingKey` is an unconstrained field and the wave-A store
    never looks it up in the announcement list.  The counterexample is
    mechanised, not merely described.
  - The conditional theorem is the faithful replacement: it proves exactly the
    attribution property under the BOLT 7 admission rule, at store level.
  - `announcedKeyAdmitted` is equivalent to the already-isolated
    `updateKeyAnnounced`, so no competing semantics is introduced.

## Remaining gap / next step

The missing model field/bridge is an admission check tying
`ChannelUpdate.signingKey` to the `channel_announcement` selected by
`u.shortChannelId` (BOLT 7: the verifying `node_id` comes from the matching
announcement).  Wave-A `applyGossip` / `acceptChannelUpdate` still use the
independent `signingKey` field; this module adds the reusable gate but does not
rewrite the shared model (out of scope for a Wave-D module).  Closing
`LN-GOSSIP-001` in the model requires either:

1. routing `applyGossip` through `acceptChannelUpdateAnnounced` (or an
   equivalent admission predicate), or
2. removing `signingKey` from `ChannelUpdate` and looking the key up in a
   `(short_channel_id, direction)`-keyed announcement store.

No `sorry`, `axiom`, `admit`, `native_decide`, `unsafe`, or
`@[implemented_by]` is used in this module.  No new dependency and no import of
another `LnLean.Proofs.WaveD.*` module.
