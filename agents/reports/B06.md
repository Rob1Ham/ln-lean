## 4. What remains open

1. **LN-ECDSA-001 / LN-ECDSA-002** (the only `sorry`s). `derFullOK` is a
   written-out DER shape (`30 len 02 rLen r 02 sLen s sighash`), but its two
   refinement lemmas are deferred. Next smallest step for LN-ECDSA-001:
   `unfold derFullOK at h`, peel the right-nested `Bool.and_eq_true` chain to
   obtain the three header equalities, then close with
   `wireSigOK_iff.mpr (Or.inr (by unfold derEnvelope; simp_all))` using
   `hlo`/`hhi`. For LN-ECDSA-002: extract `rLen := (byteAt b 3).get` and
   `sLen := (byteAt b (5 + rLen)).get` and `omega` the `decide` sum.
2. **Wave-A `verifyFunding` does not inspect bytes.** `ecdsaVerify` is
   opaque, so `Crypto.Sig.verifyFunding` passes the raw `EcdsaSig` straight
   through. This module therefore *adds* `verifyFundingChecked` /
   `verifyCommitmentChecked` / `verifyCloseChecked`, which gate on
   `wireSigOK`. The integrator must decide whether the seam should adopt the
   checked predicates; the bare predicates cannot reject a malformed length.
3. **Tags are model stand-ins.** BOLT 3 / LDK separate domains through
   distinct BIP 143 sighash digests (`chan_utils.rs:1450-1452`,
   `:1591-1593`), not through literal tags. Proving that funding,
   commitment, and close sighashes differ needs transaction types and a
   `sighash` function, which are outside this module's wave-A import set
   (`Bitcoin.Seam`, `Channel.Commitment`). The current tags are documented in
   the docstring as stand-ins; no theorem claims they equal any wire bytes.
4. **Key binding is not in C3.** `EufCma` binds a signature to a message under
   a fixed key. `eufCma_not_keyBinding` proves formally that
   `EufCma ≠ KeyBinding` for the model's `PubKey`, so
   `verifyFunding_key_change_bound` correctly takes `KeyBinding` as an extra
   hypothesis. Making key binding provable would require a stronger
   assumption field in `Crypto.Model` (integrator-owned) or a real
   secp256k1 model.
5. **Compact branch is length-only.** Any 64-byte string passes
   (`wireSigOK_accepts_any_64`); `1 ≤ r,s < n`, low-S, and RFC6979 are
   delegated to `ecdsaVerify`. No range checking is claimed.
6. **Not modelled:** compact↔DER conversion, DER canonical integer encodings,
   sighash-byte values, `tx_signatures` (BOLT 2 channel-establishment v2),
   ECDSA unforgeability itself. No unforgeability claim is made anywhere; all
   binding theorems take `AssumesEufCma` or `EufCma M.ecdsaVerify` explicitly.
