# G03 — Audit targets D05/E05 and D06/E06

## Verdict
- Recommendation: **Target 5 (`LN-CR-001`): D — keep `LnLean/Proofs/WaveD/D05.lean`.**  **Target 6 (`LN-CR-002`): E — keep `LnLean/Proofs/WaveE/E06.lean`.**  Do not ship `E05` or `D06` as the target versions.  If the integration insists on a positive universal “every valid payment hash is a SHA-256 output” theorem, a **replacement** is required: D05 plus E05’s counting core (`waveE_e05_hash_surjective_on_32`) as a clearly labelled model-artifact lemma.
- Confidence: **medium**
- Blocking issues:
  1. **Model-level vacuity.** `PrimitiveModel` is uninhabited. `LnLean/Crypto/Model.lean:101-102` contains both `sha256_collisionResistant` and `sha256_preimageResistant`, while `sha256_size` forces every image to 32 bytes. `LnLean/Proofs/Crypto/Sha256Props.lean:476` proves `no_injective_hash_into_32_bytes : ¬ PreimageResistant H` from `∀ b, (H b).size = 32`, and `Sha256Props.lean:502` packages the contradiction as `preimageResistant_vacuous (M : PrimitiveModel) : ¬ PreimageResistant M.sha256`. Combined with the field `M.sha256_preimageResistant`, this yields `False` for every `M`. Hence every theorem in all four files that begins `(M : PrimitiveModel)` is vacuously true. This affects both targets and must be repaired before any “proved” status is credible.
  2. **Target 5:** E05’s headline universal statement is a model artifact: finite injectivity on the 32-byte digest space is turned into surjectivity (`waveE_e05_hash_surjective_on_32`, `waveE_e05_payment_hash_is_sha256_output`). Real collision resistance does not imply that every 32-byte value is a SHA-256 output. D05’s counterexample is valid in the model, but it exploits a real model gap: `LnLean/Protocol/Messages.lean:411-440` (`semanticOk`, `idsValid`, `sigsValid`, `wellFormed`) never checks `paymentHash.Valid` or the SHA-256 range, and `msgLength` is `84 + onionRoutingPacket.size` regardless of the actual payment-hash width.
  3. **Target 6:** `PrimitiveModel` has no ECDSA key-binding field and no signing-correctness law. E06’s positive direction needs `SigningCompleteness`; key attribution needs `KeyBinding`. D06’s `waveD_d06_commitment_signature_verifies` is only the definitional `checkCommitmentSignature = verifyCommitment` identity, not a proof that an honestly produced counterparty signature verifies. Neither file makes `LN-CR-002` unconditional.
  4. **Report labels need correction.** E05’s report says `Status: proved` without acknowledging that its `∀ M` corollaries are vacuous under the current `PrimitiveModel`. D06’s report says the literal verification claim is proved, but `waveD_d06_commitment_signature_verifies` assumes the check already returned `true` and is definitionally the same proposition. E06’s report is materially more accurate about the missing signing law.

For **target 5**, D05 and E05 overlap on the true, unconditional provenance fact (`paymentHashOf pre` is literally `sha256 pre.bytes`) and on C1-based uniqueness. The difference is what each does with the universal reading of the catalog sentence.

E05 proves the universal reading by turning 32-byte collision resistance into a bijection of the 32-byte digest space. That proof is technically correct for the abstract hypotheses, and `waveE_e05_hash_surjective_on_32` is a genuine counting theorem. But it is exactly the kind of result the brief asks an auditor to distrust: it is a model artifact, not a cryptographic consequence of C1, and it does not engage with the model’s actual wire-level gap. E05’s own header admits that “real-world collision resistance does not imply surjectivity.” Presenting `waveE_e05_payment_hash_is_sha256_output` as the proof of `LN-CR-001` would mark the target proved on the strength of an idealisation that the catalog does not claim.

D05 takes the adversarial route. It proves the structural provenance theorem, proves the C1 binding theorem, and then proves that the literal universal claim is false in the model because `PaymentHash` is an unconstrained `ByteArray` wrapper and `wellFormed` never checks the payment-hash width or range (`waveD_d05_wellFormed_message_with_non_output_hash`, `waveD_d05_not_all_paymentHashes_are_sha256_outputs`). Its counterexample is concrete and mechanised: `badPaymentHash := ⟨zeroBytes 33⟩`, `badUpdateAddHtlc`, and `waveD_d05_badUpdateAddHtlc_wellFormed`. The 33-byte value cannot be a SHA-256 image because `sha256_size` forces every image to 32 bytes. This is the strongest evidence in either file that the model needs an ingress invariant, and it is precisely the kind of model gap that would otherwise be silently lost if E05 were selected. D05’s report also explicitly says the catalog Lean target is stale and that the global `PreimageResistant` field is inconsistent. D05 is therefore the better whole-file version for the *true* BOLT 2 claim and the safer release choice. It is not a complete universal proof, but the universal claim is false in the model as written; D05 says so instead of repairing it by assumption.

For **target 6**, both files prove the same definitional seam and the same C3 message-binding theorem. The decision turns on integration and honesty about the two missing properties.

D06 is an abstract envelope (`CommitmentSignature`, `ChannelFundingKeys`) that is not tied to `LnLean.Channel.Channel` or `Protocol.CommitmentSigned`. Its positive “verification” theorem, `waveD_d06_commitment_signature_verifies`, assumes `checkCommitmentSignature ... = true` and concludes `verifyCommitment ... = true`; that is definitionally the same proposition. It does not prove that a signature produced by the counterparty is accepted. Its domain-separation results are already present in `Crypto.Sig` and `Crypto.EcdsaProps`. Its `KeyBound` counterexample is useful, but it duplicates the existing generic `KeyBinding` counterexample.

E06 uses the actual channel record and the actual `commitment_signed` message, proves the seam, proves C3 binding, adds anti-replay across commitment numbers, and—most importantly—states the honest-signature completeness direction with the exact missing hypothesis (`SigningCompleteness`). It also states key attribution with the exact missing hypothesis (`KeyBinding`) and proves C3 does not imply it. Its added hypotheses are stronger than D06’s in the sense that it attempts more, but they are explicit and necessary; D06’s apparent avoidance of them comes at the cost of not proving the positive direction at all. E06’s report is also more accurate about the gap. E06 is therefore the better whole-file version for `LN-CR-002`.

The recommendation is not based on declaration counts. D05 has more declarations than E05, but the decisive facts are D05’s counterexample and E05’s artifact; E06 and D06 have similar counts, but E06’s declarations are tied to the real channel/message types and state the missing signing law.
