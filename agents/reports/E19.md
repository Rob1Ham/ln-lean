  - `waveE_e19_funding_signed_valid_binds_tx` — under `EufCma M.ecdsaVerify`, a fixed key/signature validates at most one funding-transaction byte string.
  - `waveE_e19_funding_signed_valid_binds_txid` — same result transported through an explicit `txidOf` map.
  - `waveE_e19_funding_signed_valid_not_commitment`, `_not_close` — under `AssumesEufCma M`, a funding signature cannot be reused in the commitment or mutual-close domain (tag prefix-freeness).
  - `waveE_e19_funding_signed_wellFormed_iff` — `wellFormed` for `funding_signed` is exactly `channelId.Valid ∧ signature.size ≤ 73`; no cryptographic check.

  - `fundingSignedAlwaysValid`, `waveE_e19_unconditional_form_false` — the literal “every well-formed message is valid for every model/key/tx” is false.
  - `waveE_e19_funding_created_valid_txid_agreement` — conditional protocol-level form: if `m.channelId = finalChannelId fc.outpoint`, `fc.fundingTxid = txidOf fundingTx`, and both signatures validate, then `m.channelId.bytes = txidOf tx'`.
- Added hypotheses:
  - `EufCma M.ecdsaVerify` for transaction-message binding; `AssumesEufCma M` for cross-domain separation. Both are fields of `PrimitiveModel`, not new axioms.
  - Validity is parametrized by the funding key and the funding-transaction bytes, because `FundingSigned` records neither.
  - The txid-form theorem takes an explicit `txidOf : ByteArray → ByteArray`; the model has no txid bridge.
- Statement fidelity:
  The target “funding_signed carries a valid signature over the funding transaction” cannot be a closed theorem over `FundingSigned` alone: the message has only `channelId` and `signature`, and `handshakeStep` never sees a message. The faithful form therefore externalizes the signed transaction and key in `fundingSignedValid`. The positive results state exactly what follows from the model’s ECDSA field; the counterexample shows the missing invariant is real, not a proof gap.

## Remaining gap / next step

The model needs one of:
1. a `FundingSigned` field binding the message to the funding transaction (or its signed digest), and
2. a signing/verification discipline in the handshake transition or channel state, so that a reachable `funding_signed` carries evidence that its signature was checked.

`wellFormed` currently checks only `channelId.Valid` and `signature.bytes.size ≤ 73`. Adding those fields/invariants (and a BOLT 3 sighash/txid bridge) would make the unconditional claim expressible; the ECDSA message-binding theorem in this module would then give transaction and txid uniqueness directly.
