## Result

`LN-L1-006` now has a faithful theorem-shaped target.  The new module
`LnLean/Proofs/Bitcoin/WeightTargets.lean` ties

* the seam constant `LnLean.Bitcoin.commitmentBaseWeight` (`⟨724⟩`),
* the channel constants `LnLean.Channel.commitmentBaseWeight false = 724` and
  `… true = 1124`, and
* the channel formulas `724 + 172 * k` / `1124 + 172 * k`

to a commitment-transaction weight model built from BOLT 3 Appendix A's byte
accounting, and, for the non-anchor variant, to the actual
`Bitcoin.Data.serTx` size of a transaction assembled from the model's own
P2WSH/P2WPKH script builders.

The exact findings are:

| Variant | Model non-witness bytes before HTLCs | Weight | Per untrimmed HTLC |
|---|---:|---:|---:|
| no anchors | `125` | `4 * 125 + 224 = 724` | `+43` bytes = `+172` WU |
| anchors | `223` serialized (`225` in BOLT Appendix A) | `4 * 223 + 224 = 1116` (`1124` fee basis) | `+43` bytes = `+172` WU |

The `1124` constant is **not** the literal weight of the model's four-output
anchor serialization.  BOLT 3 Appendix A's anchor table lists
`count_tx_out: 3 byte`; a four-output transaction has a one-byte CompactSize
output count.  The model proves the exact gap:
`1116 + 8 = 1124`, i.e. `4 * 223 + 224 + 2 * 4 = 4 * 225 + 224`.
No padding bytes are invented.  This is documented in the module docstring and
in the theorem `weightTargets_serializedWeight_anchor_gap`.

The non-anchor result is exact at the serializer level:
`weightTargets_commitmentTx_weight_noAnchors` proves, for any list of untrimmed
HTLC output scripts, that the model transaction's base serialization times four
plus the assumed `224` witness weight is exactly
`commitmentBaseWeight.val + 172 * k`.

## Model / arithmetic bridge

### Non-anchor `724`

BOLT 3 Appendix A (`refs/bolts/03-transactions.md:973-1086`, pinned
`1aadb719b4007c4cea0ba6e36b08c4fb53788dee`) gives `125` non-witness bytes:

```text
4   version
1   input count
41  funding input
1   output count
43  to_local P2WSH      (8 value + 1 length + 34 script)
31  to_remote P2WPKH    (8 value + 1 length + 22 script)
4   locktime
---
125
```

`4 * 125 + 224 = 724`.  The module builds a real `Bitcoin.Data.Tx` with those
outputs from `toLocalScriptPubKey` / `toRemoteP2WPKHScriptPubKey` and proves
`serTx.size = 125` under the standard 32-byte txid, 32-byte P2WSH hash, and
20-byte HASH160 shapes.  It then proves the weight is exactly
`724 + 172 * k` for an arbitrary list of 32-byte HTLC witness-script hashes.

### Anchor `1124`

BOLT 3 Appendix A gives `225` non-witness bytes:

```text
4   version
1   input count
41  funding input
3   count_tx_out          <-- BOLT table, four outputs should be 1 byte
43  to_remote P2WSH
43  to_local P2WSH
43  local anchor P2WSH
43  remote anchor P2WSH
4   locktime
---
225
```

`4 * 225 + 224 = 1124`.  The model's own `serTx` over the same four outputs
produces `223` bytes (`1` output-count byte), hence `1116` weight.  The proven
gap `1116 + 8 = 1124` is exactly the `2` bytes times `4` WU/byte.  The module
therefore keeps `1124` as BOLT 3's negotiated fee-basis constant and explicitly
does **not** claim it is a lower bound on the literal serialization.

### Per-HTLC increment

Every untrimmed HTLC output is P2WSH: `8 + 1 + 34 = 43` non-witness bytes, so
`4 * 43 = 172` weight units.  This is proved for an arbitrary list in
`weightTargets_commitmentTx_serSize` and as separate formulas and successor
lemmas.  The channel layer's `commitmentWeight` is proved equal to the same
closed formula in `commitmentBaseWeight_target`.

## Blockers / missing bridges

1. **Witness serialization is absent.**  `Bitcoin.Data.Tx.witness` is parsed
   but not serialized.  The `224` witness weight (2-byte marker/flag plus a
   222-byte funding-input witness with two 73-byte maximum-DER signatures and
   the 71-byte 2-of-2 script) is BOLT 3's assumed component size, not a theorem
   about a serialized witness.
2. **Anchor Appendix A count discrepancy.**  The pinned BOLT text's anchor
   table says `count_tx_out: 3 byte`; the model serializer emits one byte for
   four outputs.  The exact `8` WU gap is proved; the spec's intended padding
   is not modelled.  This is why the anchor half is an accounting theorem, not
   a literal-serialization theorem.
3. **CompactSize threshold.**  The serializer-size theorem assumes fewer than
   `253` total outputs so the output count is one byte.  Above roughly 249
   untrimmed HTLCs the count prefix grows to three bytes and BOLT 3's `172`
   per-HTLC formula omits the extra two bytes; that varint growth is not
   modelled.
4. **Dust trimming is not modelled here.**  `htlcWitnessScriptHashes` is the
   list of already-untrimmed outputs.  The BOLT 3 second-stage dust test lives
   in `LnLean.Channel.Fee` and `LnLean.Proofs.WaveD.D12`.
5. **Script execution / ECDSA.**  No sighash, signature verification, or
   script interpreter semantics are claimed; this is a size/weight theorem.
6. **Root import is owned elsewhere.**  The new module is not imported by
   `LnLean.lean`, so the full-tree build will not compile it until the
   integrator adds the import.  This lane did not run a full build.
