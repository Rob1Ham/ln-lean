## Result

`LN-L1-004` is now backed by a faithful two-branch BOLT 3 `to_local` model
and by sorry-free structural/commitment theorems for both clauses.  The old
flat seam definition is retained unchanged for compatibility, but it is
explicitly documented as **not** the BOLT 3 script and is no longer the
recommended catalog target.

This is a structural byte-level result.  It does **not** claim script
execution (`OP_IF`/`OP_CSV` semantics), signature checking, sighash handling,
or a proved SHA-256/P2WSH bridge; those remain the documented missing
bridges.

## Model change

### `LnLean/Bitcoin/Seam.lean`

Added, without changing any existing signature or definition body:

```lean
def toLocalDelayPush (csv : Blocks) : ByteArray :=
  pushData ((ByteArray.empty.push csv.toUInt8).push (csv >>> 8).toUInt8)

def toLocalScriptFull (revocationPubKey delayedPaymentPubKey : PubKey)
    (csv : Blocks) : Script :=
  ⟨(ByteArray.empty.push OP_IF)
     ++ pushData revocationPubKey.bytes
     ++ (ByteArray.empty.push OP_ELSE)
     ++ toLocalDelayPush csv
     ++ (ByteArray.empty.push OP_CSV)
     ++ (ByteArray.empty.push OP_DROP)
     ++ pushData delayedPaymentPubKey.bytes
     ++ (ByteArray.empty.push OP_ENDIF)
     ++ (ByteArray.empty.push OP_CHECKSIG)⟩
```

`toLocalScriptFull` is the BOLT 3 witness script

```text
OP_IF <revocationpubkey>
OP_ELSE <to_self_delay> OP_CSV OP_DROP <local_delayedpubkey>
OP_ENDIF OP_CHECKSIG
```

The `OP_IF` branch is the revocation/penalty path; the `OP_ELSE` branch is the
CSV-delayed local-payment path.  The delay uses the scaffold's fixed-width
two-byte little-endian push `[0x02, d % 256, (d / 256) % 256]`, matching
`ScriptTemplates.pushScriptNum16`.

The pre-existing flat fragment is unchanged and its docstring now records:

```lean
def toLocalScript (revocationPubKey : PubKey) (csv : Blocks) : Script :=
  ⟨pushData (ByteArray.mk #[csv.toUInt8])
     ++ (ByteArray.empty.push OP_CSV).push OP_DROP
     ++ pushData revocationPubKey.bytes
     ++ ByteArray.empty.push OP_CHECKSIG⟩
```

and `toLocalScriptFull_size` proves the full script is 77 bytes for two
33-byte keys, while `toLocalScript` is `6 + revocationKey.bytes.size` bytes
(39 bytes for a 33-byte revocation key), so the two are not interchangeable.

### `LnLean/Proofs/Bitcoin/ToLocalScriptTargets.lean` (new)

Imports `LnLean.Bitcoin.Seam`, `LnLean.Bitcoin.ScriptTemplates`,
`LnLean.Proofs.Bitcoin.ScriptProps`, and reuses the already-proved
injectivity/commitment lemmas in `WaveD.D42`/`WaveD.D43`.  No `sorry`, no
`axiom`, no `admit`, no `native_decide`, no `unsafe`, no `@[implemented_by]`.

## Catalog recommendation

`LN-L1-004` currently names `LnLean.Bitcoin.toLocalScript`, a `def`, so the
catalog checker cannot promote it and the named object is the flat fragment.
Recommended retarget (catalog owned by the integrator; **not edited here**):

```text
LnLean.Proofs.Bitcoin.ToLocalScriptTargets.toLocalScriptFull_carries_csv_and_revocationKey;
LnLean.Proofs.Bitcoin.ToLocalScriptTargets.toLocalScriptFull_commits_delay_and_revocationKey;
LnLean.Proofs.Bitcoin.ToLocalScriptTargets.commitmentOutputs_toLocal_commits_delay_and_revocationKey
```

The first is unconditional containment of the revocation key, the delay push,
and `OP_CSV`; the second is witness-script commitment to the revocation key
and delay; the third is the `commitmentOutputs`/P2WSH output-level version.
All are exact, sorry-free theorems, so the row is a legitimate `proved`
candidate **after** the integrator adds the root import and catalog entry.

Suggested promoted-row scope note:

> `LN-L1-004` covers the seam's full two-branch BOLT 3 `to_local` witness
> script (`toLocalScriptFull`), which is definitionally the wave-A
> `toLocalWitnessScript`.  Containment is unconditional.  Commitment assumes
> 33-byte compressed revocation keys and `to_self_delay < 2^16`; the
> output-level form additionally assumes an injective supplied `sha256` and
> the existing `CommitmentParams.HashesMatch` bridge.  Script interpretation
> and signature/CSV enforcement are not modelled.

The definition-target classification of `LN-L1-004` disappears once the
retarget is applied, because all three targets are theorems; the other
definition-target rows are unaffected.

## Blockers / missing bridge

1. **No script interpreter.**  `OP_IF`, `OP_CSV`, `OP_DROP`, and
   `OP_CHECKSIG` are byte templates only.  No spendability, signature, or
   relative-timelock semantics are proved.  This is the same boundary as
   `ScriptProps`, D42, and D43.
2. **SHA-256 / P2WSH bridge is a parameter.**  `toLocalScriptFull_p2wsh_*`
   assumes an injective `sha256 : Script → ByteArray`; the
   `commitmentOutputs` form uses the existing `HashesMatch` `Prop`.  No hash
   implementation is computed or assumed as an axiom.
3. **Fixed-width encoding.**  The delay uses the scaffold's two-byte
   little-endian push, not minimal `CScriptNum`.  The represented value is
   exact for every `d < 2^16` (BOLT 2's `u16` field), but the bytes are not
   claimed to be minimal-encoding identical for all values.
4. **Root integration is owned elsewhere.**  The new module is not imported by
   `LnLean.lean`, so a full-tree build will not compile it until the
   integrator adds the import.  `LnLean.Proofs.PhaseC3.AxiomAudit` was not
   extended by this lane.
5. **Shared-file constraint.**  Per lane ownership, the following were **not**
   edited: `LnLean.lean`, `LnLean/Proofs/Obligations.lean`,
   `LnLean/Proofs/Traceability.lean`, `LnLean/Proofs/PhaseC3/AxiomAudit.lean`,
   `scripts/**`, `docs/**`, and `agents/status/**`.
