Here `CommitmentConserved` is the existing

### 2.5 Honest construction from state


### 2.6 Negative results (the gap, mechanized)

```lean
theorem duplicate_htlc_count_coverage_not_binding :
    waveE_e20_covers_htlcs duplicateHtlcMessage duplicateHtlcCommitment ∧
      ∀ sigAt : CommitmentHTLCOutput → EcdsaSig,
        ¬ HtlcSignaturesMatch duplicateHtlcMessage duplicateHtlcCommitment sigAt

theorem no_wire_determined_coverage :
    ¬ ∃ f : CommitmentSigned → Commitment,
        ∀ (m : CommitmentSigned) (r : FeeRate),
          waveE_e20_commitment_signed_covers m r (f m)

theorem no_coverage_htlc_selector :
    ¬ ∃ f : CommitmentSigned → List CommitmentHTLCOutput,
        ∀ (m : CommitmentSigned) (c : Commitment),
          waveE_e20_covers_htlcs m c → c.htlcs = f m

theorem wellFormed_message_can_fail_coverage :
    wellFormed (.commitmentSigned waveE_e20_emptyCommitmentSigned) ∧
      ¬ waveE_e20_commitment_signed_covers
          waveE_e20_emptyCommitmentSigned ⟨0⟩
          (waveE_e20_commitmentWith 1 0)

theorem same_message_different_fees :
    ∃ (m : CommitmentSigned) (c₁ c₂ : Commitment),
      c₁.feeSat ≠ c₂.feeSat ∧
        waveE_e20_commitment_signed_covers m ⟨0⟩ c₁ ∧
        ¬ waveE_e20_commitment_signed_covers m ⟨0⟩ c₂
```

What each pins down:

* `no_wire_determined_coverage`: **no total decoder** from wire records to
  commitments can satisfy coverage at every feerate. A fixed commitment has
  a fixed `feeSat`; the BOLT 3 formula fee grows with the feerate. The fee
  half is therefore an off-wire state fact. (Proof: a one-HTLC-signature
  message forces one HTLC output, hence positive weight; coverage at rate 0
  gives `feeSat = 0`, coverage at rate 1,000,000 gives
  `feeSat = 1000 * weight > 0`.)
* `no_coverage_htlc_selector`: no function recovers the HTLC **set** from a
  covering message. E20's one-message/two-HTLC-sets counterexample is reused.
* `duplicate_htlc_count_coverage_not_binding`: equal-length positional
  coverage is strictly weaker than per-output signature binding when the
  HTLC list repeats an output; two distinct signatures cannot be the image of
  `[h, h]` under one function.
* `wellFormed_message_can_fail_coverage`: `wellFormed` checks DER lengths
  only, so the empty-signature message is accepted and covers nothing.
* `same_message_different_fees`: the same well-formed message covers the
  canonical zero-fee commitment but not the otherwise-identical commitment
  with `feeSat = 1`.

## 3. Proof strategy

1. **Reuse the model, do not restate it.** Coverage of the emitted outputs
   uses `htlcOutputCount` from `Proofs/Channel/CommitmentTxProps` and E20's
   `waveE_e20_covers_htlcs`; the bridge is one rewrite with
   `Commitment.htlcOutputCount_commitmentOutputs`.
2. **Separate the two halves.** The HTLC half is a list-length fact derived
   from `m.htlcSignatures = c.htlcs.map sigAt` and `List.length_map`. The fee
   half is `omega` from `CommitmentConserved` and `FeeIsFundingResidual`. No
   step uses `waveE_e20_commitment_signed_covers`.
3. **Construction, not assumption.** `withFormulaFee` sets the fee to the
   formula value by definition; `commitmentSignedOfState` sets the HTLC
   signature list to the mapped HTLC list by definition. Coverage is then
   `rfl`-level, and `wellFormed` is checked against the real `msgLength`,
   `sigsValid`, and `idsValid` definitions.
4. **Counterexamples use concrete records.** `duplicateHtlcCommitment` is
   `waveE_e20_commitmentWith 2 0` (two copies of E20's sample HTLC);
   `duplicateHtlcMessage` carries an empty signature and a one-byte
   signature. `oneHtlcSigMessage` is the one-item message used for the
   no-decoder theorem. `zeroHtlcZeroFeeCommitment` is the canonical zero-fee
   commitment at feerate 0.
5. **The no-decoder theorem is arithmetic, not hand-waving.** The only
   nontrivial computation is
   `1,000,000 * w / 1000 = 1000 * w` (`Nat.mul_div_right`) and
   `0 < c.weight.val` from `hcount : c.htlcs.length = 1` by case split on
   `anchorOutputs` (weights 896 / 1296).

`LnLean.Protocol.Messages.commitment_signed_covers`, whose `hc` hypothesis is
exactly `waveE_e20_commitment_signed_covers`. That is circular and must not

Recommended retarget (requires parent edits to `Obligations.lean`,
`Traceability.lean`, and the root imports, which this lane is not allowed to

* `leanTarget`:
  `LnLean.Proofs.ProtocolCoverageTargets.commitment_signed_covers_exact_of_state`
* claim: "Given a `commitment_signed` whose HTLC-signature list is the
  per-output image of the commitment's surviving HTLC outputs, together with
  the BOLT 3 conservation equation and the formula-fee residual equation for
  that commitment, the message covers exactly those HTLC outputs and its fee
  is exactly the BOLT 3 formula fee (`#htlcs + 1` signatures, payload
  `≤ 34 + 73 + 73 * #htlcs`). The wire record alone determines neither the
  fee nor the HTLC set; those require the off-wire commitment state."
* status: conditional promotion (like `LN-PR-003`), **provided** the claim is
  reworded as above and the scope caveat below is recorded. If the parent
  wants to keep the literal English sentence unchanged, leave the row
  `statementOnly` and use this report as the blocked-until-then evidence.

Scope caveats that must travel with the row:

1. `HtlcSignaturesMatch` is a signed-data hypothesis. The model has no
   `Commitment → ByteArray` sighash serializer; `WaveE.E06` binds a signature
   only to an explicitly supplied sighash. C3 verification of the commitment
   signature is still outside the record.
2. The fee equation is derived from `CommitmentConserved` and
   `FeeIsFundingResidual`, i.e. from the commitment state, not from the wire.
   `no_wire_determined_coverage` mechanizes the impossibility of the
   wire-only reading.
3. "Exactly the current HTLC set" is cardinality + per-output assignment
   only. The wire has no HTLC id/amount/direction; `no_coverage_htlc_selector`
   mechanizes that the set is not recoverable. `HtlcSignaturesMatch` is the
   strongest statement the record can support about contents.
4. The literal old conclusion (signature count, payload bound, fee) is
   available at `commitment_signed_covers_exact_of_state` without assuming
   coverage.

## 8. Residual risks

1. The positive theorem is conditional on the per-output signature relation
   and the two value equations. It is not a proof that a received wire message
   was honestly produced; it is a proof of what follows when the signed-data
   bridge and the commitment state are supplied.
2. `HtlcSignaturesMatch` uses a function `CommitmentHTLCOutput → EcdsaSig`.
   With duplicate HTLC outputs a real signer could sign the same output twice
   with different nonces; the function form forbids that. This is a *modelling
   restriction*, not a security assumption, and it is precisely why the
   duplicate counterexample exists. A future model with per-index signatures
   should replace the function by `Fin c.htlcs.length → EcdsaSig`.
3. The no-decoder theorem quantifies over total functions
   `CommitmentSigned → Commitment`; it does not rule out a partial decoder
   with side data. That is the intended reading: side data *is* the
   commitment state.
4. No full `lake build` or `collect-obligations.py` was run (per lane
   instructions). The two required targets build RC 0; the module is not
   root-imported yet, so a later parent integration must add the import and
   re-run the gate.
