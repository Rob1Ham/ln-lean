## 1. Result

The current target `LnLean.Wire.TLVStream.WellFormed` is a predicate `def`:

```lean
def TLVStream.WellFormed (s : TLVStream) : Prop := s.Sorted ∧ s.Unique
```

It cannot be promoted by the exact catalog checker, which promotes only
theorems/lemmas. The pre-existing `LnLean/Wire/TLV.lean` already proves that
strict ordering implies uniqueness (`sorted_implies_unique`), but it does not
characterize the predicate, does not give an executable admission check, and
does not connect well-formedness to the encoder/decoder.

This lane adds a theorem-level contract in a new module. It provides:

1. an exact characterization of `WellFormed` (pairwise strict increase, record
   recursive form, operational type uniqueness);
2. an executable admission check proved exact for `WellFormed`;
3. encoder/decoder preservation under the explicit `uint64` domain hypothesis;
4. retained mechanized counterexamples showing the two unconditional claims
   that **cannot** be proved: the raw parser accepts duplicate types, and the
   unconditional round trip is false for out-of-domain records.

No catalog row was edited; the retarget recommendation is §6.

## 2. Exact characterization

The new module is `LnLean/Proofs/Wire/TLVTargets.lean` (namespace
`LnLean.Wire`, imports `LnLean.Proofs.Wire.TLVProps`).

The central theorem is:

```lean
theorem TLVStream.wellFormed_iff_pairwise (s : TLVStream) :
    s.WellFormed ↔ s.types.Pairwise (· < ·)
```

This is an exact iff, not a one-way implication. The forward direction is
`sortedTypes_pairwise_lt` (already in `TLVProps`); the converse
`sortedTypes_of_pairwise` is new and turns the adjacent-pair definition of
`SortedTypes` into order-theoretic pairwise strict increase. Since
`SortedTypes → Nodup` (`sortedTypes_nodup`), the `Unique` conjunct is
redundant, and the module records:

```lean
theorem TLVStream.wellFormed_iff_sorted (s : TLVStream) :
    s.WellFormed ↔ s.Sorted

theorem TLVStream.wellFormed_iff_sorted_nodup (s : TLVStream) :
    s.WellFormed ↔ s.Sorted ∧ s.types.Nodup          -- definitional (`Iff.rfl`)
```

The second theorem is the literal catalog reading but is definitionally
trivial; it is included as a bridge, not as the recommended promotion target.

Two record-level forms make the claim operational:

```lean
theorem TLVStream.wellFormed_cons_cons (r₁ r₂ : TLVRecord)
    (rest : List TLVRecord) :
    (TLVStream.mk (r₁ :: r₂ :: rest)).WellFormed ↔
      r₁.type < r₂.type ∧ (TLVStream.mk (r₂ :: rest)).WellFormed

theorem TLVStream.wellFormed_record_type_unique (s : TLVStream)
    (h : s.WellFormed) :
    ∀ r₁ ∈ s.records, ∀ r₂ ∈ s.records,
      r₁.type = r₂.type → r₁ = r₂
```

`wellFormed_cons_cons` plus `empty_wellFormed`/`singleton_wellFormed` is a
complete structural definition. `wellFormed_record_type_unique` is the
strongest operational reading of "no duplicate types": equal types force the
same record, value included, not merely the same type list entry.

Supporting lemmas (also new):

```lean
theorem sortedTypes_of_pairwise {l : List Nat} :
    l.Pairwise (· < ·) → SortedTypes l

theorem sortedTypes_record_type_unique :
    ∀ (rs : List TLVRecord), SortedTypes (rs.map TLVRecord.type) →
      ∀ r₁ ∈ rs, ∀ r₂ ∈ rs, r₁.type = r₂.type → r₁ = r₂
```

## 3. Executable admission

`LnLean/Wire/TLV.lean` has no admission function. The new module supplies one
without modifying the read-only model:

```lean
def sortedTypesB : List Nat → Bool
def TLVStream.admissible (s : TLVStream) : Bool := sortedTypesB s.types
def decodeAdmissible (b : ByteArray) : Bool

theorem sortedTypesB_eq_true_iff (l : List Nat) :
    sortedTypesB l = true ↔ SortedTypes l

theorem TLVStream.admissible_eq_true_iff (s : TLVStream) :
    s.admissible = true ↔ s.WellFormed

def TLVStream.decidable_wellFormed (s : TLVStream) :
    Decidable s.WellFormed

theorem decodeAdmissible_eq_true_iff (b : ByteArray) :
    decodeAdmissible b = true ↔ ∃ s, decodeTLV b = some s ∧ s.WellFormed
```

`decodeAdmissible` is the actual enforcement point: it runs the reference
parser and then the exact ordering check. `admissible_eq_true_iff` proves the
checker and predicate agree on every stream, so the admission layer is neither
stronger nor weaker than `WellFormed`.

The existing parser gap is preserved and made explicit:

```lean
theorem decodeTLV_duplicateTypeStream :
    decodeTLV duplicateTypeStream = some duplicateStream

theorem duplicateStream_not_wellFormed :
    ¬ duplicateStream.WellFormed

theorem decodeAdmissible_duplicateTypeStream :
    decodeAdmissible duplicateTypeStream = false
```

`duplicateTypeStream` is the existing `TLVProps` byte string
`01 01 2a 01 01 2b`; its decoded stream has types `[1, 1]`. Thus the raw
parser accepts a duplicate/non-increasing stream, the admission check rejects
it, and **no theorem `decodeTLV b = some s → s.WellFormed` exists or can
exist** without adding an ordering check to the parser.

## 4. Encoder/decoder preservation

```lean
theorem decodeTLV_encodeTLV_of_wellFormed (s : TLVStream)
    (h : s.WellFormed)
    (hdom : ∀ r ∈ s.records, r.InDomain) :
    decodeTLV (encodeTLV s) = some s

theorem decodeTLV_encodeTLV_wellFormed (s : TLVStream)
    (h : s.WellFormed)
    (hdom : ∀ r ∈ s.records, r.InDomain) :
    ∃ t, decodeTLV (encodeTLV s) = some t ∧ t.WellFormed

theorem decodeAdmissible_encodeTLV (s : TLVStream)
    (h : s.WellFormed)
    (hdom : ∀ r ∈ s.records, r.InDomain) :
    decodeAdmissible (encodeTLV s) = true

theorem encodeTLV_injective_of_canonical {s t : TLVStream}
    (hs : s.Canonical) (ht : t.Canonical)
    (h : encodeTLV s = encodeTLV t) : s = t
```

The `InDomain` hypothesis (`type < 2^64` and `value.size < 2^64`) is **not**
decoration: `Wire.encode` truncates values at `2^64`. The module mechanizes the
failure:

```lean
def outOfDomainStream : TLVStream :=
  TLVStream.mk [⟨18446744073709551616, ByteArray.empty⟩]

theorem outOfDomainStream_wellFormed : outOfDomainStream.WellFormed

theorem decodeTLV_encodeTLV_outOfDomainStream :
    decodeTLV (encodeTLV outOfDomainStream) = none

theorem outOfDomainStream_not_roundtrip :
    decodeTLV (encodeTLV outOfDomainStream) ≠ some outOfDomainStream
```

The type `2^64` is encoded as `0xff` followed by eight zero bytes; `decode`
rejects that non-minimal field, so the whole stream decodes to `none`. Hence
the unconditional encoder/decoder theorem is false, not merely unproved.

Non-vacuity is witnessed by a concrete two-record stream:

```lean
def exampleStream : TLVStream
theorem exampleStream_wellFormed : exampleStream.WellFormed
theorem exampleStream_decode_encode :
    decodeTLV (encodeTLV exampleStream) = some exampleStream
theorem exampleStream_decodeAdmissible :
    decodeAdmissible (encodeTLV exampleStream) = true
```

`exampleStream_wellFormed` and `exampleStream_inDomain` are proved by ordinary
kernel reduction/simp; `exampleStream_decode_encode` instantiates the round-trip
theorem, so the main theorem is not vacuous.

## 7. Blockers and missing lemmas (documented, not faked)

1. **`decodeTLV` is not an ordering-enforcing decoder.** A theorem
   `decodeTLV b = some s → s.WellFormed` is refuted by
   `TLVProps.decodeTLV_accepts_duplicate_types` /
   `decodeTLV_duplicateTypeStream`. The faithful statement must either add the
   admission check (`decodeAdmissible`) or assume canonical input
   (`decodeTLV_encodeTLV`).
2. **Unconditional encode/decode round trip is false.** `Wire.encode`
   truncates values at `2^64`; `outOfDomainStream` is well formed but encodes
   to bytes that `decode` rejects. The domain hypothesis is required and is
   mechanized as a counterexample above.
3. **No production decode path calls the admission check.** `LnLean/Wire/TLV.lean`
   is read-only for this lane and its `decodeTLV` remains unchanged. Wiring
   `decodeAdmissible` into a message/extension decoder requires a model change
   in an owning lane.
4. **Module is not root-imported.** `LnLean.lean` and the `AxiomAudit` module are
   outside this lane's ownership. The integrator must add
   `import LnLean.Proofs.Wire.TLVTargets` (and an `AxiomAudit` registration if
   the gate requires it) for the module to participate in the full build; the
   module-only build above already verifies the proofs.
5. **Catalog edit pending.** `LnLean/Proofs/Obligations.lean` was not edited;
   `LN-CR-005` still resolves to the `def` and stays `statementOnly` until the
   retarget in §6 is applied by the catalog owner.
6. **Not modelled.** Known-type length validation, even/odd unknown-type
   policy, message-specific value decoding, TLV compression, concrete BOLT test
   vectors, and a byte-cursor/IO error model. The admission predicate is a
   stream-level BOLT 1 ordering check only.
