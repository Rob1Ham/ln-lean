## 1. Target and decision

`LN-CH-003` was the only unresolved **planned** catalog target. Two facts made
the old form unprovable:

1. D12 (`waveD_d12_output_ordering_fails`) mechanically refutes the
   unconditional ordering claim about
   `LnLean.Channel.Commitment.commitmentOutputs`: that function emits
   `to_local` before `to_remote` regardless of value (`[500, 200]`).
2. `LnLean.Channel.CommitmentOutput` has no `scriptPubKey` and no HTLC
   `cltv_expiry`, so D12's `waveD_d12_cltv_tiebreak_not_recoverable` shows the
   BOLT key `(value, script, cltv)` cannot even be represented on the old
   output type.

Rather than weaken the claim, this lane adds the smallest faithful extension
that makes the real BOLT 3 statement expressible, proves it, and keeps the
refutation of the old function. The catalog target name is unchanged:

```lean

```

## 3. Model extension

All new model definitions live in `namespace LnLean.Channel` in
`LnLean/Channel/Commitment.lean` (section "BOLT 3 ordered, dust-trimmed
commitment outputs").

### 3.1 Script key

```lean
structure ScriptPubKey where
  bytes : List UInt8
deriving Repr, DecidableEq, BEq

def ScriptPubKey.le (a b : ScriptPubKey) : Prop := a.bytes ≤ b.bytes
```

`List.le` on `List UInt8` is the non-strict lexicographic order with the
shorter prefix first, i.e. exactly BOLT 3's
"common-length prefix lexicographically as if by `memcmp`, then selecting the
shorter script". `le_refl`, `le_trans`, `le_total`, and decidability are
proved. This is the raw byte string; script *derivation* from funding keys is
not modelled (see §7).

### 3.2 Tagged output and BOLT 3 order

```lean
inductive CommitmentOutputKind where
  | toLocal | toRemote | htlc (direction : Direction)
  | localAnchor | remoteAnchor

structure CommitmentTxOutput where
  kind : CommitmentOutputKind
  valueSat : Nat
  scriptPubKey : ScriptPubKey
  cltvExpiry : Height

def CommitmentTxOutput.le (a b : CommitmentTxOutput) : Prop :=
  a.valueSat < b.valueSat ∨
    (a.valueSat = b.valueSat ∧
      (a.scriptPubKey.bytes < b.scriptPubKey.bytes ∨
        (a.scriptPubKey.bytes = b.scriptPubKey.bytes ∧ a.cltvExpiry ≤ b.cltvExpiry)))
```

This is `(value, script, cltv)` lexicographic order: strict on value and
script, non-strict on CLTV. `le_refl`, `le_trans`, `le_total`, and
`Decidable (a.le b)` are proved without `Classical.choice` in the relation
itself (the sorter still inherits the usual `mergeSort` axioms).

### 3.3 Rich commitment transaction

```lean
structure CommitmentTx where
  commitment : Commitment
  dustLimitSat : Nat                 -- transaction owner's dust_limit_satoshis
  toLocalScript : ScriptPubKey
  toRemoteScript : ScriptPubKey
  localAnchorScript : ScriptPubKey
  remoteAnchorScript : ScriptPubKey
  htlcScript : CommitmentHTLCOutput → ScriptPubKey
```

The existing value-only `Commitment` is embedded, so no existing construction
or theorem is broken. Output constructors:

```lean
def CommitmentTx.toLocalOutput  (tx) : Option CommitmentTxOutput
def CommitmentTx.toRemoteOutput (tx) : Option CommitmentTxOutput
def CommitmentTx.htlcOutput     (tx) (h : CommitmentHTLCOutput) : Option CommitmentTxOutput
def CommitmentTx.localAnchorOutput  (tx) : Option CommitmentTxOutput
def CommitmentTx.remoteAnchorOutput (tx) : Option CommitmentTxOutput
def CommitmentTx.outputsUnsorted (tx) : List CommitmentTxOutput
def CommitmentTx.outputs         (tx) : List CommitmentTxOutput
```

Semantics:

* `to_local`/`to_remote` are present iff `dustLimitSat ≤ value`
  (BOLT 3 "less than `dust_limit_satoshis` ⇒ MUST NOT contain").
* an HTLC output is present iff `dustLimitSat ≤ h.amountSat`, where
  `CommitmentHTLCOutput.amountSat` is the BOLT 3 post-second-stage-fee value
  (`amount - second_stage_fee`); this is the same value the legacy
  `commitmentOutputs` projects.
* anchors are present exactly when `commitment.anchorOutputs` is `true`; they
  are exempt from dust trimming (BOLT 3 fixes them at 330 sat).
* `outputs` is `sortOutputs outputsUnsorted`, where

```lean
def sortOutputs (l : List CommitmentTxOutput) : List CommitmentTxOutput :=
  l.mergeSort (fun a b => decide (CommitmentTxOutput.le a b))
```

so the construction is a deterministic function of the record; equal-key
outputs are interchangeable on-chain.

## 4. Exact proved signatures

### 4.1 Catalog target

`LnLean.Proofs.Channel.CommitmentOrderTargets`:

```lean
theorem output_ordering (tx : CommitmentTx) :
    tx.outputs.Perm tx.outputsUnsorted ∧
      tx.outputs.Pairwise CommitmentTxOutput.le ∧
      (tx.outputs.map (fun o => o.valueSat)).Pairwise (· ≤ ·) ∧
      tx.outputs.Pairwise (fun a b =>
        a.valueSat = b.valueSat → a.scriptPubKey.le b.scriptPubKey) ∧
      tx.outputs.Pairwise (fun a b =>
        a.valueSat = b.valueSat → a.scriptPubKey = b.scriptPubKey →
          a.cltvExpiry ≤ b.cltvExpiry) ∧
      (tx.toLocalOutput = none ↔ tx.commitment.toLocalSat < tx.dustLimitSat) ∧
      (tx.toRemoteOutput = none ↔ tx.commitment.toRemoteSat < tx.dustLimitSat) ∧
      (∀ h ∈ tx.commitment.htlcs,
        h.amountSat < tx.dustLimitSat → tx.htlcOutput h = none) ∧
      (∀ h ∈ tx.commitment.htlcs, tx.dustLimitSat ≤ h.amountSat →
        CommitmentTxOutput.htlc h (tx.htlcScript h) ∈ tx.outputs) ∧
      (∀ o ∈ tx.outputs, o.kind ≠ .localAnchor → o.kind ≠ .remoteAnchor →
        tx.dustLimitSat ≤ o.valueSat)
```

This is exactly `CommitmentTx.outputs_spec` (the core theorem in
`LnLean/Channel/Commitment.lean`), restated at the catalog name.

Component wrappers:

```lean
theorem outputs_values_nondecreasing (tx : CommitmentTx) :
```

## 5. Proof strategy

1. **Script order.** Reuse Lean core `List.le` / `List.lt` on `List UInt8`
   (`Init.Data.List.Lex`). This is the standard lexicographic order with the
   shorter prefix first, matching BOLT 3 `memcmp`. BOLT's script component is
   therefore not axiomatized or encoded as an opaque rank.
2. **Three-key order.** Define a non-strict lex relation on
   `(valueSat, script bytes, cltvExpiry)`. Prove reflexivity, transitivity,
   and totality by case analysis on `Nat.lt_trichotomy`,
   `Std.lt_trichotomy` for byte lists, and `Nat.le_total`. The relation keeps
   the kind out of the key, which is correct: BOLT sorts outputs, not roles.
3. **Deterministic sort.** Feed the decidable relation to `List.mergeSort` and
   use `List.mergeSort_perm` and `List.pairwise_mergeSort`. `mergeSort` is a
   function, so the order is deterministic. Component theorems project the
   value/script/CLTV consequences out of the pairwise relation.
4. **Trimming.** Model each output group as an `Option`, present exactly when
   `dustLimitSat ≤ value`. Membership in `outputsUnsorted` is reduced to a
   five-way append disjunction; HTLC membership uses `List.mem_filterMap`.
   Keeping/omitting an HTLC is then a rewrite with the `if` condition, and
   "no emitted non-anchor output is below dust" is a case analysis over the
   five groups.
5. **No weakening of D12.** The old `commitmentOutputs` is not claimed to be
   sorted or dust-filtered. The target module imports D12 and restates the
   refutations.

## 8. Blockers / integration work (not done here)

1. **Root import.** `LnLean/Proofs/Channel/CommitmentOrderTargets.lean` is not
   imported by `LnLean.lean` (not in this lane's ownership). Consequently the
   root build does not compile it and `scripts/check-final.py` will fail its
   `EXPECTED_LEAN_FILES = 166` / root-import equality check until the
   integrator adds
   `import LnLean.Proofs.Channel.CommitmentOrderTargets` and updates the
   expected file count. The module itself builds RC 0 in isolation.
2. **Model integration.** Existing consumers still use
   `Commitment.commitmentOutputs` (fixed group order, no dust filter).
   Replacing them with `CommitmentTx.outputs` requires supplying scripts and
   the owner's dust limit at every construction site, which touches many
   files outside this lane.
3. **Script derivation.** `CommitmentTx.toLocalScript`, `toRemoteScript`,
   anchor scripts, and `htlcScript` are caller-supplied. Deriving them from
   funding keys and payment hashes (BOLT 3 templates) is not done; the L1
   template side lives in `LnLean/Bitcoin/ScriptTemplates.lean`.
4. **Second-stage fees.** The trimming test uses
   `CommitmentHTLCOutput.amountSat` as the post-second-stage-fee value. The
   model does not recompute that value from `HTLCRecord` plus
   `timeoutFeeSat`/`successFeeSat` in the rich layer; D12's
   `CommitmentHTLCOutput.ofRecord` and `survivingHTLCs` provide that bridge.
5. **Anchors.** Both anchors are emitted whenever `option_anchors` is on. The
   BOLT single-anchor exception (no HTLCs and one party's output below dust)
   is out of scope, as it already was in the legacy model.
6. **CLTV key scope.** Non-HTLC outputs carry `cltvExpiry = 0`. BOLT consults
   CLTV only among HTLC outputs; equal value and equal script across two
   different output kinds is not realizable with the BOLT 3 script templates,
   so the lex key does not misorder real commitment outputs. This is worth
   stating in the catalog note.
7. **Key ties.** Outputs with identical `(value, script, cltv)` may differ in
   `kind` but are on-chain interchangeable; `mergeSort` gives a deterministic
   relative order. BOLT's rationale only requires agreement on the canonical
   order, which a function provides.
