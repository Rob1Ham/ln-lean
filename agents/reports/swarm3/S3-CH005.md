## 1. The gap and what was added

The catalog row

```
LN-CH-005  Channel / commitment
A commitment with an insufficient feerate for its weight is rejected before signing.
leanTarget := "LnLean.Channel.Fee.feeInsufficient"
```

named only the predicate definition

```lean
def LnLean.Channel.Fee.feeInsufficient (r : FeeRate) (w : Weight) (paid : Msat) : Prop :=
  ¬ feeSufficient r w paid
```

supplied by `LnLean/Proofs/WaveD/D13.lean:72`.  A predicate definition is not
a theorem about rejection or signing.  `LnLean/Proofs/Channel/FeeTargets.lean`
adds the missing theorems at two levels:

1. **Pre-signature gate level.**  An executable verdict function
   `commitmentSigningGate` uses the commitment's own `Commitment.weight` and
   its recorded `feeSat` converted to millisatoshis.  The headline theorem is
   an iff: the gate rejects exactly when `feeInsufficient` holds.
2. **Checked transition level.**  D13's `waveD_d13_FeeCheckedStep` is the BOLT 2
   step relation refined by the fee gate; its only `commitment_signed`
   constructor carries a sufficiency proof.  The module proves the converse of
   D13's one-directional no-derivation result: for a channel in the `normal`
   phase, *no* checked signing derivation exists iff the commitment is
   insufficient.  Composing the two levels gives "the gate rejects exactly
   those commitments for which no checked signing transition exists".

The forward direction (insufficient ⇒ no checked signing derivation and gate
rejection) is proved unconditionally, matching the catalog sentence.  The
converse requires the explicit phase premise `c.phase = ChannelPhase.normal`,
because `commitment_signed` is illegal before `normal` for *any* fee.

## 3. Rejection relation

The relation proved is:

```
gate rejection  ⇔  feeInsufficient r weight paid
                ⇔  ¬ feeSufficient r weight paid
                ⇔  paid.val < (feeForWeight r weight).val
                ⇔  (paid.val * 1000 + 999) < r.msatPerKw * weight.val

and, for positive commitment weight, the literal feerate threshold

  commitmentFeeInsufficient r c  ⇔
    ((c.feeSat * 1000) * 1000 + 999) / c.weight.val < r.msatPerKw

and, for a normal-phase channel with the same commitment record:

gate rejection  ⇔  ¬ ∃ c' cm', FeeCheckedStep r c cm commitmentSigned c' cm'
```

The last equivalence is the exact "rejected exactly when no signing is
possible" statement.  `insufficient_no_checkedCommitmentSigned` and
`commitment_rejected_before_signing` give the catalog's one-directional
sentence without the phase premise.

## 4. Policy assumptions kept explicit

* **Fee definition.**  BOLT 3 §4 base fee, floored:
  `feeForWeight r w = r.msatPerKw * w.val / 1000` (msat).
* **Paid fee.**  `Commitment.feeSat` is whole satoshis, converted exactly as
  `feeSat * 1000` msat.  No rounding of the recorded fee.
* **Weight.**  `Commitment.weight` is the BOLT 3 expected weight
  `commitmentBaseWeight anchors + 172 * htlcs.length`
  (724 without anchors, 1124 with anchors).
* **Rejection payload.**  `ErrorCode.feeInsufficient`.
* **Phase.**  The converse of the transition-level theorem assumes
  `c.phase = ChannelPhase.normal`; without it, `commitment_signed` has no
  derivation regardless of fee.  The forward direction needs no phase
  premise.
* **Transition refinement.**  `Channel`/`Step` carry no fee premise, so the
  signing relation used is D13's explicit refinement
  `waveD_d13_FeeCheckedStep`.  No theorem claims the bare `Step` relation
  checks fees.
* **Not modelled.**  Zero-fee commitments, anchor child-pays-for-parent, RBF,
  mempool/package relay, fee estimation, the difference between the required
  base fee and the actual on-chain fee after trimming, wire encoding of the
  `error` message, and computational/relay policy.
