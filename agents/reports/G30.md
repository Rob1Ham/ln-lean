Why these choices, adversarially:

- **Do not confuse “the module builds” with “the claim is closed.”** D39 is the clearest example: its report is honest and its build is RC 0, but the module still contains `sorry` at line 73. D13 is subtler: its report says “no added hypotheses,” yet the transition-level theorem is about `waveD_d13_FeeCheckedStep`, not the model's `Step`; the model's `Step.commitmentSigned` checks only `phase = normal` (`State.lean:92-94`). D37/E37 are the most important example: both headers explicitly disclaim the `Step` constructor, which is exactly what `LN-CH-101` asks for.
- **03 is a model-target failure, not a proof failure.** Both lanes prove their stated theorem correctly. The problem is that the theorem is about the wrong script. `Seam.toLocalScript` (`Seam.lean:129-134`) is a flat four-part fragment; BOLT 3's `to_local` is a two-branch witness script with a delayed-payment key (`ScriptTemplates.lean:125-138`). A proof of the flat fragment cannot be upgraded to the BOLT claim by naming it `to_local`. D03's own report says this, and E03's report says it too. The honest disposition is to keep D03 as the literal-target artifact and open a replacement obligation.
- **12's catalog sentence is false as written.** `commitmentOutputs` emits a fixed group order, so a 1000-sat `to_local` can precede a 500-sat `to_remote` (`D12.lean:92-114`; `E12.lean:157-161`). D12 is better than E12 because it also proves the CLTV tie-break is erased by the output representation (`D12.lean:144-156`) and gives the exact per-HTLC dust iff (`:443-464`). E12's value-sort and dust results are correct but narrower. The catalog should be revised to “the model is unsorted; the repaired construction sorts by value and trims dust,” not “ordered by value then script” as if proved.
- **13 is the one target where the exact Lean declaration matters.** The catalog says `LnLean.Channel.Fee.feeInsufficient`; D13 defines precisely that, with `Msat` (`D13.lean:72-74`). E13 defines `LnLean.Channel.feeInsufficient` with `Nat` (`E13.lean:62-64`), which is a different name and type. D13 therefore wins on statement fidelity even though E13 has useful ceiling/floor arithmetic and a cleaner negative result for the bare `Step`. Port E13's `requiredFeeSatCeil` lemmas and `waveE_e13_unconditional_rejection_false` into the D13 story if the integrator wants both. Do not use F10: `PreSignFeeOk` compares `commitmentFee r c` (an `Msat`) directly with `Commitment.feeSat` (a `Nat`) and then retains a `sorry` for the false unconditional statement (`F10.lean:468-473`).
- **33 cannot be “closed” by any of the three lanes as stated.** The target string appears in `Obligations.lean:360`, but there is no declaration with that name. D33 and E33 prove a generic induction principle and then instantiate it on a ledger-conservation game; the hard part is delegated to `Ledger.step_conserves`. E33's queue is a genuine refinement over D33's single delivery bit, but it still does not connect to `Channel.Step`. F16 is the best model because `AsyncSystem.step?` makes drops and illegal labels explicit, and its settlement instance plus `liveness_requires_fairness`/`safety_fairness_separation` are non-vacuous. Still, `F16.ledgerGame_secure` is a ledger theorem, not channel-manager safety. The right next step is a replacement target with a concrete state/label relation, not a claim that `LN-SEC-003` is proved.
- **37 is an arithmetic success but a bridge failure.** E37's `AffordableCommittedAdd` is the strongest of the three: `fitsSettled`, `leavesReserve`, `atLeastHtlcMinimum`, `withinReceiverInFlight`, a sharp `ledger_iff_covered`, and a witness. D37's reserve guard is BOLT-faithful but lacks the min/in-flight checks and has no report. Neither adds `Step.update_add_htlc`; both say so. The catalog's “missing bridge” is therefore still missing. Keep E37 as the interim arithmetic module and make the replacement a model edit to `LnLean/Channel/State.lean`.
- **39's lane choice is easy once the `sorry` is counted.** E39 has no `sorry`, proves the negation and the exact `0 < b ↔ 0 < a` equivalence, and its guarded binder agrees with `bindChannel` on admitted announcements. D39 has the richer store-level invariant (`waveD_d39_positiveCapacities` and `_applyGossipPositive`), which E39 lacks, but D39 pays for it with a `sorry` at the false unconditional statement. Take E39 and port the store invariant separately; do not take D39 wholesale.
- **44's D44 is materially stronger than E44.** E44's “proof” is a set of `decide` calls on assumed component constants (`E44.lean:205-309`); it never constructs a transaction or serializes one. D44 builds a base commitment transaction from the model's script builders and proves its `serTx` size is 125 (`D44.lean:332-348`), so the 500 non-witness weight is grounded in the serializer. The remaining 224 witness weight is still assumed; that caveat must travel with the result.
