## Reasoning
Target 13 is a close D13/E13 call, but D13 wins on the criteria that matter for integration. Both files have zero in-file `sorry` sites and clean exact-module build traces. D13 alone compiles the catalog's literal declaration name `LnLean.Channel.Fee.feeInsufficient`; E13's declaration is `LnLean.Channel.feeInsufficient`, so a release check against the catalog string would fail with E13. D13 also supplies an executable rejection verdict with `ErrorCode.feeInsufficient` and a soundness proof for a refined signing relation (`waveD_d13_FeeCheckedStep`), whereas E13's gate is only a `Prop` conjunction. E13 is stronger on one criterion: `waveE_e13_unconditional_rejection_false` is a genuine mechanized counterexample to the bare model, and E13's status line honestly says "conditional" while D13 says "proved" for a gate-level theorem. That counterexample should be preserved in integration notes, but it does not outweigh D13's exact catalog name and richer gate/transition formalization. There is a real caveat: the catalog name `LnLean.Channel.Fee.feeInsufficient` appears to conflate the module `LnLean.Channel.Fee` with a namespace; the model's `feeSufficient` is `LnLean.Channel.feeSufficient`. If the parent decides the catalog string is a typo and traces `LnLean.Channel.feeInsufficient`, E13 becomes the better fit and D13's `Fee.` namespace should not be kept.

Target 14 is not close. D14 models exactly the BOLT 2 parameter named by the catalog anchor (`max_dust_htlc_exposure_msat`), computes exposure per commitment with the correct holder-specific dust limit and direction flip, and debits the balance so the reserve preservation is not a restatement of an unchanged state. E14 substitutes `max_htlc_value_in_flight_msat` for dust exposure, uses a holder-agnostic trim test, and its `Step` preservation theorem is largely vacuous because `Step` never changes balances or HTLCs. E14 is still useful: it has a clean, self-contained reserve/in-flight-cap development, a `Reachable` preservation theorem, and a counterexample showing why the reserve guard cannot be dropped. But its exposure claim is weaker than the catalog's BOLT 2 claim, so it should not be the primary `LN-CH-006` file. D14's only material drawback is the pre-existing `ReserveProps` `sorry` in its import closure; the specific theorems D14 uses are sorry-free, and the sorry is an unrelated `LN-CH-101` obligation. If the final gate rejects any transitive `sorry`, the fix is to localize the two reserve lemmas (or accept the pre-existing base-tree sorry), not to switch to E14.

Declaration count was not used: D13 has more theorems than E13, but the decision rests on the catalog name, the executable gate, and the exact-module traces. D14 and E14 have equal theorem counts, and the decision rests on statement fidelity and counterexample quality.
