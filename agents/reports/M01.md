# M01 — make `PrimitiveModel` preimage assumption consistent

## Target

- `LnLean/Crypto/Model.lean`
- `LnLean/Proofs/Crypto/Sha256Props.lean`
- `LnLean/Proofs/WaveE/E19.lean`
- `LnLean/Proofs/WaveD/D05.lean`
- `docs/ASSUMPTIONS.md`

## Result

- Removed the field `PrimitiveModel.sha256_preimageResistant`.
- Kept the structural field `sha256_size` and the consistent 32-byte-domain
  field `sha256_collisionResistant : CollisionResistant sha256`.
- Removed the projection theorem `preimageResistant_field`.
- Retained `preimageResistant_vacuous` as a negative theorem: no 32-byte-output
  hash is globally injective.  It is no longer a contradiction inside
  `PrimitiveModel`.
- Updated `rejectAllEcdsa` (E19), the C1 discussion in `docs/ASSUMPTIONS.md`,
  and the D05 comments.
- No new `sorry`, `axiom`, `admit`, `native_decide`, `unsafe`, or Mathlib.

## Remaining interface issue handed to M02

`PrimitiveModel` still contains
`hmac_prf : HmacPrf hmacSha256` together with
`hmac_size : ∀ k m, (hmacSha256 k m).size = 32`.  For a fixed key this is the
same pigeonhole obstruction: a 32-byte-output function cannot be injective on
all `ByteArray`.  M02 owns the HMAC repair: remove the field, prove the
negative result, and replace D07's global `HmacPrf` hypothesis with a finite
execution-local tag-binding contract.

## Trust boundary after M01

C1 is exactly collision/second-preimage resistance on the 32-byte payment
preimages used by Lightning.  It is an explicit algebraic interface assumption,
not a computational hardness proof.  Global SHA-256 injectivity is not assumed.
