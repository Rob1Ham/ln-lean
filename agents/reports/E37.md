`AffordableCommittedAdd c amount` collects:

1. `fitsSettled : amount.val ≤ c.balance.localBalance.val` — the committed
   drop does not truncate;
2. `leavesReserve : localReserveSat c * 1000 + amount.val ≤ localBalance.val`
   — the post-update balance still meets the peer-advertised reserve;
3. `atLeastHtlcMinimum` — the receiver's `htlc_minimum_msat`;
4. `withinReceiverInFlight` — the receiver's
   `max_htlc_value_in_flight_msat` after the add.

Added hypotheses (all documented in the module):

- Ledger conservation requires `fitsSettled` (or full affordability) **and**
  the pre-state equation `ledgerValue c fee = c.fundingValue.val`. The
  old-ledger hypothesis is unavoidable: the theorem is about preservation.
- `waveE_e37_ledger_iff_covered` shows `fitsSettled` is necessary as well as
  sufficient for the single-add shape. The reserve/minimum/in-flight conjuncts
  are policy requirements needed for the *other* invariants; the ledger
  equation alone cannot see them (hence
  `waveE_e37_covered_can_break_reserve`).
- `fee` is held fixed; the weight/fee of the added HTLC is not modelled and
  is not claimed.

Statement fidelity: the `LN-CH-101` statement without an affordability guard
is **false** in the current model (`spendLocalBalance` is truncated natural
subtraction). Rather than retain a `sorry`, this module states the
unconditional claim as `UnguardedLedgerClaim` and proves its negation
(`waveE_e37_unguarded_claim_false`), then proves the strongest true
conditional form and its sharpness. The Wave-C false statement in
`ReserveProps` is not edited; `waveE_e37_agrees_with_reserveProps` checks that
the guarded theorem here is the same statement as the proved Wave-C
`committed_update_preserves_ledger_of_le`.

## Remaining gap / next step

The missing model field is a BOLT 2 `update_add_htlc` constructor in
`LnLean.Channel.State.Step`. `Step` still changes only phase, commitment
counters, and feerate, so `committedAdd` is a standalone successor function
and affordability is a pre-state predicate rather than a protocol check. The
next step is to add

```lean
| updateAddHtlc (c : Channel) (amount : Msat) (h : AffordableCommittedAdd' c amount) :
    Step c (.updateAddHtlc amount) (committedAdd c amount)
```

(parameterised in the model namespace), extend `Reachable` preservation
lemmas, and prove that every reachable state satisfies
`ChannelAccountingInvariant`. Also unmodelled: the net-of-second-stage-fee
HTLC dust test (known `gross_dust_rule_insufficient` gap in `ReserveProps`)
and the fee/weight impact of the added HTLC.
