## 4. Open items and next proof step

1. **`LN-WIRE-001` — canonical TLV parser round trip.** The statement is
   `s.Canonical → decodeTLV (encodeTLV s) = some s`. It is not proved.
   The next smallest step is a single-record inversion lemma:
   `parseRecord (bytesToList (TLVRecord.encode r)) = some (r, [])` for
   `r.InDomain`, using the wave-A `decode_encode` law and `List.take`/`drop`
   lemmas; then induct over `s.records` and show the fuel `size + 1` suffices
   because each record consumes at least two bytes.

2. **Parser does not enforce BOLT 1 ordering.** The wave-A module docstring
   for `LnLean/Wire/TLV.lean` claims the decoder rejects repeated or
   non-increasing types, but `parseRecord`/`decodeTLVGo` contain no ordering
   check. `decodeTLV_accepts_duplicate_types` is a checked counterexample:
   the parser returns both `type = 1` records. This is a discrepancy in a
   wave-A file, which B08 may not edit. The integrator should either add an
   ordering check to the parser (and a corresponding obligation) or amend
   the wave-A docstring. The round-trip theorem above is deliberately stated
   only for canonical **input**, not as a decoder rejection guarantee.

3. **Strictness scope.** `canonical_types_pairwise_lt` proves pairwise
   strict increase for canonical input. The parser-side rejection of
   non-increasing streams remains unproved because it is not implemented.
