Both statements are unchanged. `localAnchor_hash_ne_remoteAnchor_hash` keeps
the SHA256 collision-resistance hypothesis `hcr` and the `HashesMatch` bridge
explicit, so the crypto assumption stays visible rather than being axiomatised.

New helper lemmas (same file, namespace `LnLean.Bitcoin`):

* `byteArray_append_cancel_left {a b c : ByteArray} (h : a ++ b = a ++ c) : b = c`
* `byteArray_append_cancel_right {a b c : ByteArray} (h : a ++ b = c ++ b) : a = c`

Both are derived from `ByteArray.toList_data_append`, `Array.toList_inj`, and
the Lean-core `List.append_cancel_left` / `List.append_cancel_right`; no new
imports and no mathlib.

Proof shape of (1): `anchorWitnessScript k = ⟨pushData k.bytes ++ fixed tail⟩`
and `PubKey.Valid` gives `k.bytes.size = 33`, so `pushData k.bytes` reduces to
the one-byte push prefix `0x21 ++ k.bytes`. Reassociating appends on the bytes
side, right-cancelling the common opcode tail and left-cancelling the common
`0x21` prefix yields `k₁.bytes = k₂.bytes`; `cases` on the `PubKey` structures
finishes the equality.

Proof shape of (2): assume the two anchor hashes equal, rewrite both through
`h.2.2.1` / `h.2.2.2` (the `HashesMatch` conjuncts), apply `hcr` to get equal
anchor witness scripts, then apply (1) and contradict `hkeys`.

Axiom audit (scratch `#print axioms`): both theorems depend only on
`[propext, Quot.sound]`.
