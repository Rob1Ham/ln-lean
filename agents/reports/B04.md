## 4. Open items and next smallest step

Corrections to the brief, recorded as required:

1. **724 is the non-anchor base weight, not the anchor variant.** The tree
   (`Seam.commitmentBaseWeight` and LDK `chan_utils.rs:281-283`) fixes 724 for
   the non-anchor commitment and 1124 with `option_anchors`. The module proves
   both and the `+400` delta. No statement here claims 724 for anchors.
2. **"Fee cannot exceed funding under well-formedness" is false as stated.**
   `FeeBudget` is therefore an explicit hypothesis, and
   `fee_not_bounded_by_funding_wellformedness` proves the gap: an in-range
   1000-sat funding with feerate 10^9 msat/kw owes 724,000 sat. The missing
   premise is BOLT 2's funder-balance/`update_fee` check, which lives in the
   channel state layer.

Open, and deliberately not claimed:

* **Cross-module agreement with `LnLean.Channel.Commitment.commitmentWeight`.**
  That module is outside this agent's wave-A import whitelist, so the theorem
  `∀ a k, LnLean.Channel.commitmentWeight a k = commitmentWeight a k` cannot
  be stated here. The local definition has the same argument order and the
  same formula (`LnLean/Channel/Commitment.lean:69-70`), and
  `commitmentWeight_bolt3_formula` is the closed form. Next smallest step:
  in a channel proof module (B09/B11) add
  `import LnLean.Channel.Commitment` and prove the equality by `rfl`.
* **Actual serialized weight.** `Bitcoin.Data.Tx` has no weight function, so
  BOLT 3's expected weight is not proved to bound a real serialization; the
  byte decomposition is arithmetic on BOLT 3's own counts. Next step: add
  `Tx.weight`/serialized-size semantics to the L1 seam (integrator-owned),
  then prove `expected ≤ actual` under BOLT 3's 73-byte-signature assumptions.
* **Dust trimming.** `weightOfFlags` takes trimming as input; it does not
  decide which HTLCs are trimmed. Next step: import `LnLean.Channel.Fee`
  and BOLT 3 §5, define `untrimmed (dustLimit feerate) htlc`, and prove that
  `flags = htlcs.map (untrimmed ...)`.
* **HTLC second-stage weights (663/703/666/706)** and
  `zero_fee_commitments`/`shared_anchor` are out of scope, as documented in
  the module docstring.
