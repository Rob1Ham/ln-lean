### Corrected / conditional statements (do not overclaim)

* The mission's "punishable iff the honest party holds the revocation secret"
  is **not literally derivable** from `Channel.Penalty`: `penaltyValid` checks
  `deriveRevocationPubkey … = derivePrivkey …`, and
  `RevocationScheme.consistent` supplies that equality for *every* secret, so
  the abstract model cannot bind a witness secret to a commitment number. The
  corrected theorem is `honestPunishable_iff` (007), which carries
  `HoldsRevocationSecret sh c w` explicitly. A concrete scheme must make
  `derivePrivkey`/signature verification reject the wrong secret; that is the
  open cryptographic gap recorded below.
* "No breach is detectable after the window without a watchtower" cannot be
  proved because the model has no detection predicate or node-liveness
  semantics. The proved part is 015 (no *timely penalty* after the deadline)
  and 017/018 (any detection route other than self-observation is a watchtower
  report, hence requires `wt.live`). The watchtower remains an explicit
  external assumption, as required by `docs/ASSUMPTIONS.md` §4.
* The economic bound does not model fees, fee spikes, or BOLT 5
  `security_delay`; `penaltyFee` is a parameter and 010 needs
  `0 ≤ c.toRemoteValue` (the `BtcAmount` type is `Int`).

## 4. What remains open, and the next smallest proof step

1. **Resolve the `LnLean.Channel.HTLC` duplicate declaration** between
   `Channel/HTLC.lean:76` and `Channel/Types.lean:142`. Until then no module
   can import both `Channel.HTLC` and `Channel.State`, and the whole-library
   build cannot include all of B16's intended imports. This is the smallest
   integrator action and unblocks the stated import list.
2. **Concrete secret binding (LN-BREACH-007).** Next step: instantiate
   `RevocationScheme` with a signature check over the witness, or add a
   field `derivePrivkey base s = derivePrivkey base s' → s = s'` plus a
   signature-verification predicate to `PenaltyWitness`, then prove
   `punishable → HoldsRevocationSecret`. This is the only way to remove the
   explicit secret hypothesis from `honestPunishable_iff`.
3. **HTLC-output coverage (LN-BREACH-013).** Next step: extend `PenaltyTx`
   with `htlcInputs : List (OutPoint × BtcAmount)`, define the total sweep
   value, and prove the extended sweep equation. The current
   `penaltyTx_no_third_input` shows exactly why the two-input record cannot
   carry the claim.
4. **Watchtower liveness.** Next step: model `live` as a temporal predicate
   over heights and add a liveness assumption (e.g. `∀ h, live h`) before
   proving that a late breach is observed; the current interface only gives
   `reports → live`.
5. **Fee/security-delay economics.** Next step: carry a fee model and prove
   that `penaltyFee` remains below the swept value; this is the BOLT 5
   economic liveness condition `LN-PENALTY-ECON`, not a safety theorem.
