## 3. Proof approach and helper lemmas

The two goals are pure `Bool`-parser arithmetic, so no model extension was
needed.

* `derFullOK` is a left-associated `&&` spine:
  `(((byte0 && byte1) && byte2) && body)`. (`&&` is `infixl:35` in Lean 4.)
  Peeling with `Bool.and_eq_true` therefore yields the three header bytes on
  the left spine and the dependent `match` on the `r` length byte as the final
  conjunct.
* New private helper `derFullOK_header` performs that peel once and returns the
  three header equalities `byte0 = 0x30`, `byte1 = UInt8.ofNat (size - 3)`,
  `byte2 = 0x02`. `derFullOK_imp_wireSigOK` then closes `derEnvelope b` by
  `simp` using those equalities plus the hypotheses `71 ≤ b.size` and
  `b.size ≤ 73` (the two `decide` guards), and discharges `wireSigOK` via
  `Bool.or_eq_true`/`Or.inr`.
* `derFullOK_length_exact` peels the header spine, then does `cases` on
  `byteAt b 3`; the `none` branch contradicts `h : false = true`. In the
  `some rLen` branch it peels the two `r`-body conjuncts and does `cases` on
  `byteAt b (5 + rLen.toNat)`; the `none` branch again contradicts `h`. The
  `some sLen` branch exposes
  `decide (rLen.toNat + sLen.toNat + 7 = b.size) = true`; rewriting with
  `decide_eq_true_eq` and `omega` gives the stated partition.

No new `simp` lemmas, definitions, or imports were added. The only added
declaration is the private helper above.
