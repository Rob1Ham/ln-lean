## Remaining gap / next step

The missing model field is a verifier-level bridge: `OnionInterface.verifyHmac`
is `ByteArray → ByteArray → Bool` and receives only the expected and stored
tags, not the authenticated message or `mu`. Consequently the BOLT 4 HMAC
construction has to be supplied outside the interface (as done by
`openWithHmac`), and the security theorem is conditional on C8. A future model
extension could add a concrete onion verifier whose signature exposes
`mu`, `hop_payloads`, and `associated_data`, making
`verifyHmac mu hp ad stored = true ↔ onionHmacTag M mu hp ad = stored`
definitional and removing the explicit C8 hypothesis from the interface
instantiation. Computational PRF security, constant-time comparison, Sphinx
key derivation, and concrete ciphertexts remain unmodelled.
