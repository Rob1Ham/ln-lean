## 2. Semantics

Default behavior is unchanged and remains K01-strict:

* every `leanTarget` must resolve to exactly one declaration;
* an unresolved target is an error and exits RC 1;
* ambiguous targets, duplicate ids, incomplete rows, a wrong row count, a
  `proved` row with a `sorry` theorem/lemma, and a `proved` row naming an
  `axiom`/`constant`/`opaque` are errors.

`--allow-planned` is an explicit opt-in:

* an **unresolved** target on a row whose status is exactly `statementOnly` is
  reported in the table as
  `<PLANNED (no declaration yet)>`, collected in a dedicated audit section, and
  counted as `planned=N`;
* it is **not** added to the error list, **not** counted in `unresolved`, and
  **not** counted in `proved_failures`; it is never described as proved;
* it is **not** rewritten or promoted in the catalog;
* every other failure still exits RC 1, including an unresolved target on a
  `proved` row, an ambiguous target (on either status), duplicate id,
  incomplete row, wrong row count, and the `proved`-row kind/`sorry` checks.

Exit statuses remain `0` (checks pass), `1` (catalog failure), `2` (missing
input tree).

### Output compatibility

The strict table, promotion-candidate section, summary line, `ERRORS:`
section, and success line are unchanged. Only `--allow-planned` adds output:

* `mode=allow-planned` and `planned=N` in the summary line;
* the `PLANNED` marker in the per-target table;
* a `Planned targets (statementOnly, unresolved, permitted by --allow-planned)`
  section after the promotion candidates;
* `OK (--allow-planned): ...` on success.

## 4. Self-test

The checker now has a no-dependency `--self-test` that runs both modes on the
live catalog, captures their output, and verifies behavior rather than a frozen
catalog:

```sh
python3 scripts/check-catalog.py --self-test
```

```text
self-test: strict RC=1 (unresolved=23, proved_failures=0)
self-test: --allow-planned RC=0 (planned=23, unresolved=0, proved_failures=0)
self-test: PASS
```

**RC = 0.** It checks that strict mode never prints `PLANNED`, that RC 1 comes
with an `ERRORS:` section, that `--allow-planned` returns 0, that no permitted
target is counted as unresolved or as a proved failure, that `planned` equals
strict `unresolved` when strict is RC 1, and that the planned section, audit
candidates, and success line are present. If a future catalog resolves every
target, strict RC 0 is accepted by the self-test rather than being treated as a
failure.

## 7. Implementation notes

* The only unresolved targets that can become `PLANNED` are those whose
  resolution error is exactly `unresolved`, on rows with status exactly
  `statementOnly`, and only with `--allow-planned` set. Ambiguity is never
  downgraded.
* Planned targets are stored in a separate `planned` list, so they cannot leak
  into `unresolved`, `proved_failures`, or the promotion-candidate predicate
  (which continues to require an exact resolution).
* `--self-test` uses only `contextlib`, `io`, and the existing `re` module;
  no package or external tool was added.
* The checker remains source-level. `PLANNED` means “the catalog says this
  declaration will exist”; it is not evidence, a proof, or a promotion.
