## Claim

A channel funded by one L1 funding output conserves total value across
conserved channel steps and HTLC settlement.  `EndToEndState` holds the
btc-lean `FundingOutput`, the funding value, the `ChannelLedger`, the live
`Commitment`, the settled `PaymentSession` receipts, and an explicit fee
bucket.  The L1 bridge is a structure field `fundingLink` equating
`funding.value` (a btc-lean `Int` amount) with the `Nat` `fundingValue`; the
fee bridge is the field `feeLink : feeBucket = live.feeSat`.  No axiom is
introduced.

`TotalValue` splits the live commitment's output value into the part not yet
attributed to a settled payment and the settled payments themselves (so a
payment is counted exactly once), then adds the fee bucket.  For a `Funded`
state it is exactly the L1 funding value; a single `Step` and every finite
`Run` preserve it.

## Remaining obligations / exact missing bridges

There are no in-file `sorry` obligations.  The following are explicit
hypotheses or structure fields that a caller must discharge; none is an
axiom:

1. `EndToEndState.fundingLink : funding.value = (fundingValue : Int)` — the
   L1 funding link.  Instantiating it from a real wallet/chain model (that the
   outpoint holds this value) is outside this module.
2. `EndToEndState.feeLink : feeBucket = live.feeSat` — ties the explicit fee
   bucket to the live commitment fee.
3. `Funded`'s coverage clause `settledTotal s.payments ≤ s.live.totalOutputValue`
   — settled receipts must fit inside the commitment outputs; maintained by
   `settleHTLC_covers` and the `hcov` hypothesis of `Step.commitment`.
4. `Step.settle`'s `hpamt : p.amountSat = h.amountSat` — the bridge from the
   settled `PaymentSession` receipt to the channel HTLC being settled.
5. `CommitmentConserved` / `ChannelLedger.AllConserved` inputs — supplied by
   `LnLean.Proofs.Conservation` (`settleHTLCOutputAt_conserved`,
   `ledger_no_value_creation`).
6. Not modelled at all: chain confirmation/reorgs of the funding output, the
   SHA-256 preimage check behind `PaymentSession.state = .succeeded`, and
   second-stage/penalty fee buckets.  These are recorded in the module
   docstring rather than assumed.
