## Newly discovered gaps

1. **Model cannot enforce `LN-HT-004` by itself.**  `addHTLC` takes no
   existing id set, so it cannot reject a duplicate.  The checked wrapper
   `addHTLCChecked` supplies the missing list-aware guard; the concrete
   theorem `addHTLC_accepts_reused_id` records that two adds with id 7 both
   succeed in the unchecked model.
2. **Freshness must be relative to the right set.**  Full-list `idsNodup` is
   preserved by an add iff the id is fresh for the *full* list
   (`idsNodup_add_iff`), but the live-set version additionally needs
   `FreshLiveId` (a settled record with the same id still sits in the full
   list).  `liveIdsNodup_add` states this strongest true conditional form.
3. **Parallel list abstractions.**  `HTLCProps.addToSet/removeFromSet` and this
   module's `addToSet/removeById` have the same semantics under different
   names.  An integrator may want to alias one to the other in a later
   consolidation; no existing statement is weakened here.
4. **In-place settlement is not a list operation.**  `removeHTLC` changes only
   the lifecycle state and keeps the id (`removeHTLC_id`).  Proving that a
   settled record disappears from `htlcSet` after an in-place replacement
   needs a `replaceById`/map-update operator.  Smallest next step: define
   `replaceRecord (pred) (h) hs`, prove its `htlcSet` equals
   `removeById h.id (htlcSet hs)` when `h` is settled, and derive the live-set
   absence from `id_not_mem_liveIds_removeById`.
