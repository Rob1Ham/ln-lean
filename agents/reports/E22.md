- Added hypotheses:
  - `hAccept : ∀ n, lcl.requires n = true → rmt.supports n = true` — the
    BOLT 1 connection-survival hypothesis: a peer that does not support a
    locally required (even-bit) feature must close the connection, so every
    surviving negotiation has this property. It is the only added hypothesis
    in the main theorem.
  - `hct : ∀ n, ct.supports n = true → negotiated lcl rmt n = true` in the
    channel-type theorem is a *selection predicate* (the model has no
    channel-type TLV), not an assumption about BOLT semantics. It says "this
    channel type was selected under the negotiated feature set".
  - No result is weakened silently: the counterexample theorem records the
    exact unconditional failure.
- Statement fidelity:
  - `LnLean.Protocol.Handshake` has no `feature_intersection` theorem; its
    docstring states "Feature negotiation (BOLT 9) is not checked; `init`
    carries opaque feature bytes". The feature model lives in the existing
    committed proof module `LnLean.Proofs.Protocol.FeaturesProps`
    (`FeatureVector`, adjacent even/odd bits, `supports`, `requires`,
    `negotiated`), which this module imports. The Wave-E theorem family is
    therefore stated over that model rather than over a non-existent
    `Handshake` field.
  - The model's `negotiated` is intentionally asymmetric:
    `lcl.requires n || (lcl.supports n && rmt.supports n)`. Thus the catalog
    claim is true exactly on surviving connections. The negative result makes
    the failure explicit: `localRequiredOnly` against `emptyVector` negotiates
    feature 0 although the intersection is empty.
  - A second faithfulness point: bitwise `intersection` of the vectors is not
    the negotiated set when one peer requires feature `n` and the other offers
    it optionally; both support it, but neither raw bit is shared. The correct
    object is the support-set intersection proved here.

## Remaining gap / next step

- Missing model field: `HandshakeState` (or the `init` step) does not carry
  decoded local/remote feature vectors, and `InitMsg` exposes only opaque
  `ByteArray` fields. The main theorem is therefore about abstract
  `FeatureVector`s, not about vectors decoded from an actual `init` exchange.
  A next step is a model change adding decoded feature fields to the handshake
  state (or a `FeatureCodec`-mediated `init` record) and deriving `hAccept`
  from `FeaturesProps.accepts_iff_no_unknown_required` plus the BOLT 1
  disconnect rule.
- No concrete channel-type TLV or BOLT 9 dependency table is modelled; the
  channel-type result is the subset law only.
- The scaffold has no `Set` import, so set equality is expressed as
  extensional predicates (`Nat → Prop`); this is logically the same statement.
