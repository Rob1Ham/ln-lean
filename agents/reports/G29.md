## Recommended layout

All paths are relative to the tree root. `WaveD/` = `LnLean/Proofs/WaveD/`,
`WaveE/` = `LnLean/Proofs/WaveE/`, `MH/` =
`LnLean/Proofs/ModelHardening/`.

Selection rule, in precedence order: (1) a cross-cutting G report (G28/G30)
that resolves a conflict; (2) the pairwise G report; (3) default to the D lane
(the main tree and the primary catalog carrier). Where both lanes are
defective and the pairwise report says “replace”, the slot is kept open in the
notes, not silently upgraded.

## Rejected alternatives

1. **Import both lanes for all 48 targets (96 modules).** Rejected: duplicate
   catalog claims, double build surface, and a real collision
   (`LnLean.Channel.Reserve.bounds` in D14/E14). The tree would also import
   the known-sorry `D37`/`D39` and the rejected `E44`/`E47`.
2. **Merge the best theorems of D and E into one file per target.** Rejected:
   not whole-file, requires proof surgery, invalidates all existing build and
   report evidence, and creates new unverified code. Out of scope for a
   read-only integration.
3. **Rename everything to `LnLean.Proofs.Final.T01…T48`.** Rejected: renames
   namespaces and every `waveD_*`/`waveE_*` declaration, breaking 112 reports,
   marker-to-report links, and the G-series references; buys only cosmetic
   tidiness and risks proof breakage for zero verification gain.
4. **Move D41–D48 to `Proofs/Decomp/` with a new namespace.** Rejected:
   module/namespace mismatch, report path churn, and no Lean benefit. Keep the
   original path/namespace and separate the annex modules in the manifest.
5. **Keep all 48 D files and add E only where “better”.** Rejected: imports
   both lanes for most targets and drags in `D37` (false theorem + `sorry`),
   `D39` (false unconditional + `sorry`), and `D03` where `D03` is superseded
   as the primary by nothing (it is still primary, but the full D set adds 15
   unselected modules).
6. **Glob-copy a live lane directory, then regenerate.** Rejected: would pick
   up any transient `*Alt.lean` or scratch file and silently import it; the
   `E03Alt` orphan artifact proves this lane was live. Use an explicit
   manifest and P1/P3.
7. **Use `integrate-e.sh` / `integrate-f.sh` as the gate.** Rejected per G26:
   those scripts `cd` to the wrong worktree, index the D tree, never build the
   E/F modules, and mutate another lane. Run the main `check.sh`/`regen-root.sh`
   in the staging tree instead.
8. **Hand-edit `LnLean.lean` to the 63 imports.** Rejected: the generator is
   the single source of truth; a hand list will drift and cannot be verified
   by `comm`. Regenerate and diff.

## Risks and mitigations

- **Namespace pollution (high likelihood, low severity now).** Selected files
  add declarations to shared model namespaces: `LnLean.Channel.Fee.feeInsufficient`
  (D13); 34 names under `LnLean.Channel.Reserve` including `bounds` (D14);
  `LnLean.Protocol.Handshake.channel_ready_gate` (D18);
  `LnLean.Routing.Gossip.announcement_valid` (D27);
  `LnLean.Payment.Invoice.payment_secret_match` (D29);
  `LnLean.Payment.Keysend.preimage_binding` (E31);
  `LnLean.Channel.Commitment.Conserves`, `.FunderDebited`,
  `.CommitmentPair.AnchorDebitRule` (F04). If a future model edit adds one of
  these names, the build breaks with a duplicate declaration. Mitigation:
  freeze these names in `docs/ASSUMPTIONS.md` or move the aliases into
  `*Props` modules in a later, separately verified edit.
- **D14/E14 collision (latent).** `bounds` exists in both. It is currently
  safe because E14 is not selected. P3 is the guard; do not “helpfully” add
  E14 later without renaming.
- **Catalog-ID duplication for 41–48 (certain).** Eight annex modules share
  four catalog IDs with slots 01–12. `check.py` keys markers, not catalog IDs,
  so it passes (94 unique markers). Any doc tool that joins on catalog ID will
  see 2–3 modules per row. Mitigation: manifest `(catalog, slot, primary)`
  is the join key; never add annex entries to `Obligations.lean`; never count
  an annex as a separate closure.
- **Missing catalog IDs in nine selected docstrings (certain).** `D03`, `D07`,
  `D10`, `D17`, `D19`, `D20`, `D21`, `D24`, `D47` carry no `LN-*` string. A
  grep-based traceability check will report them as untraceable. Mitigation:
  P4 comment-only normalization, or make the manifest authoritative.
- **D14 marker invisible (certain).** It is inside a docstring, so
  `collect-obligations.py` reports 93, not 94, markers. P4 fixes it; otherwise
  document the gap.
- **F10 marker after `sorry` (blocking if copied).** `check.py` fails. Excluded;
  re-admit only after a comment-only repair.
- **Stale oleans / wrong cache (medium).** The F worktree symlinks `.lake` to
  the main tree; main `.lake` therefore contains F oleans, and the E worktree
  retains an orphan `E03Alt.olean`. Lake hashes content and should rebuild, but
  B1 purges the three new directories anyway. Never copy `.lake` into the final
  tree, and never treat a pre-existing olean as build evidence for the
  combined tree.
- **Root import omissions (high impact).** All three lane roots are incomplete
  for a combined tree: the F root imports **zero** ModelHardening modules, and
  the D root imports 48 WaveD modules that are not all selected. Using any lane
  root as the final root silently omits work. Mitigation: regenerate in the
  staging tree and assert 132 imports / per-lane counts.
- **Report and traceability paths (certain drift).** E/F reports are not in the
  main `agents/reports/` and their bodies cite absolute lane paths. Copy the 30
  selected E/F reports; keep the manifest mapping; do not mass-rewrite paths
  (that would invalidate report hashes cited by G28/G30).
- **Status overclaim (high impact).** Do not flip catalog statuses on import.
  `D03` is not the BOLT 3 `to_local`; `D05`, `D12`, `E20`, `D34`, `E35` are
  negative/conditional; `D13` is gate-level; `E44`/`E47` are rejected;
  `LN-SEC-003`, `LN-CH-101`, `LN-PR-004` remain open. The selected tree is a
