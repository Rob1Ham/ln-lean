# PC42 — Persisted channel recovery

**Lane:** `phase-c3` · **Module:** `LnLean.Proofs.PhaseC3.PersistenceRecovery`
**File:** `LnLean/Proofs/PhaseC3/PersistenceRecovery.lean`
**Build:** RC 0 (`lake build LnLean.Proofs.PhaseC3.PersistenceRecovery`)

## Claim

Persistence is modelled as a `Snapshot` of the two commitment counters, the
live HTLC set, and the `channel_ready` ("ready") flag.  If the snapshot is
**consistent** with the state after a persisted history prefix (`Snapshot.Consistent`,
i.e. `s = Snapshot.ofChannelRecord c r`), then restoring it and replaying the
in-memory suffix gives exactly the counters, HTLC set, and ready flag of
replaying the full history.  Replay is monotone in both counters and sticky in
the ready flag, so recovery never rolls back a counter that the prefix already
committed.  The consistency precondition is necessary: an inconsistent
snapshot can carry a smaller counter (`inconsistent_snapshot_rolls_back`).
