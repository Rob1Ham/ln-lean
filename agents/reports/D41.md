- Theorems/definitions:
  - `waveD_d41_fundingPrefix` — the two-byte BIP 141 prefix `OP_0 <0x20>`.
  - `waveD_d41_fundingPrefix_size` / `_version` / `_push32` — prefix is two
    bytes, `0x00` at index 0, `0x20` at index 1.
  - `waveD_d41_fundingScriptPubKey_bytes` — exact shape
    `p.fundingScriptPubKey.bytes = OP_0 <0x20> ++ p.witnessScriptHash`.
  - `waveD_d41_toFundingOutput_script` / `_bytes` — the L1 `FundingOutput`
    record built by `FundingParams.toFundingOutput` has the same script and
    byte shape.
  - `waveD_d41_fundingScriptPubKey_size_iff` — script size is 34 iff the stored
    program is 32 bytes; `_size_of_wellFormed` derives 34 bytes from
    `FundingParams.WellFormed`.
  - `waveD_d41_scriptPubKey_is_p2wsh` — for well-formed parameters, the
    `scriptPubKey` is a version-0 witness program with a 32-byte program.
  - `waveD_d41_scriptPubKey_version` / `_push32` / `_program` /
    `_program_of_size` — extracting bytes from the `scriptPubKey` returns the
    version marker, the push opcode, and exactly the stored hash.
  - `waveD_d41_scriptPubKey_unique_program` — the P2WSH wrapper is injective on
    the program: any program in the same position equals `witnessScriptHash`.
  - `waveD_d41_scriptPubKey_parse` — the concrete wave-A
    `Bitcoin.Data.Script.parse` decodes the output as
    `[push empty, push witnessScriptHash]` (version 0 + 32-byte push).
  - `waveD_d41_scriptPubKey_sha256_shape` — **conditional SHA-256 form**: under
    `p.witnessScriptHash = M.sha256 p.witnessScript.bytes`, the bytes are
    exactly `OP_0 <0x20> SHA256(witnessScript)`, the program extraction is that
    digest, the digest is 32 bytes, and the script is 34 bytes.
  - `waveD_d41_toFundingOutput_sha256_shape`,
    `waveD_d41_FundingConfirmed_sha256_shape`,
    `waveD_d41_FundingConfirmed_shape` — the same shape for the L1 funding
    record and for `FundingConfirmed` outputs.
  - `waveD_d41_witnessScriptHash_underdetermined` — **mechanized negative
    result**: two well-formed `FundingParams` with the same 2-of-2 witness
    script but different `witnessScriptHash`.
  - `waveD_d41_no_global_sha256_bridge` — no single hash function satisfies
    `witnessScriptHash = sha256(witnessScript)` for every well-formed
    `FundingParams`.
  - `waveD_d41_revealed_script_eq_witnessScript` — conditional binding: if the
    stored hash is `sha256(witnessScript)` and `sha256` is globally injective,
    a revealed script hashing to the stored value is the funding witness
    script.

- Added hypotheses:
  - `p.witnessScriptHash = M.sha256 p.witnessScript.bytes` in the SHA-256
    shape theorems. This is the missing model bridge, supplied explicitly.
  - `∀ a b, sha256 a = sha256 b → a = b` in
    `waveD_d41_revealed_script_eq_witnessScript`. This global injectivity is
    stronger than `PrimitiveModel` can consistently provide
    (see `LnLean.Proofs.Crypto.no_injective_hash_into_32_bytes`), so it is an
    explicit hypothesis, not an axiom.

- Statement fidelity: the **byte-level decomposition is unconditional and
  exact**. The model stores `witnessScriptHash` as an unconstrained
  `ByteArray`; `FundingParams` has no field or well-formedness conjunct linking
  it to SHA-256. Therefore the literal claim "the output is P2WSH over the
  SHA-256 of the witness script" cannot be proved from the current
  `FundingParams` alone. The module proves the exact `OP_0 <0x20>` shape for
  every `p`, then proves the SHA-256 identification under the explicit
  missing bridge, and proves a counterexample showing the bridge is not a
  consequence of the existing model. No claim is silently weakened: the
  decomposition theorems are unconditional, and the SHA-256 theorem names its
  extra hypothesis.

## Remaining gap / next step

- The missing model field/invariant is a link between
  `FundingParams.witnessScriptHash` and `SHA256(p.witnessScript.bytes)`. A
  natural repair is to add a well-formedness conjunct
  `p.witnessScriptHash = sha256 p.witnessScript.bytes` (or a structure field
  carrying the hash function plus a proof of the equality). Once that link is
  available, `waveD_d41_scriptPubKey_sha256_shape` can be used unconditionally;
  the byte-shape lemmas in this module need no change.
- Concrete SHA-256 compression/digest computation is still not modelled; the
  module uses the `LnLean.Crypto.PrimitiveModel` interface, whose
  `sha256_size` field supplies the 32-byte width.
