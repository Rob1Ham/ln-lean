## 4. Open items and next smallest step

Open:
* No SHA256/HASH160 bridge: `CommitmentParams.HashesMatch` and the
  `witnessScriptHash` field are parameters. The model does not claim that a
  hash field is the hash of a particular witness script.
* No L1 script-interpreter bridge: `FundingSpendableBy2of2` is only a
  parameterized predicate. Spendability of the 2-of-2, `to_local`, and HTLC
  outputs is not proved.
* Minimal script-number encoding is not modelled. The `to_self_delay` push
  is fixed 2-byte LE and `cltv_expiry` is fixed 4-byte LE, so HTLC witness
  script byte sizes are deliberately not stated as BOLT-exact.
* Output ordering (BIP 69+CLTV), dust trimming, fee deduction, and the
  no-HTLC anchor-elision exception are not modelled. `commitmentOutputs`
  always returns four outputs.
* No funding transaction construction, txid computation, or confirmation
  proof. `FundingConfirmed` is a hypothesis-level predicate.

Next smallest step: add the crypto seam's SHA256 operation as a parameter to
`LnLean.Crypto.Hash` (wave A2), then prove the four `HashesMatch` equalities
and derive `FundingParams.fundingScriptPubKey = p2wsh (sha256 witnessScript)`.
After that, the smallest L1 bridge is a `ScriptInterpreter` interface with
`verify : Script → WitnessStack → Tx → Bool` and a theorem connecting the
2-of-2 witness stack to `FundingSpendableBy2of2`.
