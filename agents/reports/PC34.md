## Summary

The new module formalises the shapes of the BOLT 3 commitment main outputs
and composes them with an explicit L1 spendability bridge.

* **Script shapes.**  `toLocalScript` is proved to be the
  `OP_CSV <csv> OP_DROP <revocation_pubkey> OP_CHECKSIG` template: its exact
  size is `6 + |pubkey|` (39 bytes for a compressed 33-byte key), it is
  non-empty, and the CSV operand, `OP_CSV`, and `OP_DROP` are at known byte
  positions.  `toRemoteScript` is definitionally the P2WPKH program and is
  22 bytes over a 20-byte hash.
* **Conditional spendability.**  An accepted `to_local` spend is either a
  contest-delay spend (relative delay satisfied, script controlled by the
  commitment holder) or a revocation-key spend.  An accepted `to_remote`
  spend is controlled by the remote holder.
* **P2WSH composition.**  The scripts named by the bridge are definitions
  from the bridge parameters, so the size theorems apply directly to the
  scripts used by the spend laws: 34 bytes for a 32-byte P2WSH hash.

## Bridge fields (the deferred interpreter/crypto interface)

`CommitmentL1Bridge` contains exactly the fields the theorems use:

```lean
spends : Tx → OutPoint → Prop
accepted : Tx → Prop
controls : Script → Prop
sha256 : ByteArray → ByteArray
revocationPubKey : PubKey
remotePaymentHash : ByteArray
toLocalOutpoint : OutPoint
toRemoteOutpoint : OutPoint
path : Tx → OutPoint → SpendPath
delaySatisfied : Tx → Prop
toLocal_contestDelay : accepted tx → spends tx toLocalOutpoint →
  path … = contestDelay → delaySatisfied tx ∧ controls (to_local P2WSH script)
toLocal_revocation : accepted tx → spends tx toLocalOutpoint →
  path … = revocation → controls (revocation P2WSH script)
toRemote_controlled : accepted tx → spends tx toRemoteOutpoint →
  controls (to_remote P2WPKH script)
```

The three law fields are the script-semantics consequences the composition
uses; they are interface fields, not global postulates.  A concrete
instantiation must prove them against the vendored byte-level interpreter
and the real secp256k1/SHA-256 implementations.  This is the intentional
`PC2-COMMIT` bridge boundary: the present module proves the composition and
the byte-level *shape* facts, not interpreter execution.
