## Defects

### High

**H1. The final HEAD was never gated end-to-end.**  
`/tmp/opencode/integrate-d.log` is dated `2026-10-18 00:20:22`; final HEAD `c07b216` is `00:24:13`. The log’s root has 118 imports and includes `D37Alt`; current root has 117 and does not. The full build was not rerun after the 00:22–00:24 cleanup commits (removal of `D37Alt.lean`, root regeneration, index refresh, repository-relative script changes). Therefore the recorded “full gates green” claim does not certify the final tree. The canonical D exact builds are probably still valid because no D source changed after 00:19:50, but there is no per-module log and the final gate scripts were not exercised.

**H2. Untracked files bypass the strict changed-file policy.**  
`check-wave-d.py:124` runs only `git diff --name-only BASE --`; `git()` at `:74-75` ignores the return code. The recorded run’s own `git status` shows every D module and report as untracked, yet the policy passed. Any untracked file outside `LnLean/Proofs/WaveD/` — a model edit, a new vendor file, an extra report, or a stray module — would also be invisible. The policy must include `git ls-files --others --exclude-standard` and classify every path.

**H3. `integrate-d.sh` ignores failures in root regeneration and index generation.**  
`scripts/integrate-d.sh:5` uses `set -uo pipefail` without `-e`. Line 13 runs `./scripts/regen-root.sh >/tmp/ln-d-root.txt` with no `|| exit`; lines 28–29 run both collectors with no `|| exit`. If `regen-root.sh` fails after truncating `LnLean.lean`, or if either collector fails, the gate continues and exits 0 after printing `git status`. A full build of an empty or stale root can therefore look green. The build step (lines 17–20) is checked, but the root/index steps are not.

**H4. The base commit is not verified, so the changed-file policy can pass vacuously.**  
`BASE = "a9f8d87"` is hard-coded at `check-wave-d.py:16`, and the `git()` helper at `:74-75` discards stderr and return code. If the short hash is missing, ambiguous, or the checkout has a different history, `git diff` returns empty stdout and the “unexpected changed files” list is empty. The gate should resolve `BASE^{commit}`, assert `git merge-base --is-ancestor`, and fail loudly.

### Medium

**M1. The generated obligation index omits `LN-WD-D37`, one of the two open sorry sites.**  
`collect-obligations.py:69` requires `-- OBLIGATION: <id> <claim>`; `D37.lean:285` is only `-- OBLIGATION: LN-WD-D37`, with no claim. Consequently `docs/OBLIGATIONS-GENERATED.md` lists WaveD obligations only for D36 and D39 (`:59-60`), and `agents/status/obligations.json` has WaveD rows only for D36 and D39. The document’s own header says 7 sorry sites, but the table cannot locate D37. This is an index-generation defect, not a D37 proof defect. It also means the index does not satisfy the report’s claim that both open sites are indexed.

**M2. Anchor verification does not prove the pinned-tree claim.**  
`verify-anchors.py` never checks `git -C refs/rust-lightning rev-parse HEAD` against `refs/PINNED.md`; it only checks that a path exists under whatever checkout is present and that `line <= total_lines`. It does not check BOLT anchors (`02-peer-protocol.md:...`), does not resolve shorthand `:2842-2848` references, does not check the end line of a range, and does not verify that the cited line contains the claimed symbol. A moved anchor, a different refs checkout, or a fabricated BOLT citation can still pass. Current refs HEADs happen to match `fe490093...` and `1aadb719...`, but that is manual evidence, not gate evidence.

**M3. Stale `D37Alt` build artifacts remain.**  
`.lake` contains 49 WaveD `.olean` files for 48 sources: `D37Alt.olean`, `.ilean`, `.olean.hash`, `.ilean.hash`, and `.trace`, all dated 00:18:54. The source and root import were removed, but the artifacts were not cleaned. This directly contradicts “no duplicate/stale builds.” It does not currently affect the root graph, because `D37Alt` is not imported, but it is a latent source of confusion and a sign that the final build was not clean.

**M4. Root generation is in-place and unvalidated; extra WaveD modules are accepted.**  
`regen-root.sh:5-11` writes directly to `LnLean.lean` with `>`; a failure after truncation leaves a broken/empty root. It imports every `LnLean/**/*.lean`, so an accidental `D37Alt.lean` or any extra module is silently added. `check-wave-d.py:127` accepts any path under `LnLean/Proofs/WaveD/`, and the loop only looks for `D01..D48`, so extra modules are never rejected. The gate also does not assert that the root contains exactly 48 D imports or that its import set equals the tree.

**M5. Report existence is checked, but content is not.**  
`check-wave-d.py:92-107` only tests `report.exists()`. A zero-byte report, a copied report for another DNN, or a report with no build/theorem/status evidence passes. The `CLOSED` label at `:103` means “no `sorry`”, not “the target theorem is present.” A module with one unrelated theorem and no `sorry` would be reported `CLOSED`. At minimum, require a non-empty report, the matching `LnLean.Proofs.WaveD.DNN` path, and a declaration count.

**M6. Marker adjacency, one-marker-per-sorry, cross-imports, and dependency policy are not enforced.**  
`check.py:106-110` only requires that a proof file containing `sorry` has *some* `OBLIGATION` marker anywhere. The Wave-D plan says “adjacent” and “one agent, one module”; `check-wave-d.py:101` counts markers but does not associate them with sorry sites. There is no check that a D module imports another `LnLean.Proofs.WaveD.*` module (current grep is clean), and no check for Mathlib/new dependencies. Current D37 and D39 happen to be well documented, but the gate does not enforce the rule.

**M7. The final `git status` is informational only.**  
`integrate-d.sh:31-32` prints `git status --short` and exits 0 unconditionally. It does not fail on unexpected untracked paths, extra D modules, stale alt reports, or generated-index drift. Since the gate is expected to leave regenerated indexes dirty, the correct behavior is an explicit allowlist of expected dirty paths and a hard failure for everything else.

**M8. Gate scripts allowlist themselves.**  
`check-wave-d.py:131-141` explicitly allows changes to `check-wave-d.py`, `check.py`, `check.sh`, `verify-vendor.sh`, `verify-anchors.py`, and the collectors. A modified checker can therefore weaken its own policy and still be “expected.” The current script diffs are only repository-relative path changes (verified), but the gate cannot attest its own integrity. Hash the gate scripts into the log or require parent-only edits/review.

**M9. Toolchain and branch selection are not asserted.**  
`check-wave-d.py:17` and `integrate-d.sh:7` hard-code `/dev/shm/btc/elan/toolchains/leanprover--lean4---v4.35.0/bin`. That path exists here and matches `lean-toolchain` (`v4.35.0`), but the gate never runs `lean --version`/`lake --version` or asserts the branch/HEAD. On another host, if the hard-coded path is absent but a different `lake` is on `PATH`, exact builds can use a different toolchain.

**M10. Vendor verification trusts the working manifest and uses fixed `/tmp` paths.**  
`verify-vendor.sh` reads `vendor/VENDOR-SHA256` from the worktree, not `git show HEAD:vendor/VENDOR-SHA256`, and writes `/tmp/ln-vendor-now.sha256` and `/tmp/ln-vendor.diff`. The manifest is tracked, so `check-wave-d` would flag a manifest edit; still, standalone `verify-vendor.sh` can be satisfied by editing both vendor and manifest. Concurrent gate runs can also collide in `/tmp`. No refs hash/pin check is performed.

**L3. `collect-obligations.py` declaration regex misses `private`, `noncomputable`, `instance`, and `opaque` declarations**, so declaration counts are undercounts. This is reporting only, but it makes the index less trustworthy.

**L4. `verify-anchors.py` succeeds when `anchors=0`.** There is no minimum-anchor assertion; a scan of the wrong tree or an empty source set prints `anchors=0 bad=0` and exits 0.

**L5. Fixed `/tmp` filenames are used for build and vendor logs** (`/tmp/ln-d-root.txt`, `/tmp/ln-d-full-build.log`, `/tmp/ln-vendor-now.sha256`). Concurrent or interleaved runs can overwrite evidence. Use `mktemp -d` and record the path.

**L6. `check-wave-d.py` captures only `proc.stdout` for failed builds** (`:117-119`); Lake diagnostics often go to stderr, so failure reports can be empty or misleading. This does not hide the nonzero RC, but it weakens diagnosis.

## Recommended fixes before final integration

1. **Make the gate final-tree-specific and reproducible.** At the start and end of `integrate-d.sh`, write `git rev-parse HEAD`, `git status --porcelain -uall`, UTC time, and SHA-256 of the gate scripts into the log. Run the final gate only on a clean worktree or a commit, and attach that log to `WAVE-D-INTEGRATOR.md`. Do not certify from `/tmp/opencode/integrate-d.log` or `/tmp/ln-d-full-build.log`.

2. **Harden `integrate-d.sh`.** Replace `set -uo pipefail` with `set -euo pipefail` and restructure the build check so the RC is still printed:
   ```bash
   if ! flock -w 1800 /tmp/ln-build.lock lake build >/tmp/ln-d-full-build.log 2>&1; then
     tail -20 /tmp/ln-d-full-build.log
     exit 1
   fi
   ```
   Add `|| exit 1` to `regen-root.sh` and both collectors, or rely on `set -e`. Make the final `git status` an allowlist check that exits nonzero on unexpected paths.

3. **Close the untracked-file hole in `check-wave-d.py`.** Resolve the base and include untracked files:
   ```python
   base = git("rev-parse", "--verify", BASE + "^{commit}").strip()
   subprocess.run(["git", "merge-base", "--is-ancestor", base, "HEAD"], check=True, ...)
   changed = set(git("diff", "--name-only", base, "--").splitlines())
   changed |= set(git("ls-files", "--others", "--exclude-standard").splitlines())
   ```
   Then use exact path regexes:
   ```text
   ^LnLean/Proofs/WaveD/D(0[1-9]|[1-4][0-9])\.lean$
   ^agents/reports/D(0[1-9]|[1-4][0-9])\.md$
   ```
   plus the explicit integration paths. Reject `D37Alt`, `D49`, `D37-alt.md`, and any other extra file. Fail if `git` resolution fails, if the branch is not `wave-d/48`, or if `git diff --check` is not clean.

4. **Validate the root exactly after regeneration.** Compare `LnLean.lean` to a temp output, not just build it. Assert `grep -c '^import'` and `grep -c '^import LnLean.Proofs.WaveD.D'` from a single source of truth, assert all 48 canonical imports and no duplicates, and reject any extra `LnLean/Proofs/WaveD/*.lean`. Make `regen-root.sh` write `LnLean.lean.tmp`, validate the import set, then `mv` atomically. A failed `find` must not leave a truncated root.

5. **Fix the obligation index and make it fail-closed.** In `collect-obligations.py`, accept marker-only lines:
   ```python
   OBLIGATION = re.compile(
       r"--\s*OBLIGATION:\s*(LN-[A-Za-z0-9_-]+)(?:\s+(.*))?$"
   )
   ```
   Add a post-generation assertion that every file containing a code `sorry` has its marker row in the index and that the number of WaveD rows matches `check-wave-d`’s count. Make writes atomic and return nonzero on duplicate/missing markers. This will add `LN-WD-D37` to both `docs/OBLIGATIONS-GENERATED.md` and `agents/status/obligations.json`.

6. **Make anchor verification prove the pinned reference and cover BOLT.** Before scanning, assert:
   ```python
   head = subprocess.run(["git", "-C", str(REFS), "rev-parse", "HEAD"], ...).stdout.strip()
   assert head == PINNED_RUST_LIGHTNING
   ```
   Also require a clean refs worktree. Parse `refs/bolts/*.md` anchors and shorthand `:line`/`:start-end` forms relative to the preceding path, check both start and end lines, and optionally check a symbol/label near the cited line. Fail if `anchors == 0`, and decide explicitly whether `UNANCHORED` rows are allowed.

7. **Clean the build cache and prove a non-replayed full build.** Remove `D37Alt.olean`, `.ilean`, `.olean.hash`, `.ilean.hash`, and `.trace`, or run a clean build. Prefer a clean-room build directory:
   ```bash
   LAKE_BUILD_DIR=$(mktemp -d) lake build
   ```
   Or `lake clean` before the final build. Add a gate assertion that every `.olean` under `WaveD` maps to a current `.lean` and that no `Alt` artifact exists.

8. **Strengthen report checks.** Require each `agents/reports/DNN.md` to be non-empty, contain `LnLean.Proofs.WaveD.DNN`, a status/build line, and at least one declaration name that exists in the module. Add a theorem/declaration count to `check-wave-d` so `CLOSED` cannot mean “empty module with no sorry.” Correct `D37.md` line 278 to 286 and `WAVE-D-INTEGRATOR.md` “126 root imports” to “117 root imports (126 old build jobs).”

9. **Pin toolchain and vendor evidence.** Run `lean --version`/`lake --version` and assert `v4.35.0` against `lean-toolchain`; make `LEAN` and `BASE` environment-overridable. Read the vendor manifest from `git show HEAD:vendor/VENDOR-SHA256` (or assert it has no diff), hash with `LC_ALL=C sort -z`, use `mktemp`, and record the manifest hash. Record the `refs/PINNED.md` commit hashes in the gate log.

10. **Then rerun the whole gate on final HEAD** and record the result, including the two open WaveD sorries and the acceptance decision. If acceptance requires a sorry-free lane, D37/D39 are a hard block; if the Wave-D plan’s “false/underspecified claim” exception applies, state that exception explicitly in the integrator report.
