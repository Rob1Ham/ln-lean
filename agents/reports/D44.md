  units, `4 * 125 + 224 = 724`. The module reproduces that split as
  field (64 B) + CompactSize varint (5 B) + script (56 B), grounds each part in
  the model (`serU32`/`serU64`/`serU8`, `compactSizeEnc`, `p2wsh`/`p2wpkh`),
  and proves `serTx` of an actual model `Tx` built from
  `toLocalScriptPubKey` and `toRemoteP2WPKHScriptPubKey` is exactly 125 bytes.
  The 724 constant is the pre-HTLC, non-anchor weight and assumes both
  commitment outputs are emitted; anchor (1124) and trimming are out of scope.

The one intentionally assumed component is the witness term: the model
(`Bitcoin.Data.Tx`) parses witnesses but has no witness serializer, and ECDSA
signature length is variable. Following BOLT 3, `witnessBytes` is
2 (marker/flag) + 222 (1 count + 1 nil length + (1 + 73) sig_alice +
(1 + 73) sig_bob + (1 + 71) witness script) = 224; the 73-byte signature is
BOLT 3's max-DER assumption. The 71-byte multisig script size is also proved in
`LnLean.Bitcoin.FundingParams.witnessScript_size`. This is the "assumed
component size" the task asks to identify, not a hidden hypothesis: it is a
named `def` with an explicit docstring, and the non-witness part is fully
mechanized.
