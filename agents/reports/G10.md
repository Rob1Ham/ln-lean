## Reasoning

**Target 19.** Both files are `sorry`-free and have consistent compiled artifacts. The decision turns on fidelity and counterexample quality, and `E19` wins both. `D19` correctly diagnoses the model gap and gives the stronger protocol-state evidence: a reachable handshake state accepts any `funding_signed` payload, and a checked-send wrapper is the minimal patch. But its counterexample uses a zero-length signature (`emptySig`), which is not a BOLT wire signature; a reviewer can dismiss it as an artifact of `wellFormed` being only a length bound. `E19` uses a 64-byte wire-shaped signature and a full `PrimitiveModel` variant that preserves `EufCma` vacuously, so it refutes the universal reading even after the wire-shape objection is removed. `E19` also gives the exact `wellFormed` characterization, the DER/compact shape theorem, explicit txid binding, and cross-domain separation for both commitment and close. The price is that `E19` lacks `D19`'s `PeerState.send` acceptance theorem and uses the model's txid-only `finalChannelId`. Those are real gaps, but they are narrower than the fidelity defect in `D19`'s counterexample. Keep `E19`; do not merge `D19`'s peer-level theorem into the same file (whole-file integration), but record it as follow-up evidence.

**Target 20.** This is the harder pair, and neither file is a proof of the catalog claim. `D20` is the more substantial construction and has the better HTLC/fee machinery, but its central theorem is a definitional identity, and its target is the local commitment: `holder := Direction.local`, `toLocalSat := c.balance.localSat`, and local dust/feerate/anchor parameters. BOLT 2 §“Committing Updates So Far” says the node signs the **remote** commitment (`refs/bolts/02-peer-protocol.md:3094-3097`), and BOLT 3 trims against the dust limit of the transaction **owner** (`refs/bolts/03-transactions.md:106-112,325-348`). If the two endpoints' dust limits or anchor settings differ — which the model allows, since `ChannelParams` is per endpoint — the untrimmed set and fee of the remote commitment can differ from `D20`'s locally parameterised target. Thus `D20`'s exactness theorem does not establish the BOLT claim for the transaction being signed. Its report's `Status: proved` is not supportable.

`E20` does not make that mistake, but it also does not prove the claim: `waveE_e20_commitment_signed_covers` is assumed by every positive theorem, and the predicate only pins the number of HTLC signatures, not the HTLC set. Its negative results are the best part of the file and should be retained as model-gap evidence: one message can match two different HTLC lists of the same length, and the fee is not recoverable from the message. But a file whose main positive theorem assumes the obligation cannot be the whole-file version kept as the target proof.

Therefore target 20 needs a replacement: take `D20`'s `signedHtlcs`/output-value/dust machinery, change the target to the remote commitment (`holder := .remote`, remote balance and `c.remoteEndpoint.params` for dust/feerate/anchors, `contestDelay := c.localEndpoint.params.toSelfDelay`), and add a sender-side `commitment_signed` constructor whose `htlcSignatures` are proved to be one per `signedHtlcs` output. Retain `E20`'s negative theorems to document what the unguarded wire record does not determine. If a whole file must be selected before that replacement exists, select `D20` but relabel it “canonical local-commitment construction; LN-PR-004 not closed”, not “proved”.
