## Reasoning

Both lanes independently produced sorry-free, exact-module-buildable proofs of the two catalog claims, so the decision is about which whole file to integrate, not about whether the claims are proved.

For target 23, D23 is the better whole file because it proves the replacement law at both levels the claim needs: the global store (`waveD_d23_changes_iff_newer`, with both directions and the strictness boundary) and the per-channel view (`waveD_d23_view_replacement_iff`, an exact iff with the timestamp strictness). E23's global-clock characterization is elegant and self-contained, but its store is append-only and its only clock is global; it never proves a per-channel replacement rule. The catalog wording "a newer `channel_update` replaces an older one" is a per-channel statement, and BOLT 7 makes it per channel *and direction*. D23 is therefore closer to the claim even though its `ChannelView` still lacks the direction bit. D23's dependence on `GossipProps` is a packaging caveat, not a proof hole: the three `sorry`s in that module are unrelated LN-GOSSIP obligations, D23 uses only sorry-free declarations, and `D23.olean` contains no `sorryAx`. The integrator should still run `#print axioms` on the selected D23 theorems in the combined tree because the import closure is not sorry-free.

For target 24, both files are sound and faithful. E24 is the better integrated version because its `waveE_e24_peel_forward_iff` gives the exact packet equality for the forward branch (not just the remaining layer list), it explicitly proves the layer count decreases by exactly one, and its three `sealLayers` witnesses show both branches are inhabited and mutually exclusive in a concrete one-hop case. D24's bundled `waveD_d24_peel_deterministic` is attractive because it packages the whole claim in one theorem and matches the catalog target name, but it does not state the full inner-packet equality for an arbitrary forward peel and has less explicit non-vacuity. The difference is a margin, not a correctness gap; if the integrator prefers one bundled catalog-shaped theorem, D24 is a safe fallback and no proof work needs redoing.

Do not keep both members of a pair: the duplicate theorem families would add integration surface without adding proved content, and the namespaces would not collide but the traceability index would have to choose one anyway. The F lane does not offer a competing version of either target; F05/F06/F07 are reusable Gossip admission hardening, not replacements for D23/E23 or D24/E24.
