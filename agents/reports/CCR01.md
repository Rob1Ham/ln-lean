# CCR01 — CrossChannelRouting elaboration blowup

**Status:** complete  
**Module:** `LnLean/Proofs/PhaseC3/CrossChannelRouting.lean`

## Problem

After the M02 HMAC change, a local full-tree rebuild failed only at
`LnLean.Proofs.PhaseC3.CrossChannelRouting` with Lean exit code 137. The same
module had built on the larger box. Investigation showed the exit was not a
kernel OOM: a local watchdog (`/tmp/opencode/btc-lean/bloat_guard.sh`) sends
`SIGKILL` to any `lean` process above 12 GiB RSS.

The actual cause of the 19 GiB peak was the telescoping-fee theorem
`backwardConserves_sender_eq_last_add_feeSum`.  Its old proof combined

* the overlapping-pattern recursive definition of `lastAmount`, and
* a nested-pattern recursive theorem (`[], [q], q :: r :: rest`).

The induction motive generated by that combination made a single recursive
call elaborate to roughly 12–19 GiB.

## Repair

* `lastAmount` is now `(forwardAmounts path).getLastD 0`, with the standard
  `List` equation lemmas.
* `backwardConserves_sender_eq_last_add_feeSum` is proved by ordinary
  induction on the tail, with no nested `cases` and no large arithmetic
  search.  The final step is `ac_rfl` after rewriting the three list equations.
* The theorem statement and all downstream results are unchanged.

No `sorry`, axiom, or extra assumption was added.

## Verification

```sh
export PATH=/home/ubuntu/.elan/toolchains/leanprover--lean4---v4.35.0/bin:$PATH
cd /home/ubuntu/ln-lean-repair
flock -w 1800 /tmp/ln-build.lock lake build LnLean.Proofs.PhaseC3.CrossChannelRouting
```

Result: **RC 0**, wall time ~1.3 s, peak RSS ~1.7 GiB.

The two local watchdogs were only `SIGSTOP`-ped around the build and resumed
afterward. They were not changed.
