## Reasoning

**Target 35 — E35 over D35.** Both files are sorry-free and have fresh oleans. Both main theorems are, structurally, close to unpacking their own hypothesis bundles: D35 takes the four core penalty conjuncts plus the secret and returns `HonestPunishable` via `honestPunishable_iff`/`punishable_iff_core`; E35 takes the same data inside `BreachResponse` and returns `BreachPunished`/`punishable`. The differences that matter for selection are fidelity and counterexample quality, not declaration count.

- E35’s main conclusion includes `bridge.confirms r.tx.toTx` through `BreachPunished`, while D35’s main bridge omits confirmation entirely and only reaches the L1 no-double-spend result in a separate theorem requiring an extra `hconf`. The catalog says “punished” and “timely L1 transaction”; E35’s main theorem is closer to that. E35 also has `waveE_e35_response_punishable` (line 145) and `waveE_e35_response_honestly_punishable` (line 154), so the `HonestPunishable` content that D35 concludes is recoverable from the same `BreachResponse`.
- E35’s negative result is the better counterexample. `waveE_e35_live_watchtower_alone_does_not_punish` (E35.lean:367) uses `sampleBreach`, which is proved a genuine breach by `waveE_e35_sampleBreach_detected` (line 325), a live `silentWatchtower`, an offline party, and a `silentBridge`; it proves no `Detectable` at the height and no `BreachPunished`. D35’s `waveD_d35_live_alone_does_not_punish` (D35.lean:269) assumes `hnotBreach : ¬ breachDetected c`, so it does not show a genuine breach going unpunished; it mostly restates that a non-breach cannot be punished. D35’s `waveD_d35_live_alone_does_not_detect` (line 255) is a genuine liveness-to-detection counterexample, but E35 combines detection and punishment in one mechanized example.
- E35 acknowledges that the catalog declaration `LnLean.Proofs.Liveness.watchtower_bridge` is statement-only and absent; D35’s report and module never mention it. For integration/traceability, E35 is more honest.
- D35 has useful model-facing lemmas that E35 lacks: `waveD_d35_holder_key_matches_commitment` (D35.lean:177), `waveD_d35_secret_binds_commitment` (189), `waveD_d35_bridge_breach_confirmed` (203), `waveD_d35_offline_detection_requires_report` (211), `waveD_d35_late_report_no_punishment` (230), and `waveD_d35_bridge_components` (303). These are not enough to outweigh the confirmation and counterexample gaps, but the store/key-match/offline-report lemmas are worth porting into E35 later if the integrator wants them. E35 already has the essential secret-binding, deadline, value-bound, no-false-positive, and effective-punishment lemmas.
- E35’s `waveE_e35_eventually_punished` (line 181) is not a real liveness theorem; it merely restates the response’s own confirmation height. Treat it as a packaging lemma, not evidence that a watchtower eventually acts.

**Target 36 — D36 over E36, with F02 noted as the stronger proof engine.** D36 and E36 are not independent proofs: both discharge the corrected theorem by calling `LnLean.Proofs.Bitcoin.FundingProps.witnessScript_parse_eq_none_of_wellFormed`. D36 is the better whole-file catalog artifact for three reasons:
- It states the exact catalog repair: `waveD_d36_wellFormed_parse_eq_none` (D36.lean:193), i.e. `p.WellFormed → p.witnessScript.parse = none`, in addition to `FundingParams.ParserSafe → parse = none`. E36 has `wellFormed_implies_parserSafe` but no direct `WellFormed → parse = none` theorem.
- Its counterexample is packaged as the catalog-relevant existential `∃ p, ¬ FundingParams.ParserSafe p ∧ p.witnessScript.parse ≠ none` (`waveD_d36_counterexample`, line 280), with a direct `simp` proof that the parameter is not parser safe. E36’s `waveE_e36_counterexample_parse_ne_none` (line 207) is only `∃ p, parse ≠ none`; its `¬ ParserSafe` fact is derived from the corrected theorem (line 220), which is sound but less direct as counterexample evidence.
- D36 adds real funding-flow lemmas: `waveD_d36_parserSafe_pushData_size` (line 105), `waveD_d36_orderedFundingKeys_parserSafe` (121), and `waveD_d36_confirmFunding_parserSafe` (134). E36 has `witnessScript_congr` instead, which is useful but does not cover the temporary-to-final channel-id transition. D36 also has `waveD_d36_parse_ne_none_not_parserSafe` (199), a clean necessity/contrapositive guard.

E36 is a legitimate fallback: it is shorter, its namespace is cleaner (`LnLean.Proofs.WaveE.E36.ParserSafe` rather than D36’s namespaced `LnLean.Proofs.WaveD.D36.FundingParams.ParserSafe`), and it explicitly names the universal negation. But on the catalog’s missing-`WellFormed` framing and counterexample packaging, D36 is stronger.

F02 is technically the strongest artifact for the same invariant: `waveF_f02_witnessScript_parse_eq_none_of_parseSafe` proves the parser rejection directly from `decodeOp_pushData33`/`fundingScript_key_pushes_decode` rather than delegating to `FundingProps`, and `waveF_f02_cex79`/`waveF_f02_cex81` mechanize both 79-byte (`0x4f` = `OP_1NEGATE`) and 81-byte (`0x51` = `OP_1`) failures. Its olean is sorry-free. It is not selected as the target-36 whole file because it carries `-- OBLIGATION: LN-WF-F02` (not `LN-FUND-001`), does not state the universal negation as a named theorem, and lives under `ModelHardening`, so adopting it would require a catalog/marker rewrite. The practical recommendation is to keep D36 and port F02’s direct decode lemmas and its second (81-byte) counterexample into D36 rather than replacing the catalog module.

**On the “unconditional” question.** Both 35 files correctly refuse to claim the literal sentence. The model-level obstruction is real and localized: `Watchtower` is an abstract record with no operational link from `live` to `reports`, and no link from `reports` to a confirmed penalty. Likewise, 36’s literal universal is false because `FundingParams` does not enforce 33-byte keys and `pushData` can emit an opcode as a length byte. These are model gaps, not missing proof steps; the selected files document them. Do not let an integrator “fix” the statements by deleting the hypotheses.
