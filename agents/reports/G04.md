### Statement fidelity
**Target 7.**  BOLT 4 states: derive `mu`, compute
`HMAC256(mu, hop_payloads || associated_data)`, constant-time-compare with the
packet `hmac`, abort on mismatch (`refs/bolts/04-onion-routing.md:936-939`).
- D07 `onionHmacTag M mu hopPayloads associatedData :=
  M.hmacSha256 mu (hopPayloads ++ associatedData)` (77–79) is the BOLT input
  literally.  `hmacOnionInterface` (133–135) keeps the base interface's
  documented convention — `verifyHmac expected stored = decide (expected =
  stored)` — and `openWithHmac` (148–150) computes the BOLT tag and passes it
  as the `tag` argument of `openLayer` (Onion.lean 305–311).  A successful open
  therefore says exactly "the computed tag equals the carried `l.hmac`", which
  is BOLT 4's check.  `waveD_d07_openWithHmac_tag` (154–163) proves the
  mechanical half from `openLayer_verified`; `waveD_d07_openWithHmac_layer_authentic`
  (168–181) adds, under C8, that the tag determines `hop_payloads` for fixed
  associated data.
- E07 `hmacVerify M key msg tag := decide (hmacSha256 M key msg = tag)` (95–96)
  is a correct recompute-and-compare verifier, but `hmacInterface` (176–178)
  reads `verifyHmac`'s **first** argument as the covered byte string, whereas
  `OnionInterface`/`openLayer` document and use that slot as the expected
  `tag` (`openLayer I tag p` calls `I.verifyHmac tag l.hmac`).  E07 documents
  the reinterpretation (172–175), but the instantiation is not drop-in for a
  downstream `openLayer` caller, and its main theorem
  `waveE_e07_openLayer_hmac_tag` (195–213) is a statement about
  `openLayer (hmacInterface M key) covered p`, i.e. the `tag` argument is
  actually the message.  Its `layerTag`/`LayerHmacValid` family (143–168) uses
  `l.ciphertext` as the covered bytes but is **not connected** to the
  `openLayer` obligation.  E07 itself admits the concrete BOLT input layout is
  not modelled (39–43).
- Both are honest that the covered bytes are opaque and that the catalog
  target name is stale.  D07 additionally matches the BOLT tag composition
  `hop_payloads || associated_data` and the expected-tag/stored-tag contract.

**Target 8.**  The claim is a two-sided inverse on canonical encodings; the
catalog target `LnLean.Wire.BigSize.decode_encode` is stale (real declaration
`LnLean.Wire.decode_encode`, `Wire/BigSize.lean:356`).
- D08 restates the model theorem verbatim as `waveD_d08_decode_encode`
  (67–69) and then proves the substantive converse for **arbitrary** bytes:
  `waveD_d08_decode_full_canonical` (241–414) — a full-length successful
  decode certifies `v < 2^64` and `encode v = b` — and the two-sided
  `waveD_d08_decode_full_iff` (420–434).  It supports this with digit
  uniqueness (`waveD_d08_decodeBEList_lt`, `_inj`,
  `waveD_d08_beBytesAux_decodeBEList`, `waveD_d08_bytesToList_inj`,
  130–226), six kernel-checked non-canonical/short-read rejections and one
  accepted boundary (443–480), and a truncation counterexample above `2^64`
  (`waveD_d08_encode_truncates`, 490–494; corollary 498–502).
- E08 re-derives the forward theorem from the four range lemmas
  (`waveE_e08_decode_encode`, 66–78) — a useful independent check, not
  stronger.  Its "converse" (`waveE_e08_canonical_roundtrip`, 115–119;
  `waveE_e08_canonical_unique`, 132–140) **assumes `IsCanonicalEncoding b`**,
  i.e. it assumes `b = encode n`, so it is close to a restatement and does not
  characterise arbitrary byte arrays.  Its report concedes this and defers the
  full inverse to "a future model change", although the model already returns
  the consumed length, which is exactly what D08 uses.
- E08 has one genuinely extra result D08 lacks: domain closure
  `waveE_e08_decode_value_lt` (227–260), that every successful decode lands
  below `2^64`.  D08 gets that only for full decodes, inside
  `decode_full_canonical`; it is a useful supplement, not a reason to prefer
  E08.

### Added hypotheses / model gaps
- **Target 7:** D07 takes `hC8 : HmacPrf M.hmacSha256` explicitly on its
  binding theorems (104–108, 114–117, 168–175) and discharges it for every
  model with `waveD_d07_c8_from_model` (97–98) from `M.hmac_prf`; this is the
  hypothesis the claim names, not a weakening.  E07 adds no explicit
  hypothesis because `hmac_prf` is a required field of `PrimitiveModel`
  (`waveE_e07_hmac_prf_available`, 86–88).  Both are conditional on the same
  model field.  In both, C8 is idealised as **injectivity of HMAC in its
  message for a fixed key**, which is stronger than a computational PRF; both
  say so.  Neither models `mu` derivation from ECDH/HKDF, the concrete
  `hop_payloads` layout, ChaCha20-Poly1305, or constant-time comparison.
  D07's interface also leaves `OnionInterface.hmacBinding` unused by the
  verifier; E07's `hmacBinding` is proved (`waveE_e07_hmacInterface_binding`,
  181–183) but is likewise not consumed by `openLayer`.
- **Target 8:** both restrict the forward direction to the model's `uint64`
  domain `n < 2^64` (a model invariant, not extra mathematics) and both assume
  canonicality on the weak converse.  D08's strong converse adds the
  documented condition `len = b.size` (a complete, not prefix, decode), which
  is precisely what makes the statement meaningful.  D08's header sentence
  "The only hypothesis is … `n < 2^64`" is imprecise because several theorems
  also take `IsCanonicalEncoding` or `len = b.size`; its report states these
  correctly.  Neither models IO/short-read exceptions (both are `Option`) or
  trailing-byte consumption; D08 handles the latter explicitly via the
  `len = b.size` iff rather than ignoring it.

## Reasoning
- **No `sorry` and equally strong build evidence** for all four modules, so
  the decision turns on fidelity, hypotheses, and counterexample quality, not
  on proof completeness.
- **Target 7: D07 wins narrowly, on interface and BOLT fidelity.**  The
  catalog and BOLT claim is about the integrity *check*: compute
  `HMAC256(mu, hop_payloads || associated_data)` and compare it with the carried
  `hmac`.  D07 states that construction with the BOLT operands, keeps the
  model's `verifyHmac` argument contract (expected tag vs stored tag), and
  proves the binding consequence under C8.  E07's extra content is real — the
  packet-level `waveE_e07_openLayer_covered_eq` (219–240) and the C8-necessity
  counterexample pair `constantHmac` / `waveE_e07_constantHmac_not_prf` /
  `waveE_e07_tag_check_needs_c8` (245–273) are better negative results than
  D07's `permissiveOnionInterface` witness (189–199) — but E07 buys them by
  reinterpreting `OnionInterface`'s `tag` slot as the covered message, which a
  downstream `openLayer` caller will get wrong, and its layer-tag development
  is disconnected from its main theorem.  E07's report also labels the result
  `proved` although it is conditional on the model's C8 field, while D07 says
  `conditional`.  This is a genuine judgment call (hence medium confidence),
  but the brief ranks statement fidelity above breadth, and "never choose on
  declaration count alone"; E07's larger theorem count is not decisive.
- **Target 8: D08 wins clearly.**  The catalog claim is two-sided, and only
  D08 proves the second side for arbitrary bytes instead of assuming
  canonicality.  `waveD_d08_decode_full_iff` is the faithful inverse law
  (`decode b = some (v, b.size) ↔ v < 2^64 ∧ b = encode v`), obtained without
  any model change, and `waveD_d08_encode_truncates` shows kernel-checked that
  the `uint64` bound is essential.  E08's converse is near-definitional; its
  domain closure is a nice addition but does not compensate.
