## 8. Rollback / no-force rules

1. **Never** force-push `main`, `phase-c`, `phase-c2`, `phase-c3`, or
   `wave-c/235`. If rejected, stop and investigate; do not escalate to `+`.
2. If a **new** branch was pushed with wrong content, publish a corrective commit on
   top (preferred). Deleting the ref (`git push origin --delete <branch>`) is
   allowed only with explicit owner approval and only for branches created in this
   release; it still cannot damage `main` because `main` is not an ancestor target.
3. If `main` moved before push: `git fetch`, rebase **local** feature branches onto
   `origin/main`, re-run the full gate, then push non-force. Never rebase a pushed
   branch; never force-with-lease a shared one.
4. If an atomic push is partly rejected, nothing is published — re-verify local
   hashes and retry; do not split into `--force` retries.
5. Recovery anchor: every SHA in §1 is recorded here, and each local head is ahead
   of its remote counterpart, so the worst case is re-pushing the same SHAs.
   `main` is recoverable at `b891a59` from any clone.
6. Guard rails to set before the release: `git config --local push.default nothing`,
   `git config --local push.followTags false`, explicit refspecs on every push,
   `GIT_TERMINAL_PROMPT=0`, and (recommended) GitHub branch protection on `main`.
