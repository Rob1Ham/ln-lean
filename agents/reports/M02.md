# M02 — replace impossible global HMAC injectivity with finite tag binding

## Target

- `LnLean/Proofs/WaveD/D07.lean`

- `LnLean/Proofs/WaveE/E19.lean` (HMAC field assignment only)

## Result

`PrimitiveModel` no longer contains `hmac_prf`.  It keeps only the structural
field

```lean
hmac_size : ∀ k m, (hmacSha256 k m).size = 32.
```

The impossible global predicate is retained as an abbreviation for
traceability, and its unsatisfiability is proved:

```lean
hmacPrf_vacuous (M : PrimitiveModel) (k : ByteArray) :
    ¬ HmacPrf M.hmacSha256
```

The proof applies `no_injective_hash_into_32_bytes` to the fixed-key slice
`m ↦ M.hmacSha256 k m` with width proof `M.hmac_size k`.  For a fixed key, a
32-byte-output function cannot be injective on all `ByteArray`.  This is a
theorem, not an axiom, and it is not a contradiction of the now-inhabited
`PrimitiveModel`.

`rejectAllEcdsa` in `LnLean/Proofs/WaveE/E19.lean` no longer assigns
`hmac_prf`.  No other Lean call site referenced the field.

## D07 refactor

C8 is now a local admission over the messages of one onion execution:

```lean
def HmacBindsOn (hmac : ByteArray → ByteArray → ByteArray)
    (mu : ByteArray) (msgs : List ByteArray) : Prop :=
  ∀ m₁ ∈ msgs, ∀ m₂ ∈ msgs, hmac mu m₁ = hmac mu m₂ → m₁ = m₂
```

The global hypothesis `hC8 : HmacPrf M.hmacSha256` was removed from every
positive theorem.  The changed declarations are:

| Declaration | New hypothesis |
|---|---|
| `waveD_d07_onionHmacTag_message_unique` | `hb : HmacBindsOn M.hmacSha256 mu msgs`, plus `hp₁ ++ ad₁ ∈ msgs`, `hp₂ ++ ad₂ ∈ msgs` |
| `waveD_d07_onionHmacTag_payloads_unique` | `hb`, plus `hp₁ ++ ad ∈ msgs`, `hp₂ ++ ad ∈ msgs` |
| `waveD_d07_onionHmacTag_no_reuse` | `hb`, plus `hp' ++ ad ∈ msgs`, `hp ++ ad ∈ msgs` |
| `waveD_d07_openWithHmac_layer_authentic` | `hb`, plus `hopPayloads ++ associatedData ∈ msgs`; each alternative `hp'` must satisfy `hp' ++ associatedData ∈ msgs` |
| `waveD_d07_c8_from_model` | **deleted** (it extracted the impossible global predicate) |

`hmacOnionInterface` is now

```lean
def hmacOnionInterface (M : PrimitiveModel) (mu : ByteArray)
    (msgs : List ByteArray) : OnionInterface where
  verifyHmac := fun expected stored => decide (expected = stored)
  hmacBinding := HmacBindsOn M.hmacSha256 mu msgs
```

and `openWithHmac` takes the same `mu` and `msgs`.  The mechanical theorems
keep their claims:

- `waveD_d07_onionHmacTag_size_eq_32`
- `waveD_d07_onionHmacTag_size_eq_ONION_HMAC_LEN`
- `waveD_d07_hmacOnionInterface_verify` (verifier accepts iff tags are equal)
- `waveD_d07_openWithHmac_tag` (successful open yields the expected stored tag)
- `waveD_d07_abstract_interface_accepts_any_tag`

The only extra parameters on the interface-acceptance theorem are `mu` and
`msgs`, required by the new interface signature.  No mechanical claim was
weakened.

## Why the new contract is satisfiable

`HmacBindsOn` quantifies only over the finite list `msgs`; it is not a global
injectivity statement.  Two supporting theorems are proved:

```lean
hmacBindsOn_of_pairwise_tags :
  (∀ m₁ ∈ msgs, ∀ m₂ ∈ msgs, m₁ ≠ m₂ → hmac mu m₁ ≠ hmac mu m₂) →
    HmacBindsOn hmac mu msgs

hmacBindsOn_singleton (hmac) (mu m) : HmacBindsOn hmac mu [m]
```

The singleton instance is non-empty and holds for every HMAC, key and
message with no cryptographic assumption.  In a real onion execution the
caller supplies `msgs` and the evidence that those finitely many tags are
distinct; the model does not assert that this holds for all messages.

`native_decide`, `unsafe`, or Mathlib import was added.

## Remaining C8 trust boundary

The model does not prove computational HMAC security.  C8 is an explicit
finite-execution admission supplied by the caller at the onion boundary; tag
distinctness on `msgs`, PRF distinguishing advantage, forgery probability and
computational reductions remain outside the model.  The mechanical facts
(32-byte tag width, verifier equality, stored-tag extraction) are proved
unconditionally.
