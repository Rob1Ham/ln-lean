### Correction to the brief

The brief's phrase "the anchor output does not change the
`to_local`/`to_remote` conservation equation except through the fee term" is
**not true in the model or in BOLT 3**, so the corrected equation is proved:

* the anchor outputs are outputs: the funder pays `2 * 330 = 660` sat in
  addition to the fee (BOLT 3 `:320-326`);
* anchor presence adds 400 weight units, which changes the fee only through
  the weight (BOLT 3 `:489-497`).

`conservation_two_anchors` and `conservation_effective_deduction` state
`to_local + to_remote = funding - (fee + 2 * 330)`, and
`conservation_no_anchors` records the no-anchor special case. The model's
anchor satoshi value is *not* read by the fee rule
(`fee_ignores_anchor_value`); only the weight is.

## 4. What remains open and next smallest proof steps

1. **`LN-ANCHOR-007` (key injectivity).** Next step: prove the prefix lemma
   `(anchorWitnessScript k).bytes = pushData k.bytes ++ fixedSuffix` for a
   valid 33-byte key, then cancel the common suffix with ByteArray/List
   append cancellation (the L1 snapshot exposes `ByteArray.toList` but no
   convenient append-cancellation lemma here).
2. **`LN-ANCHOR-008` (anchor program separation).** Derive it from
   `LN-ANCHOR-007`, `HashesMatch` (`h.2.2.1`, `h.2.2.2`), and the collision
   resistance hypothesis `hcr`. The proof skeleton is: equal programs ⇒
   equal witness scripts by `hcr` ⇒ equal funding keys by 007 ⇒ contradiction
   with `hkeys`. Once 007 is available this is a short proof.
3. **L1 interpreter bridge.** `AnchorSpendModel.sound` and the 16-block CSV
   anyone-sweep path are assumed/not modelled because
   `Bitcoin.Interpreter` and BIP 143 are outside the wave-A import set. The
   next step is a model module (owned by the L1 seam) exposing
   `verify : Script → WitnessStack → Tx → PubKey → Bool` with a soundness
   theorem for the committed funding key.
4. **Dust exception.** BOLT 3 allows a single anchor when there are no HTLCs
   and one commitment output is below the dust limit. `commitmentOutputs` is
   the both-outputs-present template; this module proves exactly two for
   that template, not for arbitrary dust states. The next step is to extend
   the template with a `dustLimitSat` predicate and prove the 0/1/2 cases.
5. **Cross-module reconciliation.** `boltCommitmentWeight` restates
   `LnLean.Channel.Commitment.commitmentWeight` because wave-B import rules
   forbid importing `LnLean.Channel.*` here. The integrator should link the
   two definitions in the theorem index (they agree definitionally:
   724/1124 + 172·n).
6. **Repo check note.** `python3 scripts/check.py` currently exits non-zero
   because `LnLean/Proofs/Bitcoin/FundingProps.lean` (owned by B01) contains
   duplicate obligation ids `LN-FUND-001`/`LN-FUND-002`. B03's own ids are
   unique and both its `sorry`s are marked. This needs B01/integrator repair
   before the full-library check can pass.
