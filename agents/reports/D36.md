  `bytes.size.toUInt8` as the push-length byte.  The mechanized counterexample

  `OP_2 OP_CHECKMULTISIG`, so `Script.parse` returns `some ...` instead of

  `ByteArray` and a fuel-indexed `parseWith` trace (no `native_decide`).
  The corrected theorem is faithful to BOLT 3

  well-formed defaults (0 sat, 0 push, a 32-byte zero hash) and the existing

  changing the witness script.

## Remaining gap / next step

- The concrete `ScriptInstr` type still lacks `OP_CHECKMULTISIG`, so the
  corrected theorem only proves parser rejection, not the interpreter
  bridge `FundingSpendBridge`; spendability and ECDSA unforgeability remain
  out of scope.
- `FundingParams` still does not *enforce* `ParserSafe` (or `WellFormed`) at
  construction.  The invariant is a predicate, and `ParserSafe` is module-local
  because Wave-D modules may not import one another; at integration it should
  be promoted to `LnLean.Bitcoin.FundingParams` and checked by the
  `open_channel` admission path (BOLT 2 requires valid compressed funding
  keys).
- Next: add a `ScriptInstr.checkMultisig` constructor and its `decodeOp`
  branch, then state/prove the L1 interpreter bridge, and use
  `waveD_d36_parserSafe_witnessScript_size` to connect the 71-byte script to
  the 34-byte P2WSH output.
