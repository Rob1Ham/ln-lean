# D47 — dust HTLC trimming

## Target

- Parent/catalog: `LN-CH-003`
- Module: `LnLean.Proofs.WaveD.D47`
- File: `LnLean/Proofs/WaveD/D47.lean`

## Result

- Status: conditional
- Build: RC 0 (`flock -w 900 /tmp/ln-build.lock lake build LnLean.Proofs.WaveD.D47`)
- Theorems/definitions:

  Definitions (all in `LnLean.Proofs.WaveD.D47`):

  - `waveD_d47_dustThreshold`, `waveD_d47_isDustOutput` — the BOLT 3 output
    threshold `dust_limit + secondStageFee(direction)` and strict dust test.
  - `CommitmentHTLCOutput.ofHTLC` — projects an `HTLCRecord` to a commitment
    output with no invented fields (`amountSat = floor(amount_msat / 1000)`).
  - `trimHtlcs`, `dustHtlcs` — the survivors and the removed outputs.
  - `effectiveFee c = c.fundingValueSat - c.totalOutputValue` — the fee the
    ledger actually charges.
  - `buildCommitmentTrimmed` — BOLT 3 construction that reduces the residual
    output by the whole pending HTLC value and emits only survivors.

  Exactness of trimming (proved, no `sorry`):

  - `waveD_d47_isDustHTLC_iff_threshold`, `waveD_d47_hasOutput_iff_threshold`,
    `waveD_d47_threshold_not_dust` — the model's `isDustHTLC`/`hasOutput` are
    exactly `amountSat < dust + fee` / `dust + fee ≤ amountSat`; equality with
    the threshold is kept.
  - `waveD_d47_ofHTLC_isDust_iff` — on `ofHTLC`, the commitment-level test is
    the model's `isDustHTLC`.
  - `waveD_d47_mem_trimHtlcs`, `waveD_d47_mem_dustHtlcs` — an output survives
    iff present and at/above threshold; it is removed iff present and strictly
    below.
  - `waveD_d47_dust_not_mem_trim`, `waveD_d47_untouched_mem_trim`,
    `waveD_d47_trimHtlcs_idempotent` — no dust survives, every non-dust input
    survives, trimming is idempotent.
  - `waveD_d47_trimHtlcs_length_add`, `waveD_d47_htlcValue_partition` — the
    lengths and HTLC values split exactly into survivors + trimmed.
  - `waveD_d47_buildCommitmentTrimmed_htlcOutputCount` — the emitted HTLC
    output count equals the survivor count.

  Fee accounting (conditional):

  - `waveD_d47_buildCommitmentTrimmed_totalOutputValue` — total emitted value
    is `funding - fee - trimmedValue`.
  - `waveD_d47_effectiveFee_buildCommitmentTrimmed` — effective fee is
    `fee + trimmedValue`.
  - `waveD_d47_trimmed_value_accounted_as_fee` — emitted outputs +
    `(fee + trimmedValue) = funding`.

  Model gap (proved):

  - `waveD_d47_buildCommitment_toRemote`,
    `waveD_d47_pretrimmed_toRemote_excess` — the existing pre-trimmed
    `buildCommitment` leaves exactly `trimmedValue` in `to_remote` instead of
    moving it to the fee.
  - `waveD_d47_pretrimmed_fee_excludes_trimmed` — on that constructor,
    `outputs + fee = funding`; adding the trimmed value to the fee would
    over-count (given positive trimmed value).
  - `waveD_d47_feeSat_not_determined_by_outputs` — `feeSat` is an independent
    field: two records with identical output lists and HTLC lists can carry
    different `feeSat`.
  - `waveD_d47_addHtlc_dust_fee_unchanged` — `Commitment.addHtlc` drops a
    dust HTLC while leaving `feeSat`, the output list and the total output
    value unchanged.

- Added hypotheses:

  - `0 < dustLimitSat` in the HTLC-record threshold lemmas
    (`isDustHTLC`/`hasOutput` use saturating `Nat` subtraction); every
    negotiated BOLT 3 dust limit is positive (default 546).
  - `hfit : fee + toLocal + htlcOutputsValue hs + commitmentAnchorTotal anchors
    ≤ funding` in the accounting theorems: the BOLT 3 no-underflow condition
    for the residual output. Without it the model's `Nat` subtraction
    truncates and the ledger identity is false.
  - `hdust : 0 < htlcOutputsValue (dustHtlcs d t s hs)` in the negative gap
    theorem; with no trimmed value the two ledgers coincide.
  - No hypothesis weakens the trimming claims themselves; they are
    unconditional (apart from `0 < dustLimitSat` where noted).

- Statement fidelity:

  The trimming half is proved exactly as stated for the model's own dust test
  and for a concrete output-level trim. The fee half is **not** derivable
  from the current model: `LnLean.Channel.Commitment` has no constructor that
  subtracts the whole pending HTLC value from the funder, `feeSat` is not
  linked to any output sum, and the existing `buildCommitment` /
  `Commitment.addHtlc` leave trimmed value in the residual output while
  leaving `feeSat` unchanged. The module therefore proves the faithful
  BOLT 3 ledger with the new `buildCommitmentTrimmed`, and separately proves
  the exact gap in the existing constructors. This is a conditional result,
  not an unconditional theorem about `Commitment.feeSat`.

## Remaining gap / next step

The model needs one of:
1. a commitment constructor that reduces the funder's output by the full
   pending HTLC value (including trimmed HTLCs), with `feeSat` as the base fee;
   or
2. an explicit effective-fee field (or defined `paidFee = funding - outputs`)
   plus the invariant that it equals `feeSat + trimmedValue`.

With either in place, `waveD_d47_trimmed_value_accounted_as_fee` can be
restated directly over the model constructor. Also worth linking the trim to
`LnLean.Channel.State.Step` (which HTLC set is committed), and combining with
`LN-CH-005` (fee sufficiency): the trimmed value only strengthens the fee
margin, so fee sufficiency is preserved when trimming is applied.
