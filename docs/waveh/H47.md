## 1. What this lane adds

`scripts/waveh/clean-checkout-dry-run.sh` prints the exact gate sequence that a
clean public checkout can run, and labels every step by what it proves:

| Label | Meaning | Executed by `--run`? |
|---|---|---|
| `SOURCE` | must pass on a clean checkout without the vendor snapshot | yes |
| `SOURCE-DEFER` | source check that needs `refs/rust-lightning` at the pinned commit | yes, only if the ref is present |
| `VENDOR` | vendor provisioning/verification; absence is the explicit RC 3 skip (`OPS-01`) | **no, never** |
| `BUILD` | full `lake build` / axiom audit | **no, never** |

The default is **print-only**. `--run` executes only the `SOURCE` steps. The
script never runs `fetch-vendor.sh` provisioning, never runs `lake build`,
never uses the network, never writes Git state, and never creates a file.

This does **not** resolve `OPS-01` (no vendor artifact is published) or `OPS-03`
(no tag/PR/merge path is chosen). It makes the distinction those issues depend
on reproducible and machine-checkable.

## 2. Exact invocation and exit contract

```sh
scripts/waveh/clean-checkout-dry-run.sh                # plan only, RC 0/1/3
scripts/waveh/clean-checkout-dry-run.sh --run          # plan + SOURCE gates
scripts/waveh/clean-checkout-dry-run.sh --root DIR     # inspect an export
scripts/waveh/clean-checkout-dry-run.sh --require-vendor
REQUIRE_VENDOR_BUILD=true scripts/waveh/clean-checkout-dry-run.sh
```

| RC | Condition |
|---|---|
| `0` | plan printed; with `--run`, every runnable source gate passed |
| `1` | a required source file is missing, untracked, or a required script is not executable |
| `2` | usage/configuration error (bad `--root`, unknown option) |
| `3` | vendor snapshot absent while `--require-vendor` / `REQUIRE_VENDOR_BUILD=true` is set (mirrors CI) |
| `4` | a source gate failed under `--run` |

`--keep-going` continues after a failing source gate; the final RC stays `4`.
`--no-tracked` disables the `git ls-files` tracked-input check (used when
inspecting a non-Git export).

## 3. Reproducibility properties

- Deterministic environment for every invocation: `LC_ALL=C`,
  `PYTHONHASHSEED=0`, `PYTHONDONTWRITEBYTECODE=1`, `TZ=UTC`.
- Prints SHA-256 digests of the eight gate scripts, `lakefile.lean`,
  `lean-toolchain`, `lake-manifest.json`, `vendor/VENDOR-SHA256`,
  `tests/conformance/vectors.json`, and itself, so a dry-run record can be
  compared byte-for-byte later.
- Reports the root, whether it is a Git worktree, `.lake` shape (symlink vs
  directory), vendor presence, and the pinned ref HEAD. Nothing under `.lake`
  is read or trusted.
- The only Git commands are read-only: `git ls-files --error-unmatch` and
  `git -C refs/rust-lightning rev-parse HEAD`. No `commit`, `checkout`,
  `switch`, `branch`, `tag`, `reset`, `push`, `worktree`, `fetch`, or `clone`.
- `PYTHONDONTWRITEBYTECODE=1` prevents `__pycache__` creation during `--run`
  (verified: no `.pyc`/`__pycache__` appeared in the test export).

## 5. Scope caveats

- **No build evidence.** Steps 10–11 are printed but never executed. A green
  dry run says only that source gates pass on a tree with no vendor snapshot.
- **Vendor state is inferred, not provisioned.** `vendor/btc-lean-core` presence
  is read via `lakefile.lean`; step 8 is never invoked. A present-but-modified
  snapshot is only caught by the separately printed `verify-vendor.sh` command.
- **No `OPS-01` resolution.** No archive is published, no URL/checksum is
  chosen, and `vendor/` remains gitignored.
- **No `OPS-03` resolution.** No branch is switched, no tag is created, no PR is
  opened, no remote is contacted. The script cannot make `main` current.
- **Anchors need a pinned ref.** Without `refs/rust-lightning`, step 7 is
  deferred; that is a documented gap in the dry run, not a pass.
- **Expected counts are baseline labels.** The `expect:` lines (204 Lean files,
  202 root imports, 48/79 catalog, 306 anchors) are wave-7 facts at `50d78ed`.
  The parent must update them after wave-8 integration; the script does not
  enforce them (the real gates do).
- **Shared-worktree runs are not meaningful.** Other lanes' untracked modules
  change file counts and may contain in-progress `sorry`; always pass a clean
  export via `--root`.
- **Tracked check is skipped for non-Git exports.** In a `git archive` export
  there is no `.git`, so "required files are tracked" cannot be re-verified
  there; it is verified when run against the repository worktree.
- **No JSON/machine output.** The plan is human-readable text only; the digests
  in the header are the machine-checkable record.

## 6. Integration patch (parent-owned; not applied here)

`H47` owns no workflow file. To make the distinction part of the real CI
source-gates job, apply this exact patch (a print-only step, so it does not
duplicate any gate work):

```diff
diff --git a/.github/workflows/ci.yml b/.github/workflows/ci.yml
--- a/.github/workflows/ci.yml
+++ b/.github/workflows/ci.yml
@@ -42,6 +42,11 @@ jobs:
       - name: Set up Python
         uses: actions/setup-python@v5
         with:
           python-version: "3.12"
 
+      - name: Dry-run the clean-checkout source-gate plan
+        # H47: prints the exact gate order and records the explicit vendor skip.
+        # Print-only: it validates required inputs and never builds or fetches.
+        run: ./scripts/waveh/clean-checkout-dry-run.sh --root .
+
       - name: Check obligation catalog (strict audit)
         run: python3 scripts/check-catalog.py --audit
```

The step must be `chmod +x` before commit (`git update-index --chmod=+x` if the
mode is not already staged). On CI, `vendor/btc-lean-core` is absent, so the
plan prints step 8 as the RC 3 explicit skip and exits `0`; a missing tracked
input exits `1` and fails the job.
